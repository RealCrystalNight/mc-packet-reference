Deep Dive

Role in the protocol

S23 is the server's single-block state correction. The server sends it whenever one block in a loaded chunk changes and the change is cheap to express, with the alternative S21PacketChunkData / S22PacketMultiBlockChange reserved for bulk edits. The block state is encoded as a VarInt into the Block.BLOCK_STATE_IDS registry, not as the old blockId | (meta << 12) split; every block in 1.8.9 has a unique registry ID. NetHandlerPlayServer pushes it from the block-breaking path (line 481), the block-placement path (line 535), ItemInWorldManager.tryHarvestBlock (line 254) and PlayerManager's chunk watcher broadcast (line 436).

Vanilla handling

NetHandlerPlayClient.handleBlockChange calls PacketThreadUtil.func_180031_a for main-thread dispatch, then clientWorldController.func_180503_b(pos, state), which is WorldClient.setBlockState: it replaces the local block, updates the lightmap, and re-renders the region. That is the entire effect; there is no server round trip. Because the handler writes straight into the world, any module that reads world state after the event bus gets the correction for free, which is why so few clients intercept S23 directly.

Why clients touch it

Only one module in the 8-client corpus references S23PacketBlockChange: Rise 6.2.4's WatchdogJumpSprint, a Scaffold sprint mode. It treats every S23 as proof the server accepted a placed block: the PacketReceiveEvent handler sets start3 = true and increments a block counter, and the pre-motion handler then uses start3 to fire a spoofed C08PacketPlayerBlockPlacement with an ice ItemStack against the player's own position (line 116), which is the Watchdog anti-cheat block-placement trigger used to keep the player's on-ground state consistent while sprint-jumping. The counter also feeds previousBlockValue / previousTick logic that paces how often the exploit packet is sent.

Exploit surface

S23 is clientbound and carries no player identity, so there is nothing to spoof server-side; the abuse is entirely on the receiving end. Ghost-block clients that locally predict block state must reconcile against S23 when the server disagrees, and scaffold / nuker modules can use the arrival timing of S23 as a cheap ping-free ack. Anti-cheats watch the reverse direction: they validate that a C08PacketPlayerBlockPlacement is followed by a matching S23 echo and check the placed block against the client's claimed reach, which is exactly the surface WatchdogJumpSprint's ice-placement trick plays on.

Server-Side Handling

NetHandlerPlayServer sends S23 on block break (processPlayerDigging, ~line 481), on placement and its neighbor update (~line 535), plus a second packet for the offset block when the placed block has a block-on-use neighbor. ItemInWorldManager sends it after a successful harvest, and PlayerManager.sendToAllPlayersWatchingChunk broadcasts to every player with the chunk loaded. In 1.8.9 there is no server-side validation of the client's C08 beyond reach and interval checks in the digging/placement handlers.

Protocol Analysis

Wire format: BlockPos as a packed long (readBlockPos) followed by a VarInt block state registry ID. The state is resolved at construction time from the world, so the server always sends what it believes is current, and a stale S23 can overwrite a newer client-side prediction. In PLAY state only. Frequency is bounded by player block interactions, which is what makes it a usable ack channel.

Anti-Cheat Landscape

S23 itself is never flagged; it is server-originated truth. Anti-cheats use it to detect ghost blocks and reach abuse: a placed block whose S23 echo position lies outside the client's valid reach, or a C08 that gets no echo, feeds reach and scaffold checks. Clients that spoof block placement need the echo to keep their internal state honest, and the timing between C08 and S23 is a latency signal that modules like WatchdogJumpSprint fold into their pacing.

implementation Implementation Cases

The server's authoritative one-block correction. In this corpus it is used by exactly one module, Rise 6.2.4's WatchdogJumpSprint, which reads S23 arrivals as placement acknowledgements to pace a Watchdog-targeted ice-block C08 exploit. Everything else in the 8 clients lets the vanilla handler write the state into WorldClient and reads the world afterwards.

anticheat Anti-Cheat Checks

S23 changes a single block and tells the client about it; it is the smallest world mutation in the protocol. For server-side anticheats it is still a compensated-world event: the cache must apply the change before checks judge the player, and scaffolding checks use the client-facing block state to validate placement supports. The corpus for S23 is the block-change pipeline again (Grim AirLiquidPlace and CompensatedWorld, NCP BlockChangeTracker and BlockChangeListener, Intave SingleBlockChangeReader, Kauri BlockUpdateHandler, FlopAC WrappedOutBlockChange), with the same world-cache pattern as S22 but per block.

AirLiquidPlace (Grim) (GrimAnticheat-Grim)

Flag block placements against air or liquid supports, which scaffolding and tower cheats produce.

BlockPlaceListener reads the placement position and the compensated world's block state at the support location; it first checks blockHistory for recent START_DIGGING or netty-sync modifications at that position so instant-breaking plus placing in the same tick does not false. If the support is air or a no-place liquid, the check flags and resyncs the placed block. The file's comment documents years of false-positive archaeology around dig-then-place ordering.

SingleBlockChangeReader (Intave) (intave-intave)
