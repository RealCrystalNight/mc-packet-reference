Deep Dive

Role in the protocol

C0B carries an action enum (START_SNEAKING, STOP_SNEAKING, START_SPRINTING, STOP_SPRINTING, STOP_SLEEPING, RIDING_JUMP, OPEN_INVENTORY) plus an int aux value used only for RIDING_JUMP. The server's processEntityAction maps it directly onto the player entity state: setSneaking, setSprinting, wakeUpPlayer, horse jump. It is a pure state packet with no position, which makes it the perfect carrier for sprint/sneak manipulation that must not touch movement packets.

Vanilla handling

processEntityAction switches on the action ordinal and mutates the player entity. STOP_SLEEPING also resets hasMoved = false so the next C03 position is accepted (this is why WakeUp/phase tricks use it). RIDING_JUMP sets horse jump power from the aux int. OPEN_INVENTORY opens the horse GUI. The client sends C0B from EntityPlayerSP on key presses; sprint is normally also mirrored inside C03PacketPlayer's sprinting flag, which is where anti-cheats cross-check.

Why clients touch it

Sprint modules (Rise 5.99 Sprint) intercept and rewrite C0B to keep sprint always-on. Sneak modules (Rise 5.99 Sneak, Rise 6.2.4 NCPSneak) send START/STOP_SNEAKING on a timer to trick anti-cheat sneak checks. Scaffold (Rise 5.99, Tenacity, VulcanSprint mode) sneaks while placing on edges. WTap (Rise 5.99, Spicy) sends STOP_SPRINTING then START_SPRINTING around hits to reset the target's knockback velocity. Sigma KeepSprint cancels STOP_SPRINTING entirely so the player keeps sprint speed after attacking.

Exploit surface

The packet is unvalidated beyond the enum, so clients can send START_SPRINTING while standing still or STOP_SNEAKING while never having sneaked. Anti-cheats therefore correlate C0B with C03's sprinting flag and with the movement deltas: sprint flag on but forward speed zero flags. WTap's stop-sprint-while-close is measured against hit timing. Sneak-spam (sending sneak every N ticks) is the classic NCP/Verus phase and safewalk enabler.

Server-Side Handling

processEntityAction mutates playerEntity state: setSneaking/setSprinting booleans, wakeUpPlayer (which clears hasMoved so the next position packet passes the movement check), horse jump power, horse GUI. No rate limiting; the aux int is ignored for all actions except RIDING_JUMP.

Protocol Analysis

Fields: VarInt entityId (client player), VarInt action ordinal, VarInt aux (0 for non-horse actions). Sent in PLAY state. Vanilla sends START_SPRINTING/STOP_SPRINTING from the sprint key handler and sneak actions from the sneak key; modules send it from motion/update events.

Anti-Cheat Landscape

NCP's sprint check compares C0B against C03's onGround/sprinting fields and movement speed. Verus detects sprint-stutter (WTap) by knockback timing. Sneak-abuse (sending sneak while moving fast) flags on Intave and newer NCP; Rise 6.2.4 NCPSneak and the scaffold sprint modes exist precisely to shape these patterns per AC.

implementation Implementation Cases

The entity-state switchboard. Sprint modules rewrite it, sneak modules spam it, scaffold sneaks with it, WTap stutters it, and KeepSprint eats the STOP_SPRINTING. Every trick exploits the gap between the boolean state the server stores and the movement the client actually sends.

Sprint (Rise 5.99)

Force sprint state server-side regardless of direction keys, and cancel sprint-stopping packets.

Sneak (Rise 5.99, Rise 6.2.4, Rise 6.1.30)

Send START/STOP_SNEAKING on a timer to exploit sneak-based anti-cheat logic or to safely place/phase.

WTap (Rise 5.99, Spicy)

Reset the target's knockback by briefly stopping sprint right at the hit, then re-sprinting.

On the attack, if the target is in range and the player was sprinting, send STOP_SPRINTING then START_SPRINTING in the same tick (or on consecutive ticks). The server stops applying sprint-knockback multiplier to the target for that hit. Rise 5.99 WTap sends both packets back-to-back via sendPacketWithoutEvent; Spicy Wtap uses sendQueue.addToSendQueue.

KeepSprint (Sigma 4.11)

Cancel STOP_SPRINTING so the player keeps sprint speed after landing a hit.

Sigma KeepSprint hooks EventPacket on the receive/send path, and when a C0B with STOP_SPRINTING is seen it cancels the event, leaving the server-side sprint flag set. The result is that attacking no longer drops the player out of sprint.
