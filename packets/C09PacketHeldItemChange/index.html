Deep Dive

Role in the protocol

C09 carries one int: the hotbar slot index the client is switching to. The server's processHeldItemChange validates 0 <= slot < 9 and sets the player's currentItem, which changes the server-side held item used for reach, damage, block breaking and what other players see. It is the cheapest stateful packet in the play state: no position, no timestamp, so clients can spam it freely, which is exactly why silent-switch modules rely on it.

Vanilla handling

NetHandlerPlayServer.processHeldItemChange: if the slot is within the hotbar, set inventory.currentItem and mark the player active; otherwise log a warning. The client-side vanilla path is EntityPlayerSP/PlayerControllerMP updating the slot when the user scrolls. Because the server trusts the packet entirely, any module that sends C09 with a different slot than the visible one desynchronizes the server's view of the held item.

Why clients touch it

Three families across the ten clients. (1) Silent switching: Scaffold (Tenacity ScaffoldModule, Rise 5.99 Scaffold, Sigma Scaffold) sends C09 to the block slot while the visible hotbar stays put, and cancels incoming C09 echoes. (2) Tool/weapon automation: Rise 6.2.4 NewNewBreaker switches to the best tool before breaking, KillAura (Rise 6.2.4/6.1.30) swaps weapons for 1.9+ style switching. (3) Consumable routing: AutoPotion/AutoSoup/AutoGap/AutoHead/AutoEat (Memeware, Rise 5.99, Sigma) switch to the food/potion slot, use the item, then switch back. November Recode 2.0 adds an InventoryManager that tracks the C09/S09 streams and re-syncs the slot, and a NoSlowDown that switches away and back; LiquidSense Dev's AutoHead, AutoArmor, AutoADL and the NoFall MLG save all use the silent-switch pair.

Exploit surface

The packet is unthrottled, so modules can switch slots 20 times per tick. The detectability comes from the server comparing the packet slot to the client's own S09PacketHeldItemChange echoes and to attack/place packets: an aura that attacks with a sword while C09 says a block is held gets flagged by rotation+slot correlation checks. Silent switch modules therefore cancel the visible slot change or re-send it after the action.

Server-Side Handling

processHeldItemChange validates the slot range and sets inventory.currentItem. There is no rate limit and no validation against the client's last known slot. The side effect is that the server-side held item drives entity equipment broadcasts (S04PacketEntityEquipment) and the player's attack/place behavior.

Protocol Analysis

Single VarInt slot field. Sent in PLAY state only. Vanilla sends it on scroll wheel input; modules send it via PacketUtil.sendPacket, addToSendQueue, or addToSendQueueNoEvent (Tenacity). Silent-switch modules cancel the packet when it matches the player's real current slot so the visible hotbar never moves.

Anti-Cheat Landscape

Anti-cheats correlate C09 with C02/C08/C07: switching to a sword then attacking with reach is normal, but attacking while the C09 stream says a block is held trips slot-consistency checks on Verus and newer NCP. The fix in clients is to send C09 to the weapon slot before the attack and back after, or to cancel the switch entirely and spoof the attack slot.

implementation Implementation Cases

The slot-switch packet that silent everything depends on. Scaffold switches to blocks invisibly, breakers grab the best tool, and consumable modules hop to the potion slot and back. The server trusts the int, so the entire game is keeping the visible slot in sync with the action slot.
