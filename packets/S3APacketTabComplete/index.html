Deep Dive

Role in the protocol

The server's answer to C14PacketTabComplete: a VarInt count followed by the matching command and player-name strings. The vanilla GUI feeds them into GuiChat.onAutocompleteResponse to cycle suggestions on Tab. Because Bukkit forks populate the server command registry from plugins, the response leaks plugin names as colon-prefixed commands (/plugin:subcommand), which is the entire basis of the plugin-enumeration features in the corpus.

Vanilla handling

NetHandlerPlayServer.processTabComplete asks the command dispatcher for matches and echoes them back as S3APacketTabComplete with no rate limit and no length guard beyond the request's own string cap. Client side, handleTabComplete dispatches on the main thread and, only when the current screen is a GuiChat, calls onAutocompleteResponse; any other screen means the payload is silently ignored, a detail modules must remember when they fire requests outside chat.

Why clients touch it

Five corpus features consume the response. Rise 5.99 Plugins sends C14 with '/' in Normal mode or '/a' through '/z' in Bypass mode, then parses every S3A response, splits on ':' and filters '/minecraft' to print the plugin list; Bypass defers the printout to onDisable. Sigma 4.11 PluginFinder is a command doing the same with a 20-second listen window, its own dedupe and a cancel of the event. Rise 6.1.30 and 6.2.4 Chat reimplements the chat screen and consumes S3A for autocomplete cycling: it stores the matches on receive, rotates through them on Tab, and fires C14 itself with the typed text and an optional targeted BlockPos. LiquidSense Dev's Plugins module fires a single C14 on enable and auto-disables after printing the sorted, deduped list. November Recode 2.0's PluginsCommand runs the same enumeration as a chat command and additionally regex-parses bare-word suggestions and accepts a custom completion seed.

Exploit surface

The enumeration trick is the exploit: a server that does not filter tab completion inventories its own plugins, which names the anti-cheat and its version for targeted research. Bypass modes blast up to 26 requests in one burst, which is a clean rate signal; servers that rate-limit C14 or strip plugin-prefixed commands from the registry kill both modes. The GUI dependency is the subtle constraint: S3A only reaches the vanilla autocomplete when a chat screen is open, so UI-less requesters must hold their own state.

Server-Side Handling

processTabComplete resolves matches from the server command registry and player list, then sends S3A. There is no server-side rate limit in vanilla; rate limiting lives in plugins. The response is a snapshot, one S3A per request in order, and nothing invalidates a previous response, which is why burst enumeration is reliable.

Protocol Analysis

VarInt count, then count strings, each VarInt-length-prefixed UTF-8, bounded by the 32767-byte frame limit per string. The request may carry an optional targeted BlockPos that enables coordinate-aware completions, but the response carries no position data back. Results arrive in registry order, which is why cycling modules rotate through the array instead of assuming alphabetical order.

Anti-Cheat Landscape

Anti-cheats do not flag S3A; they flag the request side. A burst of 26 C14 packets inside one tick is a clean rate signal, which makes Rise 5.99's Normal mode (one request, one parse) the safe variant and Bypass the risky one. Servers defeat enumeration server-side by filtering S3A responses or hiding plugin-prefixed commands, both invisible to the client.

implementation Implementation Cases

The tab-completion response channel and the backbone of plugin enumeration: Bukkit leaks plugin names as colon-prefixed commands. Five features across the corpus consume it: Rise 5.99 Plugins (Normal and Bypass modes), Sigma 4.11's PluginFinder command, the Rise 6.x Chat module, LiquidSense Dev's Plugins module, and November Recode 2.0's PluginsCommand.

Plugins (Rise 5.99)

Enumerate server plugins by parsing the colon-prefixed commands leaked in tab-completion responses.

Normal mode sends one C14PacketTabComplete("/") on enable and parses the S3A response immediately, splitting each command on ':' and filtering the '/minecraft' namespace; results print to chat as they arrive and the module toggles off. Bypass mode fires 26 requests ('/a' through '/z') and defers the deduped printout to onDisable. Timeouts (5s Normal, 2.5s Bypass) disable the module when the server returns nothing.
