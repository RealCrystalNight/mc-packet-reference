Deep Dive

Role in the protocol

S00PacketKeepAlive is the clientbound half of the play-state liveness probe. NetHandlerPlayServer sends it roughly once per second from its update loop with a server-chosen int key (field_147378_h), and the vanilla client echoes it back as C00PacketKeepAlive with the same key. NetHandlerPlayServer.processKeepAlive compares the echoed key and folds the round-trip into the player's ping EMA: ping = (ping * 3 + delta) / 4. Because it is the only timing-only packet in the play state, it is the reference clock that ping spoofers, disablers and timing-based velocity exploits all anchor on.

Vanilla handling

NetHandlerPlayClient.handleKeepAlive echoes immediately: addToSendQueue(new C00PacketKeepAlive(packetIn.func_149134_c())). Server side, processKeepAlive is a pure timing check: a matching key updates the ping EMA, a wrong key is silently ignored. There is no per-connection timeout in the vanilla 1.8.9 server for a missing echo; timeouts are enforced by the network layer read timeout or by anti-cheat plugins. That asymmetry, an immediate client echo versus a server that never punishes a missing one, is what every keepalive-timing exploit depends on.

Why clients touch it

Four distinct uses in the 8 clients. (1) Debugger in Rise 5.99, 6.1.30 and 6.2.4 prints incoming keepalive ids to chat so the user can watch server cadence while tuning other modules. (2) Rise 6.2.4 WatchdogVelocity and WatchdogPredictionVelocity cancel the keepalive while a velocity spoof is armed, silencing the server's timing reference during the spoof window. (3) Sigma 4.11 Disabler Erisium mode captures the key on receive and replays a stale C00 every 1500ms, freezing the measured ping. (4) Rise 6.x NetworkAPI registers the class so JavaScript scripts can hook its receive. Note the corpus has no PingSpoof hit for S00: the spoofers in these clients intercept the C00 echo side instead.

Exploit surface

Because the vanilla echo is immediate, any delay, cancellation or replay shows up as a ping shift or a stalled keepalive stream. The Watchdog velocity modules cancel S00 while holding S12/S32 packets so the server cannot correlate a latency spike with the velocity cancel; WatchdogPredictionVelocity re-injects the buffered keepalive on the strafe trigger to restore sequencing. Sigma's Erisium mode cancels C00 echoes and re-sends the last captured key on a timer, which keeps the server's key comparison failing silently so the ping EMA never updates. The trade-off is structural: cancellation is invisible to the packet stream but leaves the connection dead on servers that do track keepalive gaps.

Server-Side Handling

NetHandlerPlayServer sends S00PacketKeepAlive(field_147378_h) roughly every second from its tick loop. processKeepAlive: if the echoed key matches field_147378_h, ping = (ping * 3 + (now - lastPingTime)) / 4; wrong or missing keys are silently dropped with no penalty. There is no vanilla timeout for a dead keepalive; connection liveness is the network layer's job.

Protocol Analysis

PLAY state, id 0x00, one VarInt int key (server-tick counter in vanilla). Clientbound; the serverbound echo is C00PacketKeepAlive with the same id value but a different class in the opposite direction. The key is opaque to the client: modules that mutate or replay it rely on the server never validating beyond equality with the last sent key. Because it arrives constantly, it is also the cheapest packet for modules to use as a timing beacon.

Anti-Cheat Landscape

NCP and AAC track keepalive timing to separate real latency from timer abuse; a frozen or wildly inflated ping is a classic timer/fly tell. Verus-era checks correlate keepalive gaps with C0F transaction gaps, which is why the Rise 6.2.4 Watchdog modes cancel S00 and S32 together, and why Sigma's Erisium mode replays keys instead of cancelling outright: pure cancellation is strong but lethal on servers with keepalive timeouts. Debugger and NetworkAPI are observation-only and never flag.

anticheat Anti-Cheat Checks

S00 is the server's keep-alive probe: the client must echo the id back in C00. Anticheats use the round trip as their latency clock: the server records when it sent each id and when the matching reply arrives, which yields the player's ping and exposes ping-spoof, timer and connection-manipulation cheats. The corpus shows the same echo-tracking pattern at every scale, from the four-line ConnectionManager in Frequency to NCP's keepalive-frequency check with kick actions and Grim's validation that the replied id was actually sent.

BadPacketsO (Grim) (GrimAnticheat-Grim)

Flags keep-alive replies whose id was never sent by the server, the signature of a spoofed or replayed keep-alive stream.

Tracks every OUT keep-alive id in a queue. On the IN keep-alive reply, searches the queue for the id: a match removes the id (pruning the queue) and passes, while a reply with an unknown id flags and cancels the packet.

Detects: Ping-spoof clients that fabricate keep-alive replies, and lag-switch or timer tools that replay stale ids.

KeepAliveTracker (Hydro) (Incognitolol-Hydro)

Tracks the keep-alive round trip as the player's latency clock, feeding ping data to every other check.

On the OUT keep-alive, stores the id with a send timestamp in an expected map. On the IN reply, looks up the id, removes it and computes keepAlivePing as the receive timestamp minus the send timestamp, setting the acceptedKeepAlive flag. The ping value is displayed in the /hydro debug command and feeds the ping-based exclusions.

Detects: Ping spoofing is exposed because the computed ping diverges from the transport-level expectation; the tracker itself is data, not a flagger.
