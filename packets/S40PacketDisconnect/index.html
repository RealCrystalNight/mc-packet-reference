Deep Dive

Role in the protocol

The play-state kick. One IChatComponent reason, serialized as a chat component. Sent by NetHandlerPlayServer and NetworkSystem when the server closes a PLAY connection with a reason; the client's handleDisconnect closes the channel and the onDisconnect path unloads the world and shows GuiDisconnected with the reason. It is the play-state counterpart of the login-state S00PacketDisconnect, and it is the last packet on the wire before the server tears the connection down.

Vanilla handling

handleDisconnect calls netManager.closeChannel(reason), which triggers the disconnect cascade: world unload, then GuiDisconnected with the reason. The kick is one-way; there is no acknowledgement. Modules see the packet in PacketReceiveEvent before the vanilla handler runs, which is the only window for reacting to it.

Why clients touch it

Sigma 4.11 Ranking inspects the reason text: if it contains 'ban' and the player has been alive more than 15 seconds, it reports a ban stat into its kill and death ranking telemetry. Rise 5.99 StaffAlert imports S40PacketDisconnect but never branches on it; the module's real work polls the Hypixel punishment API over HTTPS. The classic AutoReconnect and AntiKick modules of the wider ecosystem (Tenacity 5.1, Gugustus) sit outside this corpus, so none of the 8 reference clients cancels the kick. Rise 6.x registers the class in the script API.

Exploit surface

The kick cannot be meaningfully cancelled: the server has already dropped the connection after sending the packet, so cancelling it only skips the disconnect screen and leaves a dead connection. The real value is reading the reason: ban detection for telemetry (Ranking) and staff-ban awareness. Reason parsing is the only client-side logic, and it is invisible to the server. Anti-cheats use S40 as the enforcement channel, not as a measurable signal.

Server-Side Handling

NetHandlerPlayServer and NetworkSystem both send S40 with a GenericFutureListener that closes the channel after the packet flushes, so the kick is fire-and-forget. The reason is built from translated chat components. The server removes the player from its world state regardless of whether the client ever processes the packet.

Protocol Analysis

Single field: a chat component serialized via writeChatComponent, which embeds the full JSON chat tree including formatting and translations. The reason string is attacker-controlled, so clients parsing it must handle arbitrary text. Registered clientbound in PLAY state; the login-state equivalent is S00PacketDisconnect at id 0x00.

Anti-Cheat Landscape

Anti-cheats use S40 as the enforcement channel: a flagged player receives one and is gone, so there is nothing to bypass inside the packet. Client-side modules can only observe it. Ranking's use is the only corpus example of reacting to the reason text, and it is telemetry, not evasion.
