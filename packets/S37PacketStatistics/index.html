Deep Dive

Role in the protocol

The stats and achievements channel. The server ships a map of StatBase to integer value on join and after each stat change, and the client folds it into its StatisticsFile and triggers the achievement toast for positive achievement values. The payload mixes plain counters with achievements, so a module cannot silence the toast without also discarding the counters unless it rewrites the map.

Vanilla handling

handleStatistics iterates the entry set and calls the stat file writer's readStat per entry, then triggers the toast sequence for achievements with a value greater than zero. Server side, StatisticsFile.sendStats dumps the full file on join and sendUpdate pushes a delta after each change, both via S37. It is the only path by which the client learns its own stats, which makes it the interception point for any stats-related module.

Why clients touch it

Exactly one real module in the corpus: Rise 5.99 NoAchievements cancels every S37 on receive, killing the toast at the cost of stale local counters. The other seven clients have zero module hits; their corpus entries are the vanilla handler, the StatisticsFile producers, the registry and the Rise 6.x script NetworkAPI registration. The metadata draft for a StatSpoof module has no corpus backing. The landscape is thin because stats are cosmetic: they grant no combat, movement or rendering advantage.

Exploit surface

The entire surface is the client-side cancel, and it is invisible: there is no serverbound stats packet, so the server never learns the client discarded the data. Anti-cheats ignore the packet entirely. The engineering subtlety is collateral: S37 bundles achievements with counters, so NoAchievements trades accurate local stats for a quiet toast; a surgical implementation would rewrite the map instead of cancelling the packet.

Server-Side Handling

StatisticsFile.sendStats (join, full dump) and sendUpdate (per-change delta) both push via playerNetServerHandler.sendPacket. There is no rate limit, no acknowledgment and no retry: the server pushes and forgets, and the client applies whatever arrives. On join the packet is part of the login burst alongside S38 and S39.

Protocol Analysis

Encoding: VarInt count, then per entry a VarInt stat id and a VarInt value. Stat ids resolve against the client's own StatList tables; unknown ids are skipped silently. A full join dump is dozens of entries but each is compact, so the packet rarely matters for bandwidth. The values are absolute rather than deltas even in sendUpdate: the map holds the new totals.

Anti-Cheat Landscape

Not measured by any anti-cheat: no serverbound counterpart exists, so nothing about client behavior can be inferred from this stream, and the client-side cancel produces zero server-visible signal. Modules face no detection risk from S37 handling, which is why the only module in the corpus uses it as a blunt UI toggle.

implementation Implementation Cases

The stats and achievements channel, normally invisible to cheat clients. Exactly one corpus module touches it: Rise 5.99 NoAchievements cancels the packet on receive to silence the achievement toast, accepting stale local counters as the price. Everything else in the corpus is vanilla handler and producer code.

NoAchievements (Rise 5.99)

Suppress the achievement notification toast by cancelling the entire statistics packet.

A PacketReceiveEvent handler checks the packet type and calls event.setCancelled(true) on every S37PacketStatistics. Because the packet bundles plain stat counters with achievements, cancelling it also kills the toast trigger inside handleStatistics; the local counters simply never update.
