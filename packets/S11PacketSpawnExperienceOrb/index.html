Deep Dive

Role in the protocol

Spawns experience orbs: entity id, fixed-point position (x32) and a short XP value. The server splits orb value at 2000 when an XP source drops, so a large experience drop produces several S11 packets instead of one huge orb. EntityTrackerEntry.getPacket emits it for EntityXPOrb. The packet is frequent on farming servers and essentially free of state: no rotation, no velocity, no metadata.

Vanilla handling

handleSpawnExperienceOrb creates an EntityXPOrb, sets its position and assigns the xpValue. The client's XP bar is driven by pickup events and S06 health/xp updates, not by this packet, so S11 has no visible effect beyond the floating orb entity. Server side, orb value splitting happens at drop time, so the value in the packet is already the split value.

Why clients touch it

Exactly one module in the corpus references S11: Tenacity 6.0 AntiExploit, which rate-limits orb spawns as a crash-exploit guard (two S11 packets within 1 ms increments a violation counter that cancels the second packet). No AutoFarm or XP-tracker module exists in the 8 clients: XP collection modules iterate EntityXPOrb instances in the world entity list rather than hooking spawn packets, mirroring how ESP treats every other spawn packet.

Exploit surface

The orb-flood: a hostile server or proxy streaming S11 at high rate creates hundreds of EntityXPOrb instances per second, each with its own render state, which is the classic XP-lag crash vector. Tenacity's 1 ms rate gate is the canonical mitigation. The xpValue short is unsigned server-side; values above 32767 wrap negative client-side, which makes the orb render but breaks pickup logic. Nothing here is flaggable by anti-cheats because the packet is clientbound and server-authored.

Server-Side Handling

EntityTrackerEntry.getPacket returns new S11PacketSpawnExperienceOrb((EntityXPOrb) trackedEntity) for tracked XP orbs, snapshotting the orb's value. The server splits any XP drop exceeding 2000 into multiple orbs before they are tracked, so each S11 carries a value at or below the split cap. The client handler creates the orb and assigns the value with no validation.

Protocol Analysis

VarInt entity id, three x32 position ints, then a short XP value. No rotations, velocity or metadata fields. Because the value is a signed short, values in the 32768-65535 range arrive negative; the vanilla client does not guard against it. The packet is emitted in bursts when an XP source is destroyed, which is what makes it a flood-exploit vector.

Anti-Cheat Landscape

Anti-cheats ignore S11 entirely: it is clientbound, cosmetic and cannot be influenced by the player. The relevant defense is client-side (Tenacity's rate gate) and server-side (spawn rate caps on XP sources). No bypass trade-off exists for this packet.

AntiExploit (Tenacity 6.0)

Rate-limit XP orb spawns and other clientbound floods so a hostile server cannot lag or crash the client.

A PacketReceiveEvent handler tracks the timestamp of the last S11. If a new one arrives within 1 ms, invalidExperience increments and the packet is cancelled on the second violation with a chat warning; a gap longer than 1 ms resets the counter. The same handler sanitizes resource pack URIs, S43 camera teleports, S2A particle floods, S27 explosion strength and S18 teleport coordinates.
