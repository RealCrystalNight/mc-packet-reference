Deep Dive

Role in the protocol

C13 announces ability state changes: a 4-bit flag byte (invulnerable, flying, allowFlying, creative) plus fly and walk speed floats. Vanilla sends it only when the flying flag flips, from EntityPlayerSP.sendPlayerAbilities. Despite the full struct, the 1.8.9 server reads exactly one bit: it writes isFlying into the player's capabilities and discards everything else.

Vanilla handling

processPlayerAbilities is a single line: capabilities.isFlying = packetIn.isFlying() && capabilities.allowFlying. The server's own allowFlying flag, set exclusively via S39PacketPlayerAbilities, ANDs out any client claim of flight, which is the core reason ability spoofing is a dead end against vanilla. The float fields are not stored at all in 1.8.9, so a forged flySpeed or walkSpeed never reaches server math.

Why clients touch it

The 8 clients show four families. (1) Disabler modes: Memeware Watchdog sends C13 with NaN flySpeed on Hypixel, Rise 5.99's hypixelSlime and c13 modes send allowFlying/isFlying true, Spicy's Disabler sends creative flags. (2) Rise 6.x AbilitiesDisabler spams C13 every 5 ticks. (3) Flight movement: Spicy LongJump, Fly and BackupFly forge full PlayerCapabilities with random flySpeed. (4) Utility: Rise 6.x Nuker syncs the flying flag before teleport-nuking, and the script PacketAPI exposes sendAbilities. The two new research clients add two more. November Recode 2.0 only maps C13 to id 0x13 for its Lua scripting API, with no dedicated module. LiquidSense Dev declares isFlying on enable in LastestHypixelFly and Tp, and TeleportCommand spams absurd flySpeed and walkSpeed floats (1.0E8F and 1.0E8F minus 1) along its C04 teleport path.

Exploit surface

Because the server ANDs against its own allowFlying, the packet is the safest spoof in the protocol: a forged isFlying claim is dropped silently on any non-creative player, which is why disablers spam it freely. The NaN flySpeed in Memeware targets proxy and anti-cheat parsers that copy the float before the handler drops it. The real signal anti-cheats measure is not C13 but the motion that follows: clients that declare flying then move at fly speed without S39 authorization flag on movement checks, not on the packet itself.

Server-Side Handling

processPlayerAbilities writes capabilities.isFlying = packetIn.isFlying() && capabilities.allowFlying and nothing else. The invulnerable, allowFlying, creativeMode, flySpeed and walkSpeed fields are parsed from the wire and discarded. S39PacketPlayerAbilities is the only way the server-side allowFlying changes.

Protocol Analysis

Flag byte (0x01 invulnerable, 0x02 flying, 0x04 allowFlying, 0x08 creative) + two floats. Vanilla clients emit it on double-tap-space in creative; modules emit it on ticks, strafe events or module enable. The wire format accepts any float, including NaN and values far outside the 0..1 range.

Anti-Cheat Landscape

Anti-cheats treat C13 as a weak signal because vanilla discards most of it. NCP and Verus correlate declared flying with actual vertical motion; a client that spams isFlying=true but moves like a walker is suspicious, and one that moves like a flier without S39 authorization flags on motion. The NaN flySpeed trick only works against layers that deserialize the float before the vanilla handler.
