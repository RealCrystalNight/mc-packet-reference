Deep Dive

Role in the protocol

The clientbound plugin message. A channel name string (20-char cap) plus a raw PacketBuffer payload capped at 1048576 bytes. Vanilla channels include MC|Brand (server brand, sent once at join), MC|TrList (villager trades), MC|BOpen (book opening), and MC|AdvCmd (command block updates). handleCustomPayload dispatches by channel name; unknown channels are ignored. This is the standard bus for server-to-client mod and plugin communication.

Vanilla handling

handleCustomPayload branches on the channel: MC|TrList decodes the merchant recipe list into the open GuiMerchant, MC|Brand stores the brand string on the player, MC|BOpen opens the written-book GUI. The buffer is released in a finally block. Channel length is capped at 20 and the payload at 1MB, with an IOException on overflow.

Why clients touch it

Rise 5.99 PacketDebugger logs the channel name of every S3FPacketCustomPayload to chat via Rise.addChatMessage, as part of anti-cheat fingerprinting: the module also times keepalives and transactions. Reading MC|Brand is the standard server-identity read: brand strings identify Paper, Purpur, BungeeCord, and plugin stacks before a bypass picks a mode. Rise 6.x registers the class in the script API. The dedicated BrandDetector modules of the wider ecosystem (Flux, Lycoris) sit outside this corpus, so PacketDebugger is the only real consumer here.

Exploit surface

Purely observational. The payload is server-controlled; a malicious server can send oversized or malformed payloads, but the 1MB cap and try/finally release keep the vanilla path safe. Clients read the channel and payload for fingerprinting, and nothing is sent back, so servers cannot detect the read. The detection value is the brand string itself, which identifies the server stack before a disabler selects a mode.

Server-Side Handling

ServerConfigurationManager sends MC|Brand once per join with the server mod name. EntityPlayerMP sends MC|TrList when a player opens a merchant and MC|BOpen when opening a written book. The channel table is per-connection; the vanilla client only receives S3F and never echoes it. The wire payload length is the remaining readable bytes, capped at 1MB.

Protocol Analysis

readPacketData reads the channel (20-char cap), then takes the remaining readable bytes as the payload buffer, rejecting anything over 1048576 bytes with an IOException. writePacketData writes the channel then the raw buffer bytes. The payload is channel-specific; parsers must know the channel before reading fields from the buffer.

Anti-Cheat Landscape

Passive surface. The brand and channel names fingerprint the server stack; anti-cheats that send their own channels (version checks, telemetry) leak their presence through this packet. Clients never echo S3F, so the read is undetectable server-side. No anti-cheat in the corpus flags the packet itself.

BrandHider (Photon) (Photon-GitHub-AntiCheatAddition)

Stop clients from fingerprinting the server: rewrite every outbound brand payload to a configured fake brand.

Two PacketAdapterBuilder listeners hook the outbound PLUGIN_MESSAGE packets (Configuration.Server and Play.Server, the S3F path) with onSendingRaw. When the channel is the brand channel (MC|Brand or minecraft:brand), the payload data is replaced with createBrandPayload of the configured brand ('Some Spigot' by default) and the packet is marked for re-encode. On join, and at an optional refresh rate, the module also pushes an empty brand payload so the adapter has something to rewrite.

Detects: Clients and disablers that read the server brand to pick a bypass mode; the rewrite keeps the advertised stack generic.

FML mod probe (Negativity) (Elikill58-Negativity)

Detect Forge clients by sending FML handshake payloads and reading the mod-list reply.

initMods sends three FML|HS plugin messages (bytes {-2,0}, {0,2,0,0,0,0} and {2,0,0,0,0}) to the player when the outgoing FML channel is registered, the standard FML handshake sequence that makes Forge reply with its mod list. ChannelEvents handles the incoming FML data (the C17 side) and stores the result in the player's mod map, which feeds the mod-based cheat checks.

Detects: The presence and version of Forge and its mods; server owners use the result to allow or block modded clients.
