Notes

Rise 6.0 CancelInventoryMove cancels C0D to keep the inventory 'open' and allow WASD movement. RektSky B5 ChestStealer sends C0D after stealing. Jigsaw 0.26 InventoryPlus cancels C0D. Sigma 4.11 InventoryWalk cancels C0D.

Deep Dive

Role in the protocol

Closes an inventory window. One unsigned byte windowId, where 0 is the player inventory. The vanilla client sends it from EntityPlayerSP.closeScreen() with the currently open container's id; the server calls closeContainer(), which drops or returns the carried item and switches the player back to the inventory container. It is the bookend to S2DPacketOpenWindow and pairs with the C0EPacketClickWindow clicks that mutate the container.

Vanilla handling

processCloseWindow calls this.playerEntity.closeContainer() unconditionally: the server does not verify the windowId against the player's open container. That makes C0D(0) and C0D(inventoryContainer.windowId) interchangeable in module code, and a C0D with a stale id still closes whatever container is open. The client side is EntityPlayerSP.closeScreen(), which also fires when the GUI closes for any other reason.

Why clients touch it

Inventory-movement modules cancel C0D so the server-side window stays open while the player walks (Rise 5.99 InvMove, Rise 6.x CancelInventoryMove, Sigma InventoryWalk). Sort and steal managers send C0D(0) to force the server-side close after a batch of clicks (Rise 5.99 InvManager, Rise 6.x Manager, Spicy InventoryManager). Tenacity NoSlowModule sends C0D(0) plus a shift-click C0E to ghost-swap the held item while eating. Rise 6.x WatchdogDisabler emits C0D through sendUnregisteredPacket during its blink window.

Exploit surface

Cancelling C0D while moving leaves the server convinced the inventory is open; servers and anti-cheats that tie container state to movement flag this. Sending C0D(0) at the wrong moment desyncs the container: clicks after the close are answered with S2FPacketSetSlot updates for a closed window. The NoSlow trick exploits the fact that a close plus a click on window 0 re-syncs the server's view of the held slot without cancelling the item use.

Server-Side Handling

processCloseWindow unconditionally runs closeContainer(): the carried item is dropped or returned, the open container is detached, and the player inventory container becomes active. No windowId validation, no cooldown. A C0D with no open container is ignored. Ordering against C0EPacketClickWindow matters: a C0D mid-batch ends the transaction window, and later C0E packets get S2FPacketSetSlot failure responses.

Protocol Analysis

One unsigned byte (writeByte(windowId)). Window 0 is the player inventory; S2DPacketOpenWindow assigns ids from 1 upward. Because the server ignores the id, module code freely alternates between C0D(0) and C0D(inventoryContainer.windowId). The packet is sent on the main thread from closeScreen(), so module-injected copies use raw send paths to avoid GUI state.

Anti-Cheat Landscape

NCP and similar treat container state as server truth: closing a window while C03 movement continues is normal, so cancelling C0D is itself the flag surface, not the movement. Anti-cheats also correlate the NoSlow ghost pattern (C0D(0) plus C0E(0, 36+slot, 6)) with item-use state. Blink-based disablers (Rise 6.x) buffer C0D inside the blink queue so its arrival timing is controlled rather than cancelled.

implementation Implementation Cases

The window-close packet. Inventory move modules cancel it to keep the server-side window open while walking, managers and stealers send C0D(0) to force-close after click batches, NoSlowModule pairs it with a click to ghost-swap items, and WatchdogDisabler fires it through the unregistered send path during blink.

CancelInventoryMove / InvMove / InventoryWalk (Rise 5.99, Rise 6.2.4, Rise 6.1.30, Sigma 4.11)

Keep the server-side inventory open while walking by cancelling the open and close packets, then force-pressing movement keys so the client moves with the GUI up.

NoSlowModule (Tenacity 6.0)

Cancel the server-side slowdown while eating or using items by ghost-swapping the held item: close window 0 and shift-click the current slot back.

While using an item with no GUI open, sendBypass() pushes C0DPacketCloseWindow(0) then C0EPacketClickWindow(0, 36 + currentItem, 0, 6, null, nextTransactionID) into the send queue, setting isItemGhost. The S2FPacketSetSlot cancels on receive keep the ghost state invisible.
