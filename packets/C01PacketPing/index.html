Notes

Sent after receiving S00PacketServerInfo. The server echoes the exact same long value in S01PacketPong. The client computes latency as receiveTime - sentTime.

Deep Dive

Role in the protocol

C01PacketPing is the STATUS-state latency probe. After S00PacketServerInfo arrives, OldServerPinger sends it with a single long field, and the server echoes the exact value back in S01PacketPong. The client computes the row latency as receiveTime minus sentTime, averages it over the last few samples, and displays it in the server list. RealmsServerStatusPinger sends the same packet with Realms.currentTimeMillis() on realm connections. This is the only ping in the protocol that exists outside the PLAY state; the tab-list ping later comes from the C00/S00 keepalive pair.

Vanilla handling

NetHandlerStatusServer.processPing is a pure echo: it sends S01PacketPong(packetIn.getClientTime()) with no transformation and no state change. OldServerPinger tracks a counter (field_175092_e) incremented per ping cycle and sends C01PacketPing with it; the pong handler then computes the round-trip against the stored send time. The packet's long value is opaque to the server: it never reads it beyond echoing, which is why the value can be any client-chosen timestamp.

Why clients touch it

Only Rise 6.1.30 and 6.2.4 BlinkComponent reference C01PacketPing, in the same pre-play exemption list as the other handshake packets. No ping-spoof module in the 8 clients targets it: every PingSpoof implementation operates on C00PacketKeepAlive in the PLAY state, where the server folds the round-trip into the tab-list ping EMA. Spoofing the STATUS ping would only fake the user's own server-list readout, which is a purely local number, so no module bothers. The corpus confirms the packet is otherwise untouched vanilla plumbing.

Exploit surface

There is no meaningful exploit surface. The value is client-chosen and server-echoed, so a client could lie about its own latency, but the result is displayed only to itself on the multiplayer screen and vanishes on join. Server scanners could skip the ping to save a round-trip per host, but none of the 8 clients implements one. The only code interaction is defensive: BlinkComponent must not buffer this packet, or the pinger's latency sample would stall and the server row would show a stale or zero ping.

Server-Side Handling

NetHandlerStatusServer.processPing sends S01PacketPong with the same long value, no validation, no rate limiting, no state change. The status handler is stateless by design: it answers queries and pings and expects the client to close the connection.

Protocol Analysis

STATUS state, id 0x01, one 8-byte long. Must follow C00PacketServerQuery and S00PacketServerInfo. The server never interprets the value; it is a client-chosen timestamp (OldServerPinger uses a counter, RealmsServerStatusPinger uses currentTimeMillis). The same field name family (C01) collides with the LOGIN-state C01PacketEncryptionResponse and the PLAY-state C01PacketChatMessage, so id-based dispatch depends entirely on the connection state.

Anti-Cheat Landscape

No anti-cheat measures the STATUS ping: it carries no player identity, no timing that persists, and no gameplay state. Anti-cheat plugins only ever see PLAY-state traffic. The only consumers are the server-list UI and reflection tools, neither of which is a flagging surface.

implementation Implementation Cases

The STATUS-state latency probe: client sends an arbitrary long, server echoes it, client measures the round-trip for the server list. No module spoofs it, because the result is a local display value; the sole corpus hit is BlinkComponent's exemption list.

BlinkComponent (Rise 6.1.30, Rise 6.2.4)

Exempt C01PacketPing from blink buffering so the server-list latency sample completes while blink is armed.

The hard-coded pre-play exemption list includes C01PacketPing alongside C00Handshake, C00PacketLoginStart, C00PacketServerQuery and C01PacketEncryptionResponse; the PacketSendEvent listener returns before the blink queue logic, so the ping always reaches the wire.

anticheat Anti-Cheat Checks
