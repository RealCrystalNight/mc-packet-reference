Deep Dive

Role in the protocol

S21PacketChunkData carries one chunk's block, light and biome data. Server send sites: PlayerManager sends a ground-up chunk on initial load (line 365 in the corpus) and section updates with a bitmask on the chunk update tick (line 447), EntityPlayerMP sends the player's spawn chunk with bitmask 65535, and S26PacketMapChunkBulk is the multi-chunk variant. Wire layout: chunkX int, chunkZ int, groundUpContinuous bool, bitmask unsigned short, dataLength VarInt, then zlib-compressed bytes holding per-section block IDs, block light, sky light and 256 biome bytes for ground-up chunks.

Vanilla handling

NetHandlerPlayClient.handleChunkData first handles unloads: a ground-up packet with bitmask 0 calls doPreChunk(false). Otherwise it invalidates the block receive region, fetches the chunk (loading it if missing), applies the extracted sections through chunk.func_177439_a, marks the range for render update, and resets relight checks for non-surface dimensions. This is the heaviest decompression and block-write path in the play state, and it runs on the client thread.

Why clients touch it

None of the 8 reference clients hook S21 in a module. The only non-vanilla corpus hit is Rise 6.1.30/6.2.4 NetworkAPI, which registers the class (clientbound index 76) so scripts can synthesize chunk packets. The XRay/Search/ChestESP entries from older docs reference Sigma 3.9, which is not in the reference set. Modules that want block data read the loaded Chunk object after vanilla applies it; rewriting chunk content would force them to decompress and re-encode the packed sections, which none of these clients does.

Exploit surface

Cancelling S21 empties the client's view of the world while the player stays in the server world, the core of chunk-void behavior; the server never notices because there is no acknowledgement. The heavier abuse is bandwidth: PlayerManager caps per-tick chunk traffic server-side, but a plugin that floods S21 can stall a client's single-threaded handler. On the client side, Rise 6.x scripts can call receivePacket with a fabricated S21 to draw fake terrain locally, which is render-only and has no server effect.

Server-Side Handling

PlayerManager sends ground-up S21 (bitmask 0, line 365) when a player enters a chunk's watch range, and section updates (groundUp=false, line 447) on the per-chunk update tick, batching changed sections into the bitmask. EntityPlayerMP sends the spawn chunk with all 16 sections (65535). Chunk data is extracted and zlib-compressed at send time; there is no inbound handler because the packet is clientbound.

Protocol Analysis

Each section in the bitmask contributes 4096 block IDs at 2 bytes each plus 2048 block-light and 2048 sky-light nibbles; ground-up chunks append 256 biome bytes. The data field is zlib-compressed as a whole, so the client must inflate it before touching any block. A ground-up packet with bitmask 0 means chunk unload, not empty data. S26PacketMapChunkBulk reuses S21PacketChunkData.Extracted for the bulk variant.

Anti-Cheat Landscape

Anti-cheats never measure S21; the server cannot tell what the client rendered. Chunk-based cheats (XRay, cave finder) are undetectable server-side in principle, which is why they are banned by staff rather than flagged. The client-side risk is stability: malformed or flooded chunk data crashes the vanilla handler, the basis of chunk-ban exploits that server plugins mitigate by validating senders.

implementation Implementation Cases

Chunk payload delivery with zero module usage in the 8 reference clients: block-aware features read the loaded world instead of hooking the packet, and the only non-vanilla reference is the Rise 6.x script registry entry.

No module in the 8 clients registers a receive handler for S21. Rise 6.x exposes the class to scripts via NetworkAPI; all other references are vanilla net/minecraft files.
All 8 clients ship the vanilla handleChunkData. Rise 6.1.30/6.2.4 additionally list the class in NetworkAPI; Memeware, Nekoware, Sigma, Spicy and Tenacity differ only in the bundled vanilla source revision.

anticheat Anti-Cheat Checks

S21 delivers a full chunk column to the client, and it is the transport that makes xray and world-downloader cheating possible. Server-side anticheats approach it from two directions: xray checks score ore-breaking behavior (BAC XRayCheck, AntiCheatPlus XRayListener, Negativity XRayProtocol), sentinel modules neutralize world downloaders at the plugin-message level (Photon WorldDownloaderSentinel), and simulation anticheats parse the chunk bytes into a compensated world so their movement and phase checks see the same blocks the client sees (Grim PacketWorldReaderEight, Hydro WorldTracker, Truthful CompensatedWorld, Kauri Chunk and World, Intave block caches). The corpus for S21 is dominated by the replication side, because every block-based check depends on it.

XRayCheck (BasicAntiCheat) (MC-Jinky-BasicAntiCheat)

Ghost-block xray heuristic: spawn fake ore blocks in front of the player and flag anyone who breaks them.

On BlockBreakEvent, when the player breaks an ore, the check walks up to 9 blocks in the player's facing direction and replaces a buried stone block with the same ore type, recording it as a ghost block with a proximity counter. On PlayerMoveEvent, ghost blocks that the player approaches too often and then breaks (5 or more close encounters) fail the check; sneaking while standing over a block also registers it. The check is marked as heavy beta in the config.

Detects: Xray users who path straight to ores through solid rock and break ghost blocks that were never visible.

PacketWorldReaderEight (Grim) (GrimAnticheat-Grim)

Parse the raw S21 chunk data bytes into Grim's compensated world so simulation checks see the exact blocks the client received.

BasePacketWorldReader dispatches the outbound chunk packets: handleMapChunk reads the chunk x/z, ground-up flag, section mask and size, decodes each 16-section column with the 1.8 endian-flipped palette reader, skips biome and light arrays, and merges the result into the compensated world cache with the transaction id. The 1.9+ and 1.18 readers are separate implementations; unloads are queued via removeChunkLater.

Detect WorldDownloader mods and disable their chunk caching, entity saving and container saving over the wdl plugin-message channel.

Registers the wdl/init and wdl/control plugin-message channels.
