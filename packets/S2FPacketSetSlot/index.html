Notes

windowId=-1 special case: updates the cursor item (the item held by the mouse cursor). windowId=0: updates player inventory. S2F is sent for EVERY slot change — armor equips, hotbar changes, cursor picks up/drops. Inventory modules track S2F to detect armor swaps and item pickups.

Deep Dive

Role in the protocol

S2FPacketSetSlot is the single-slot inventory sync packet, the fine-grained counterpart to the S30 full-window dump. The server emits it for every slot mutation: EntityPlayerMP.updateCraftingInventory pushes windowId/slot/stack on each container change, the cursor is synced with the (-1, -1) variant after clicks settle (lines 760, 774, 805), NetHandlerPlayServer line 554 re-sends the held hotbar slot after a swap, and ItemEditableBook pushes the signed book back into slot 0. windowId -1 means the cursor, 0 means the player inventory, anything else the open container.

Vanilla handling

NetHandlerPlayClient.handleSetSlot resolves the target container from the window id: -1 sets the player's cursor stack, 0 and the player inventory window id write into inventoryContainer, otherwise the open container receives the slot. The matching GuiScreen is notified so the renderer updates. There is no validation: the client trusts the server's slot content unconditionally, which is exactly the trust that cancel-based modules exploit. The vanilla client never sends S2F; it is strictly clientbound.

Why clients touch it

Four distinct uses in the 8 clients. Rise 5.99 Auto sniffs S2F for the Redesky captcha item and clicks it with a crafted C0E. Rise 5.99 Scaffold and Spicy BlockFly cancel every S2F so the server cannot correct the hotbar while they place blocks. Tenacity 6.0 NoSlowModule cancels window-0 slot updates while using a non-sword item, keeping the ghost-item no-slow state alive. Rise 6.x AdaptiveRefreshRateComponent treats S2F as a significant packet that forces a HUD cache redraw, and PacketUtil exposes a wrapper for the script API.

Exploit surface

Cancelling S2F is a local lie that only survives until the next window resync: the server owns slot state, and a rejected click (S32 accepted=false) triggers a full S30 dump that snaps the client back. That makes S2F cancellation a short-horizon trick, useful inside a single click loop, not a persistent desync. For inventory modules the packet is a cheap signal: an armor swap or a hotbar change arrives as one small packet, so AutoArmor-style logic can react without parsing a window. The trade-off is ordering: any module that cancels S2F upstream silently blinds every other module that reads it.

Server-Side Handling

EntityPlayerMP.updateCraftingInventory sends S2F(windowId, slot, stack) per slot change and the cursor variant (-1, -1) after click processing (lines 760, 774, 805 in the bundled sources). NetHandlerPlayServer line 554 re-sends the held item slot after a hotbar swap; ItemEditableBook line 116 pushes the signed book into slot 0. There is no rate limit and no client-side validation: handleSetSlot writes the slot into the resolved container and notifies the open GUI.

Protocol Analysis

Wire layout: byte windowId, short slot, then a Slot encoding (short item id, byte count, short damage, optional NBT; item id -1 encodes null). windowId -1 (0xFF) targets the cursor, 0 the player inventory, other values the open container. S2F is PLAY-state only and always carries exactly one slot, which is what makes it the cheapest way for a module to detect an armor equip or hotbar change. The cursor variant pairs slot -1 with windowId -1.

Anti-Cheat Landscape

No anti-cheat measures S2F: it is server-authoritative display state. The abuse is purely client-side view desync, and the detection surface is the eventual resync: a server that rejects a click re-sends S30, and any client that still behaves as if the old slot content exists is visibly desynced. Cancel-heavy movement modules (Scaffold, BlockFly) therefore risk inventory desync that manifests as phantom hotbar items rather than a flag.

implementation Implementation Cases

The single-slot sync packet and the cheapest inventory signal on the wire. Rise's Auto reads it to click captcha items, Scaffold and Spicy's BlockFly cancel it to freeze the hotbar, Tenacity's NoSlow cancels window-0 updates to preserve a ghost item, and Rise 6.x treats it as a HUD-significant packet. The server always owns slot truth; cancelling only delays the client's view.
