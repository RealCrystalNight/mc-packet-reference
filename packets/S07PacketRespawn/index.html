Notes

After receiving this, the client resets chunk loading, clears all entities, sends C00PacketKeepAlive to re-sync, and sends a C03/C06 position packet. The packet is used both for death respawn (same dimension) and portal dimension changes (dimension changes).

Deep Dive

Role in the protocol

The respawn and dimension-change control. The server sends it on death respawn (ServerConfigurationManager line ~496), on portal dimension transfer (NetHandlerPlayServer line ~587, ServerConfigurationManager line ~473) and on gamemode changes; the payload is dimension id, difficulty, terrain type and gamemode. The client must treat it as a world-reload command: clear entities, rebuild chunk state, re-arm keepalive and re-sync position.

Vanilla handling

handleRespawn branches on the dimension: an equal dimension is a soft reset that rebuilds the player entity in place, a different dimension triggers a full world load with chunks unloaded, entities cleared and the player respawned. PacketThreadUtil special-cases S07 so the reload runs on the main thread and pre-processes the world transition before ordinary packet handling resumes. Every module that buffers per-world state (blink queues, transaction lists, teleport buffers, freecam position) must flush on this packet or carry stale state across the boundary.

Why clients touch it

The corpus reaction surface is exactly the flush pattern, and it lives in the disabler machinery. Rise 6.1.30 WatchdogDisabler clears its position, transaction and blink queues plus both stopwatches on S07; Rise 6.2.4 keeps only the import. UniversoCraftDisabler (both builds) uses S07 to arm a respawn-window transaction corruption. Tenacity 6.0 AdvancedDisablerModule carries a commented-out S07 import, evidence the reset was planned and disabled. No Freecam, AutoTool or inventory module hooks S07 in this corpus even though world reload visibly resets their state; those clients rely on vanilla world-load callbacks instead of the packet.

Exploit surface

The respawn window is the attack surface: after S07 the server re-arms the player's transaction stream, so replaying C0F uids from the previous world desynchronizes the server's bookkeeping. UniversoCraftDisabler weaponizes the window by overwriting C0F uids with Short.MIN_VALUE or Short.MAX_VALUE for the first 350 ticks after respawn, alternating on tick parity. Anti-cheats that key transaction continuity off confirm/transaction pairs are the target. S07 itself is server-authored and not client-spoofable in the vanilla protocol, so the client side is purely defensive: flush old state, then corrupt the new window.

Server-Side Handling

ServerConfigurationManager sends S07 on death respawn (line ~496) and on dimension transfer (line ~473), NetHandlerPlayServer sends it on its own dimension-change path (line ~587 in MCP builds), always with the player's current dimension, difficulty, terrain type and gamemode. After sending, the server waits for the client's position re-sync (C03/C06) before resuming normal tracking. The client never sends S07; the closest serverbound step is C16 PERFORM_RESPAWN from the death screen.

Protocol Analysis

Fields in order: int dimension, unsigned byte difficulty, unsigned byte gamemode, String level type. PacketThreadUtil pre-processes S07 in Rise 6.1.30/6.2.4 and Tenacity (lines ~31 and ~40 respectively), forcing the world transition onto the main thread ahead of queued packets. The dimension field is the branch key: equal dimension means soft reset, different dimension means full reload, and modules keying state resets on S07 catch both cases in one hook.

Anti-Cheat Landscape

Transaction-continuity anti-cheats (Watchdog, Verus) reset their per-player counters on respawn, which is why stale C0F uids replayed across the boundary flag. The UniversoCraft corruption window targets exactly this reset: uid values of Short.MIN_VALUE and Short.MAX_VALUE alternating on tick parity are chosen to break the server's expectation of monotonic actions without a visible cancel pattern. The flush side (WatchdogDisabler) is the defensive mirror and is invisible; the corruption side is the detectable one if the server validates uids.

implementation Implementation Cases

The world-reload command: death respawn, portal transfer and gamemode change all arrive as S07, and the client tears down and rebuilds world state in response. In this corpus the packet is consumed by disabler state machines (Rise WatchdogDisabler flush, UniversoCraftDisabler corruption window) and was planned-but-disabled in Tenacity's AdvancedDisablerModule.

Hypixel Watchdog disabler mode that uses S07 as the hard reset point for its buffered packet state.

UniversoCraftDisabler (Rise 6.1.30, Rise 6.2.4)

UniversoCraft disabler mode that arms a respawn-window transaction corruption from the S07 packet.

On the packet send listener, S07 sets disabling=true; C02PacketUseEntity clears it; C03PacketPlayer within the first 10 ticks sets it; and while disabling with ticksExisted below 350, every C0FPacketConfirmTransaction gets its uid overwritten with Short.MIN_VALUE or Short.MAX_VALUE alternating on tick parity. The S07 branch is redundant in practice because the C03-within-10-ticks branch arms the same flag, and its usefulness depends on the client's event wiring delivering clientbound packets to this listener.

anticheat Anti-Cheat Checks

The respawn packet is a state-reset command: the world reloads, so every anticheat that keeps per-player state must re-arm it on respawn. Simulation anticheats parse WrapperPlayServerRespawn on the send side and rebuild their player model (Grim, Shard, Artemis), while classic anticheats zero grace timers on PlayerRespawnEvent so freshly respawned players are not flagged by movement and combat checks. The packet itself is never flagged; it is the boundary that makes the checks after it trustworthy.

PacketPlayerRespawn (Grim) (GrimAnticheat-Grim)

Reset the entire simulated player model on respawn and dimension change: positions, ground flags, attributes, entity list and the death-screen state.

The RESPAWN branch wraps the packet as WrapperPlayServerRespawn, invalidates the setback teleport (hasAcceptedSpawnTeleport = false), clears server entity positions on world change, and schedules a real-time task that resets onGround, pose, sprinting, food, known input, the self PacketEntity and the BadPacketsE/G/M/F state. KEEP_TRACKED_DATA and KEEP_ATTRIBUTES flags decide what survives on 1.20.2+; isWorldChange compares world name or dimension type to detect cross-dimension teleports that wipe chunks and entities.

Detects: Nothing directly. It prevents stale movement state (old ground flags, old velocity, old entity ids) from leaking across the respawn boundary, which would poison every downstream check.
