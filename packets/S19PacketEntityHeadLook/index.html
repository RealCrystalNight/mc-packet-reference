Notes

Head yaw is separate from body yaw — entities can look in a different direction than they're moving. Used by Backtrack modules to track the full entity rotation, and by ESP modules for accurate head-position aim prediction.

Deep Dive

Role in the protocol

S19PacketEntityHeadLook updates only the head yaw of an entity, independent of the body yaw carried by S16/S17. The wire format is a VarInt entityId plus one byte decoded as yaw * 360 / 256. The server sends it whenever the head rotation changes: EntityTrackerEntry broadcasts it to tracked players (corpus line 236, sendPacketToTrackedPlayers(new S19PacketEntityHeadLook(trackedEntity, (byte) l))) while body rotation travels in the S14 family. It is the only rotation packet keyed to the head rather than the body.

Vanilla handling

NetHandlerPlayClient.handleEntityHeadLook (Memeware 7.3 bundle, line 573) resolves the entity and calls setRotationYawHead(yaw * 360 / 256.0F). Only yaw is transmitted; the head pitch is derived from the body pitch at render time, and the model's head mesh rotates around the neck joint using this value. The body rotation is untouched, which is why a player can look sideways while running straight.

Why clients touch it

None of the 8 clients has an ESP, Tracers or KillAura module that reads S19. The corpus consumers are all Rise 6.x infrastructure and one velocity module: WatchdogVelocity includes S19 in the spoof packet set so a held head-look update completes the backtrack illusion, PingSpoofComponent classifies it in the players tuple (delayed with the S14 family and S18), the translation PacketType maps ENTITY_HEAD_LOOK into the position cache, and NetworkAPI whitelists it for scripts in both 6.1.30 and 6.2.4. Renderers skip it because aim indicators are derived from body yaw/pitch in S16/S17; head yaw only affects the model mesh.

Exploit surface

The packet is cosmetic clientbound state with no serverbound counterpart and no server-side validation, so there is no direct abuse. The interesting quirk is in the translation cache: ENTITY_HEAD_LOOK writes the decoded head yaw into the Position.yaw slot while keeping pitch, so the cached orientation becomes the head yaw until the next S16/S17 overwrites it. Any aim or rotation math fed from that cache inherits the error. Backtrack modules that hold S19 along with the movement set produce the visible frozen-head artifact, which is a staff-visible tell rather than a detection risk.

Server-Side Handling

Clientbound only. The server emits it from EntityTrackerEntry when the tracked entity's head yaw changes, and the client applies it as setRotationYawHead with the * 360 / 256 decode. There is no rate limit or validation; a server can spam it harmlessly. The client-side consequence is limited to the model's head rotation and any module that consumes rotation state.

Protocol Analysis

Single byte angle, decode yaw * 360 / 256.0F. Body yaw lives in S16/S17; head yaw lives here; the two can differ by up to 180 degrees for a player looking over the shoulder. S19 arrives at the same tracking cadence as the S14 family and typically interleaves with it. The translation cache's ENTITY_HEAD_LOOK handler overwrites the yaw slot, so cached positions diverge from vanilla rotation semantics until the next look packet.

Anti-Cheat Landscape

No server anticheat consumes head yaw; killaura rotation-sync detection works on the serverbound C05/C06 look packets, not on this clientbound announcement. For cheat clients the only relevance is fidelity: backtrack and reach modules that reconstruct entity state must either include S19 in the held set (WatchdogVelocity) or accept that the reconstructed orientation drifts. There is no flag surface, only visual artifacts.

implementation Implementation Cases

The head-look packet is the least-touched entity packet in the corpus: no renderer or aim module in the 8 clients reads it. It survives only in Rise 6.x packet-classification components (PingSpoofComponent, translation PacketType) and WatchdogVelocity's backtrack set, plus the script API whitelist.

PacketType (translation component) (Rise 6.1.30, Rise 6.2.4)

Write the decoded head yaw into the per-entity position cache used by the translation system.

ENTITY_HEAD_LOOK decodes headYaw as getYaw() * 360 / 256.0F, looks up the entity's cached Position and stores new Position(posX, posY, posZ, headYaw, currentPitch). It returns null when no entry exists, so head-look updates for entities that never spawned through the cache (no S0F/S0C seen) are silently dropped.
