Deep Dive

Role in the protocol

The vehicle steering packet. Every tick while the player rides a boat, horse or pig, EntityPlayerSP.onUpdateWalkingPlayer sends C0CPacketInput with strafeSpeed (moveStrafing), forwardSpeed (moveForward), the jump flag and the sneak/unmount flag. The server applies these to the ridden entity via setEntityActionState, which drives boat paddling, horse jump charging and pig steering. The empty constructor used by every module in the corpus defaults to (0.0F, 0.0F, false, false): a request to stop all input.

Vanilla handling

NetHandlerPlayServer.processInput calls playerEntity.setEntityActionState(strafeSpeed, forwardSpeed, isJumping, isSneaking) with no validation on the floats. The values feed the ridden entity on the next tick: forward and sideways map to boat rowing velocity and pig steering angle, the jump flag charges a horse jump. Because the floats are applied directly, absurd magnitudes propagate straight into vehicle motion.

Why clients touch it

Every real use in the 8 clients is disabler-side. Memeware's AACv1.9.10 and Ghostly modes inject an empty C0C before each C03PacketPlayer; Nekoware's Ghostly mode sends one every 10 ticks; Rise 5.99's Disabler sends empty C0C (verusOld, ghostly), (0.98F, 0.0F, false, false) (coc) and (Float.MAX_VALUE, Float.MAX_VALUE, false, false) (funnyCraft); Spicy's Disabler cancels C0C outright. Rise 6.x splits the pattern into VehicleDisabler, InputDisabler and GhostlyDisabler modes. Nekoware's Fly Damage mode sends empty C0C before its fall packets.

Exploit surface

The server applies input floats without clamping, so extreme values distort vehicle physics and desync the server's vehicle state from the player's C03 position stream, which movement anti-cheats then flag. An empty C0C freezes the boat server-side while the client moves freely, the classic BoatFly primitive. Cancelling C0C (Spicy) makes the server keep the player's input stale, which some anti-cheat versions read as a mounted state inconsistent with C03 movement.

Server-Side Handling

processInput forwards the four fields verbatim into setEntityActionState; EntityPlayer feeds them to the ridden entity each tick. Boat motion is rowing ticks derived from forward input, horse jump is a charged power from the jump flag hold, and the sneak flag dismounts. There is no clamp, no rate limit, and no check that the player is actually riding.

Protocol Analysis

Four fields: two floats (strafe, forward), two booleans (jump, sneak/unmount). Sent once per tick while ridingEntity is non-null; vanilla sends it even when all inputs are zero. The default constructor (0, 0, false, false) is the module workhorse, injected as a stop-input reset. Float.MAX_VALUE pairs decode normally and are applied unclamped. Wire order: strafe, forward, jump, sneak.

Anti-Cheat Landscape

Vehicle checks compare C0C input against the motion the server applies to the boat or horse and against the player's C03 position stream. Float.MAX_VALUE input alongside normal C03 movement is a classic desync flag; empty C0C spam is low risk because zero input is legitimate when standing still in a boat. NCP-era disablers used the empty-C0C reset to clear vehicle and water checks right before each C03.

implementation Implementation Cases

The vehicle input packet. No client in the corpus uses C0C for direct BoatFly-style speed; every real use is a disabler injecting empty or extreme C0C values to corrupt server-side input state, plus Spicy cancelling it and Nekoware pairing it with fall packets in Fly.

anticheat Anti-Cheat Checks

The input packet, also called steer vehicle, is sent every tick while riding a boat or horse, carrying forward and sideways axes plus the jump and unmount flags. It is the only stream that tells the server what the rider wants to do, so vehicle movement checks pair it with the vehicle move packet: impossible axis values, steering while not in a vehicle, and input that does not match the predicted vehicle motion are all C0C signatures. Boat fly and boat speed cheats are detected by comparing the claimed input against the vehicle's actual motion.
