Deep Dive

Role in the protocol

Server-to-client broadcast of a named sound at a fixed-point position. The server computes a delivery radius of 16 blocks, scaled by volume when volume exceeds 1.0, and fans the packet out through ConfigurationManager.sendToAllNear. The client handler converts the x8 fixed-point ints back to doubles and hands the call to World.playSound. Because the sound name is an arbitrary server-controlled string, the field is both a gameplay input and a data-injection surface for anything downstream that logs or parses it.

Vanilla handling

NetHandlerPlayClient.handleSoundEffect does PacketThreadUtil.func_180031_a (main-thread marshalling) then World.playSound(name, x/8, y/8, z/8, volume, pitch/63, false). The pitch arrives as an unsigned byte with 63 meaning normal pitch; the client divides by 63.0F. Server side the packet is created by WorldManager.playSound and playSoundAtEntity, and by /playsound (CommandPlaySound), which converts double coordinates to the x8 int encoding. Netty reads the name with a 256-char cap via readStringFromBuffer(256).

Why clients touch it

Only two real handlers exist across the 8 clients, and neither is a sound-ESP. Rise 5.99's Disabler, in its HypixelSlime mode, cancels the mob.slime.big sound to strip the Hypixel double-jump slime indicator. Rise 6.1.30 and 6.2.4 route the packet through LoggerRCECheck, a security feature that matches the sound name against a ${...} pattern to catch Log4j RCE attempts (CVE-2021-44228): sound names are logged by the client logger, so a crafted name is an injection vector. No client in the corpus tracks sounds for ESP purposes.

Exploit surface

The sound name string is the interesting field. It passes through String formatting and logger calls on both ends, which is exactly the Log4j RCE chain that LoggerRCECheck defends. Volume has no clamp on the wire, so a malicious server can send volume values far above 1.0 and inflate the client-side audio range beyond the 16-block visibility radius. The pitch byte is unsigned, so values above 127 encode negative pitches when interpreted as signed, a quirk modules rarely bother with.

Server-Side Handling

WorldManager.playSound sends to all players within 16 blocks, or 16*volume when volume > 1.0F, on the same dimension. CommandPlaySound builds the packet from parsed coordinates (x*8, y*8, z*8) and clamps pitch to 0..255 before writing. The client handler marshals to the main thread, then plays the sound with pitch = raw byte / 63.0F. No server-side rate limit exists; sound spam is only bounded by the 256-char name cap and the per-packet cost.

Protocol Analysis

Encoding order: String name (max 256), int x*8, int y*8, int z*8, float volume, unsigned byte pitch. The y field is initialized to Integer.MAX_VALUE in the no-arg constructor as a sentinel for the client-side y-clamping fallback (field_149218_c). In 1.8.9 MCP this packet predates the generic Packet<T> signature, so it implements raw Packet and does a double dispatch through processPacket.

Anti-Cheat Landscape

Anti-cheats do not flag sound packets; they are cosmetic. The abuse surface is the name string, and the relevant defense is client-side: Rise's LoggerRCECheck pattern-matches ${...} in the name to block Log4j RCE payloads that would otherwise execute through the client's logging pipeline. Because the packet is clientbound and server-trusted, there is no bypass trade-off: a compromised server can always send it, so the check is a pure filter.

implementation Implementation Cases

A pure world-effect broadcast: named sound, x8 fixed-point position, volume, pitch byte. The 8 clients barely touch it. The only module-grade hit is Rise 5.99's Disabler cancelling the Hypixel slime jump sound; Rise 6.x handles it as a Log4j RCE scan surface rather than as audio.

anticheat Anti-Cheat Checks

The named-sound packet is the one sound packet in this family that a major anticheat actively intercepts. NoCheatPlus ships SoundDistance, a ProtocolLib listener on PacketType.Play.Server.NAMED_SOUND_EFFECT that cancels wither, enderdragon and lightning sounds when the player is too far from the sound origin, which removes fake distant-boss audio and reduces client noise. The rest of the corpus is registration plumbing: Artemis maps the packet name to a wrapper interface, and Negativity lists it in its packet-type registry. Bukkit playSound calls in Hydro, TruthfulAC and SafeguardAC are anticheat GUI sounds, not S29 handling.

SoundDistance (NoCheatPlus) (Updated-NoCheatPlus-NoCheatPlus)

Cancel named sound packets for wither, enderdragon and lightning events when the player is beyond the configured audible radius of the sound origin.

A ProtocolLib BaseAdapter registered at ListenerPriority.LOW on PacketType.Play.Server.NAMED_SOUND_EFFECT (S29). It maintains a hardcoded set of boss and weather sound names (pre-1.9 resource keys plus 1.9 and 1.21 enum names), matched against the packet's sound field via getStrings().read(0) on legacy servers or the Bukkit access matchSounds() on modern ones. For a match it computes the squared horizontal distance between the player and the packet's x8 fixed-point position and cancels the packet when that exceeds the configured soundDistanceSq limit, counting each cancel on the packet.sound.cancel counter.

Detects: Server-side sound spoofing where distant boss spawns or weather events are audible to players who should not hear them; the check doubles as client-noise reduction.
