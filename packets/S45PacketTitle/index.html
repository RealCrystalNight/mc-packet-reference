Deep Dive

Role in the protocol

Screen title display with five actions: TITLE, SUBTITLE, TIMES, CLEAR and RESET. The vanilla server produces it from the /title command (CommandTitle), and plugins use it for game announcements. TITLE and SUBTITLE carry an IChatComponent, TIMES carries three ints (fade-in, stay, fade-out in ticks), and CLEAR and RESET carry no text. The client handler routes everything into GuiIngame.displayTitle, which owns the fade state machine.

Vanilla handling

handleTitle reads the type, formats the component text, and calls ingameGUI.displayTitle(title, subtitle, fadeIn, displayTime, fadeOut). GuiIngame stores the strings plus the three timings and animates alpha over ticks. RESET clears both text slots and restores default timings (10/70/20); CLEAR hides immediately. The packet is clientbound-only and stateless server-side: the server tracks nothing about what the client currently displays.

Why clients touch it

Two module hits in the corpus. Rise 6.1.30 and 6.2.4 ship RueSessionStats, a SessionStats HUD mode that listens on PacketReceiveEvent, strips control codes from the title message, and increments its wins counter when the text equals 'VICTORY!' (Hypixel game-win detection). November Recode 2.0's AutoPlayModule pattern-matches S45PacketTitle inside its packet-in handler but only null-checks the message; the branch carries no behaviour, so the title serves as a guard against a null component rather than a signal. Anti-title modules that suppress or rewrite titles are common in other clients, but none of the 10 reference clients has one: the corpus shows no cancel-based title handling.

Exploit surface

The text is a full IChatComponent parsed client-side, so it shares the component-parsing attack surface of S02PacketChat, including formatting codes and arbitrarily nested JSON. The handler calls getFormattedText() with no length limit beyond the component parser's own. For module authors the useful property is that titles are a timing-accurate game-state signal: Hypixel sends VICTORY! exactly once per win, which is why the win counter keys off it rather than chat.

Server-Side Handling

CommandTitle constructs the packet per /title syntax: TIMES from three parsed ints, TITLE and SUBTITLE with a ChatComponentProcessor-processed component, CLEAR and RESET with a null component. The server keeps no per-client title state; each packet is fire-and-forget. Plugins such as Hypixel send titles directly with their own timing sequences, typically TIMES followed by TITLE.

Protocol Analysis

Type is a VarInt enum. TITLE and SUBTITLE append an IChatComponent (JSON); TIMES appends three ints; CLEAR and RESET append nothing. readPacketData reads the component only for TITLE and SUBTITLE and the three ints only for TIMES. The component is null on the wire for TIMES, CLEAR and RESET, and handlers must tolerate that; RueSessionStats and November's AutoPlayModule both null-guard the component before use.

Anti-Cheat Landscape

No anti-cheat involvement: titles are cosmetic, clientbound and unacknowledged. Suppressing or rewriting them cannot affect server-side validation. The only measurable behaviour is client rendering, which is invisible to the server.

implementation Implementation Cases

Screen title state machine fed by /title and plugin announcements. Rise's RueSessionStats HUD mode uses the VICTORY! title as a win signal for its session stats counter; November Recode 2.0's AutoPlayModule pattern-matches S45PacketTitle with a null-message guard only. No anti-title module exists in the 10 clients.
