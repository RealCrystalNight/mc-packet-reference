Notes

Deep Dive

Role in the protocol

The server orders the client to load a resource pack. Two strings travel: the URL and a SHA-1 hash used for integrity. The vanilla flow downloads the pack, applies it and answers with C19PacketResourcePackStatus (ACCEPTED, DECLINED, FAILED_DOWNLOAD, SUCCESSFULLY_LOADED). The level:// scheme is the sharp edge: vanilla maps level://name to a file inside the local saves directory, so the URL doubles as a local file path.

Vanilla handling

handleResourcePack branches on the scheme. level:// URLs resolve against mcDataDir/saves: if the file exists the pack loads and ACCEPTED then SUCCESSFULLY_LOADED are sent; if not, FAILED_DOWNLOAD. HTTP(S) URLs go through the resource pack repository asynchronously, with a GUI prompt unless the server's resource mode is ENABLED or DISABLED.

Why clients touch it

Two defensive families in the corpus. Rise 6.1.30 and 6.2.4 run ResourcePackCheck as a SecurityFeature: it validates the scheme, decodes the level:// path, and rejects any URL containing ".." or not ending in /resources.zip, answering with C19 FAILED_DOWNLOAD. Tenacity's AntiExploit module cancels the packet and sends FAILED_DOWNLOAD for the same classes of malicious URLs. Both target the level:// traversal that reads arbitrary files from the saves folder.

Exploit surface

A level:// URL with ../ segments walks out of the saves directory into other local files, which the client then loads as a resource pack; vanilla does not verify the hash for level:// packs. Replying FAILED_DOWNLOAD keeps the server's state machine consistent so it stops waiting for a status, which is why both defenses send C19 rather than silently dropping the packet.

Server-Side Handling

Server side, the packet is built by EntityPlayerMP.loadResourcePack or sendResourcePack with an arbitrary URL and hash supplied by plugins or server config. The server waits for a C19 status before re-prompting; a client that never replies eventually stops receiving pack offers. The hash is echoed back verbatim in C19.

Protocol Analysis

Two strings: URL and SHA-1 hash. The level:// scheme is special-cased client-side, and the hash is ignored for level:// packs in vanilla. C19 carries the same hash back, so the status reply identifies which offer it answers. The packet id 0x48 is clientbound-only in PLAY state.

Anti-Cheat Landscape

Not a movement or combat surface: no anti-cheat measures S48 traffic. The defense angle is client security (file disclosure via level://), and both corpus implementations are client-side self-defense rather than anti-cheat bypasses.

implementation Implementation Cases

The resource pack push. Rise 6.x defends it as a SecurityFeature (ResourcePackCheck) and Tenacity as an AntiExploit module; both reject level:// path traversal URLs and reply C19 FAILED_DOWNLOAD to keep the server's status state machine moving.

ResourcePackCheck (Rise 6.2.4, Rise 6.1.30)

Block malicious resource pack offers, specifically level:// URLs that read local files, before the vanilla download flow runs.

A SecurityFeature (not a toggleable module) whose handle() inspects every packet: for S48 it takes the URL and hash, and only acts on level:// URLs. The URL is parsed as a URI, the scheme must be http, https or level, and a decoded level path containing ".." or not ending in /resources.zip is rejected with C19 FAILED_DOWNLOAD. The attempted path is printed to stdout.

AntiExploit (Tenacity 6.0)

Cancel malicious resource pack offers inside a general anti-exploit module, replying FAILED_DOWNLOAD so the server does not stall.

PacketReceiveEvent handler: for S48 the URL is parsed as a URI; non-http(s)/level schemes cancel the packet, and level:// URLs containing ".." or not ending in /resources.zip are cancelled with a C19 FAILED_DOWNLOAD reply. URISyntaxException also cancels with FAILED_DOWNLOAD. The same handler guards S43PacketCamera, S2APacketParticles, S27PacketExplosion, S18PacketEntityTeleport and S11PacketSpawnExperienceOrb, plus a 100-packet-per-second counter.
