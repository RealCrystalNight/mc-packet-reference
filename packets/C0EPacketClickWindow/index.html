Deep Dive

Role in the protocol

C0E is the inventory click packet: windowId, slotId, usedButton, mode, clickedItem (the server's copy of the stack being clicked), and an action number. The server runs openContainer.slotClick and confirms with S32PacketConfirmTransaction only when the clicked-item copy matches; otherwise it re-sends the whole container. It is the only way to move items programmatically, so every inventory automation module funnels through it, either by constructing it directly or through PlayerControllerMP.windowClick.

Vanilla handling

processClickWindow verifies the window id matches the open container and that crafting is allowed, then runs slotClick(slotId, button, mode, player). If the returned stack equals packetIn.getClickedItem() it confirms with S32 (accepted = true) and resyncs; otherwise it stores the action number in a pending map, sends S32 accepted = false, and force-syncs the container. The windowId 0 check matters: clients must match the current window or the click is silently dropped.

Why clients touch it

In the 10-client corpus C0E is used by inventory managers (Sigma InventoryManager via PlayerControllerMP.windowClick), inventory-move modules (Rise 5.99 InvMove cancels and re-wraps C0E with C16+C0D), the Rise 6.2.4 BufferAbuseInventoryMove exploit (sends empty C0E packets to abuse the transaction buffer), captcha bots (Rise 5.99 Auto clicks the Redesky captcha item), and Tenacity NoSlowModule (clicks the armor slot to swap the held item). Note that ChestStealer and AutoArmor in this corpus route through C16 open-inventory status, not C0E clicks. LiquidSense Dev overwrites PlayerControllerMP.windowClick to fire a cancelable ClickWindowEvent before every C0E send, and November Recode 2.0 registers C0E in its Lua scripting packet-id map (0x0E) so scripts can observe and cancel it, but ships no click module of its own.

Exploit surface

The action number and clicked-item echo are the attack surface. Sending clicks with a stale or forged clickedItem makes the server resync the container, which some disablers use to flood the transaction pipeline. BufferAbuseInventoryMove exploits the server's transaction accounting by sending clicks the server must answer, delaying watchdog's transaction-based checks. The windowId mismatch is a silent drop, which InvMove uses to cancel clicks and re-send them under a fake open-inventory state. LiquidSense's windowClick overwrite computes the container transaction id and then discards it, sending (short) -1; the server never validates the action number against a counter, it only echoes it in the S32 reply, so the click confirms the same way a real id would and the client container counter is left stale.

Server-Side Handling

processClickWindow: windowId must equal openContainer.windowId and crafting must be allowed. slotClick mutates the container; on clickedItem match the server confirms (S32 true) and resyncs, on mismatch it stores the action number, sends S32 false, and force-syncs all slots. Crafting players get a full container resend instead of a click.

Protocol Analysis

Fields: windowId byte, slotId short, usedButton byte, mode byte, clickedItem (ItemStack or null), actionNumber short. Window 0 is the player inventory; chests start at 1. The clickedItem must be the exact stack the server last sent for that slot, which is why clients cache S2FPacketSetSlot/S30PacketWindowItems state.

Anti-Cheat Landscape

Anti-cheats track click rate and window state. Inventory move (clicking while moving) is detected by comparing C0E timing against movement packets; CancelInventoryMove in Rise 6.2.4 exists to cancel the C16 open-inventory status so the server never learns the inventory is open. Transaction flooding via C0E is a disabler vector against Watchdog, which uses transaction gaps to time its checks.

implementation Implementation Cases

The programmatic inventory click. Inventory managers click through it, InvMove re-wraps it, BufferAbuseInventoryMove floods it, and a captcha bot clicks with it. Its confirm/resync loop is what makes it both reliable for automation and exploitable for transaction flooding. LiquidSense Dev adds the ClickWindowEvent mixin that lets any module veto clicks, and November Recode 2.0 exposes the packet to Lua scripts.
