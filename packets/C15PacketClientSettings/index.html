Notes

Sent by vanilla client every time settings change. The server stores locale for player language detection. View distance affects how many chunks the server sends. Rise 6.0 ClientSpoofer sends spoofed C15 to change the locale string for server-side language detection bypass and to set a fake view distance.

Deep Dive

Role in the protocol

C15 declares client preferences: locale string, render distance byte, chat visibility enum, chat colors flag and a model-part bitmask. Vanilla re-sends it from GameSettings whenever any of those settings change, and the server stores the values on the player. It is the only serverbound packet that carries the client's locale, which makes it the hook for server-side language detection.

Vanilla handling

processClientSettings delegates to EntityPlayerMP.handleClientSettings, which stores translator (locale), chatVisibility and chatColours on the player and pushes the model-part flags into DataWatcher slot 10. The render distance byte is parsed but not stored by the bundled 1.8.9 handler; chunk streaming distance stays server-configured. The locale is what language-detection plugins read.

Why clients touch it

None of the 8 clients ships a locale-spoof module; the corpus hits are indirect. Rise 6.x PingSpoofComponent lists C15 in its blink tuple so settings packets are held and replayed during blink spoofs, and the script PacketAPI exposes sendSettings(). Spicy's Bhop imports C15 without using it. Clients known to cancel C15 for locale bypasses exist outside this corpus.

Exploit surface

The packet is informational and server-validated trivially, so abuse is limited to two corners: re-sending it to reset the server's stored locale after a language change (defeating per-locale chat filters), and the blink interaction, where holding C15 for the blink window freezes the server's view of client settings. The model-part bitmask is the only field that reaches other players (via DataWatcher), so a corrupted mask is the only client-visible side effect.

Server-Side Handling

processClientSettings -> EntityPlayerMP.handleClientSettings: stores locale, chat visibility and colors; model-part flags go to DataWatcher slot 10 (broadcast to other players). Render distance is parsed and discarded in the bundled 1.8.9 sources. No validation beyond String length.

Protocol Analysis

String locale + byte viewDistance + byte chatVisibility enum + bool colors + byte modelPartFlags (bitmask for cape/jacket/sleeves/pants/hat). Re-sent on every settings change, so a settings GUI session naturally emits several. The locale is a plain String and is never matched against a known list.

Anti-Cheat Landscape

No anti-cheat measures C15. Language-detection and anti-spam plugins key off the locale string; spoofing it changes plugin behavior, not server physics. The blink-hold interaction matters to anti-cheats only insofar as the same component also holds C03 and C0F packets, which is where the actual detection signal lives.

implementation Implementation Cases

The settings declaration packet. No locale-spoof module exists in the 8 clients; C15 shows up only inside Rise 6.x's blink-hold component and the script PacketAPI, plus dead imports in Spicy Bhop.

PingSpoofComponent (blink hold) (Rise 6.1.30, Rise 6.2.4)

Hold C15 (with C13, C17, C18, C19 and movement packets) while the client blinks, then replay it in order.

C15 is in the blink class tuple. When blink() enables the regular and blink tuples, onPacket cancels matching packets and parks them with a timestamp; PostMotionEvent replays entries whose delay elapsed and dispatch() flushes the rest on world change.
