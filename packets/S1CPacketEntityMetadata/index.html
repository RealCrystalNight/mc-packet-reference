Deep Dive

Role in the protocol

S1CPacketEntityMetadata carries DataWatcher updates for one entity: a list of WatchableObject entries, or the full watcher dump on spawn. EntityTrackerEntry sends the full watcher with the metadata flag true when a player enters tracking range (corpus line 360) and incremental changed entries otherwise (line 303). The client merges them into the entity's DataWatcher. Relevant indexes: 0 is the byte flags (sneaking, sprinting, invisible, riding), 2 the name tag, 3 name visibility, 6 health for living entities. The sneak flag (bit 1, byte value 2) is the one the corpus actually reads.

Vanilla handling

NetHandlerPlayClient.handleEntityMetadata (Memeware 7.3 bundle, line 468) resolves the entity, guards against a null list and calls entity.getDataWatcher().updateWatchedObjectsFromList(list). The DataWatcher then notifies the renderer and any systems watching specific indexes. The same list rides inside S0CPacketSpawnPlayer and S0FPacketSpawnMob for the initial state.

Why clients touch it

The canonical ESP/AntiInvis reads (invisibility flag, name-tag index) do not appear in the 8 clients; their renderers read entity fields after the vanilla handler applies S1C. The real hits: Rise 5.99 EagleA reads the sneak byte from the WatchableObjects, the only genuine module consumer; Sigma 4.11 AutoPot and InventoryManager import the class but never process it, polling isPotionActive and inventoryContainer on EventUpdate instead, so both imports are dead code; Rise 6.x PingSpoofComponent classifies S1C in its regular tuple, delayed with C0F and C00 during spoof, and NetworkAPI whitelists it for scripts.

Exploit surface

Metadata is read-only intelligence: 1.8.9 has no serverbound metadata packet, so the stream is the only place the server's view of entity state leaks back to the client. That makes it the natural feed for anti-invis and name-tag modules, and its absence in these 8 clients is a design choice, not a protocol limitation. The sneak flag is the load-bearing bit for anticheats: eagle checks (Rise 5.99) read it against the S14 ground state, and any client that spoofs sneak serverbound via C0B must keep the server-visible flag consistent or the mismatch is a flag.

Server-Side Handling

Clientbound only. EntityTrackerEntry sends the full DataWatcher on tracking start and incremental entries on change; the client merges them via updateWatchedObjectsFromList. Index 0 byte flags encode sneaking (bit 1), sprinting (bit 3), invisible (bit 5) and riding (bit 6). No validation is applied to incoming values, so a malicious server can inject arbitrary metadata, which is why clients that care about server-side state reads (name tags, invisibility) consume it defensively.

Protocol Analysis

The packet carries a VarInt entityId followed by the DataWatcher serialization: repeated (index byte, type byte, value) triples terminated by 127, with an empty list meaning no changes. A full dump is flagged server-side by the boolean constructor argument (true on tracking start). Sneak is bit 1 of the flags byte, which decodes to exactly 2 when it is the only set bit, matching EagleA's equality check. Metadata changes do not touch position or rotation, so the packet interleaves freely with the S14/S18 stream.

Anti-Cheat Landscape

The sneak flag is the anticheat-relevant field: eagle and shift-tap checks correlate the flag with S14 ground transitions, and the Rise 5.99 EagleA check flags a sneak byte that appears within two ticks of walking off a ledge. Server anticheats compare the sneak flag against serverbound C0B sneak actions; a client whose metadata-visible sneak disagrees with its C0B stream leaks the discrepancy. Everything else in the packet (name tags, health) is cosmetic to anticheats.

implementation Implementation Cases

The metadata stream is the server's mirror of entity state, but only one module in the corpus genuinely reads it: Rise 5.99's EagleA, which checks the sneak flag byte. Sigma's AutoPot and InventoryManager carry dead imports, and Rise 6.x classifies the packet for ping-spoof delay and scripts.

EagleA (Rise 5.99)

Detect eagle (auto-sneak at block edges) by reading the sneak flag byte out of the tracked player's metadata stream.

On S14 relative moves it sets shouldEagle when the packet's onGround flag is true and the block below the reconstructed position is air, then counts ticks. On S1CPacketEntityMetadata for the tracked player it scans the WatchableObjects for a Byte whose value is exactly 2 (the sneak bit alone), and if shouldEagle is set with ticks <= 2 it increases the buffer and fails past 10; otherwise the buffer decays by 5.

anticheat Anti-Cheat Checks

The metadata packet is the server's mirror of entity state, and anticheats read it for two reasons: to keep the player's own simulation state honest (sneak, gliding, pose, sleeping) and to hide or rewrite health information so clients cannot exploit it. The corpus splits into self-metadata listeners (Grim PacketSelfMetadataListener, intave MetadataTracker), a health rewrite check (Kauri HealthSpoof, disabled), Photon's damage-hiding module, and wrapper layers (FlopAC). The sneak and health indexes are the only fields any check actually touches.

Extract sleeping bed position, gliding flag and pose from the self entity's metadata so the movement simulation knows the player's physical state.
