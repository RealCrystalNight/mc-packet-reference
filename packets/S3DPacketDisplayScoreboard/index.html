Deep Dive

Role in the protocol

Binds an objective to a display slot: a position byte (0 sidebar, 1 player list, 2 below name) followed by the objective name string. An empty name clears the slot. The packet is tiny and is sent by ServerScoreboard whenever the display binding changes and during full replays on objective creation and removal. The HUD reads the bound objective each frame and renders its rows from the client scoreboard.

Vanilla handling

handleDisplayScoreboard sets or clears the objective in the given slot. The visible sidebar depends on the combination of S3B (objective definition), S3C (rows), and S3D (binding): S3D alone paints nothing, it only points the renderer at an objective.

Why clients touch it

Almost nothing across the 8 clients. Spicy's HideName imports the class (line 15) but its handler has no S3D branch, mirroring the dead S3B import. Rise 6.x registers the class in the script API. No module cancels the display binding; a cancel would freeze the previous objective in the slot, a HUD artifact none of the 8 clients bothers to produce.

Exploit surface

Nil for anti-cheat. The slot byte is not validated: values outside 0-2 are stored in the client's 19-entry slot array and render nowhere. Cancelling S3D only affects local rendering. The packet carries no timing or movement state, so no anti-cheat in the corpus measures it.

Server-Side Handling

ServerScoreboard sends S3D in setObjectiveInDisplaySlot (both the set and clear paths) and during full replays on objective creation and removal, with a null objective serialized as an empty name string. The server never reads the binding back from the client.

Protocol Analysis

Two fields: position byte then objective name string. An empty name clears the slot. The position byte indexes the client's 19-slot display array directly, so out-of-range values are stored but never rendered.

Anti-Cheat Landscape

Not monitored. S3D carries a slot index and a display string, no state an anti-cheat validates. Tampering is client-visual only.

implementation Implementation Cases

Display slot binding. In the 8-client corpus it is an import in Spicy's HideName and a script API entry in Rise 6.x; no module binds, clears, or blocks the slot.
