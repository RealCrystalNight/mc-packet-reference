Deep Dive

Role in the protocol

C14 requests command and player-name completions: a String (the partial input, with or without the leading slash) and an optional BlockPos for block-sensitive completions. The server replies with S3APacketTabComplete. GuiChat fires it on the tab key; the position is set when the cursor is over a block, which lets /give-style commands complete with looked-at block data.

Vanilla handling

processTabComplete calls the server command dispatcher's getTabCompletions with the message and target block, collects the returned strings and replies with S3A. There is no rate limit or throttle in the bundled 1.8.9 handler, which is what makes the packet a free information oracle: every registered command, including plugin-registered ones, is reachable through the completion namespace.

Why clients touch it

Three families across the 8 clients. (1) Plugin enumeration: Rise 5.99 Plugins sends '/' and parses S3A, with a Bypass mode that sweeps '/a'..'/z'; Sigma 4.11's PluginFinder command sends '/' once and parses the reply for ':' prefixed plugin names. (2) Crasher: Rise 5.99's FAWE mode sends a deeply nested command string. (3) Chat UX: the Rise 6.x Chat module drives its own completion via C14 with a block position.

Exploit surface

The missing throttle is the whole story: a client can dump the full command namespace by sweeping single letters, and servers that hide the plain '/' reply still leak commands through per-letter prefixes. The FAWE crash works because the completion handler parses the input command recursively; a 4-deep loop body of nested for() statements overflows that parser. Anti-cheats ignore C14; anti-exploit plugins rate-limit completions, which is exactly what Plugins' Bypass mode cycles around.

Server-Side Handling

processTabComplete: getTabCompletions(message, targetBlock) then S3APacketTabComplete with the results. No permission pre-check beyond what the dispatcher applies to the requesting player, no rate limit, no length cap beyond the String wire limit. Completions are computed against the live command registry, so plugin commands appear without any /plugins permission.

Protocol Analysis

VarInt-length-prefixed String + bool hasTargetBlock + optional BlockPos. The message does not need to start with '/' for the server to run the completion path. Replies are a String array; plugin-registered commands commonly appear as pluginname:command, which is the parsing key for enumeration tools.

Anti-Cheat Landscape

No anti-cheat measures C14. Anti-exploit and anti-spam plugins throttle completion requests per second; the '/a'..'/z' sweep is designed to stay under naive thresholds while still covering the namespace. The FAWE payload is a plugin-specific parser kill and is invisible to movement anti-cheats.

implementation Implementation Cases

The tab-complete request packet and the protocol's least-guarded information oracle. Plugin enumeration (Rise 5.99 Plugins, Sigma PluginFinder), a FAWE command-parser crash (Rise 5.99 Crasher) and custom chat completion (Rise 6.x Chat) are the corpus families.

Plugins (Rise 5.99, LiquidSense Dev, November Recode 2.0)

Enumerate the server's plugin list through the tab-complete namespace and print it in chat.

Normal mode sends C14('/') once and parses the S3A reply for completions. Bypass mode sends C14('/' + letter) for every letter of the alphabet to recover commands that servers filter from the plain dump; results are cached and the module disables after the sweep.
