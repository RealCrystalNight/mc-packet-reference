Deep Dive

Role in the protocol

C08 is the serverbound use/place packet. With placedBlockDirection == 255 it is a pure item use (eating, blocking, throwing), otherwise it is a block placement against the BlockPos + face with a cursor offset. The stack field lets the server verify the client's inventory state. This dual role makes it the single most-abused packet for movement and combat bypasses: it is how scaffold places blocks, how killaura holds a shield or sword block, how noslow keeps the use-item state alive, and how item-spam modules (AutoPot, AutoSoup) consume consumables at inhuman speed.

Vanilla handling

NetHandlerPlayServer.processPlayerBlockPlacement branches on the direction byte. For 255 it calls theItemInWorldManager.tryUseItem, which starts the item's use-tick state server-side. For a face it checks build limit, distance (hasMoved and 8-block radius), world border, then calls func_180236_a to place. The server compares packetIn.getStack() against the real inventory slot and re-sends S2FPacketSetSlot on mismatch, which is why clients that spoof the stack field get desynced slots.

Why clients touch it

All ten clients construct C08 directly. Scaffold modules (Rise 5.99, Rise 6.x, Sigma 4.11) send placements with computed BlockPos + face; Memeware and Nekoware auras send the autoblock form (new BlockPos(-1, -1, -1), 255) to start blocking mid-aura; NoSlow modules (Rise 5.99 NoSlow, Rise 6.x IntaveNoSlow/LegitNoSlow/NCPNoSlow/NewNCPNoSlow/WatchdogNoSlow, Sigma NoSlowdown, Spicy NoSlow) re-send the item-use C08 to keep the server believing the player is using the item; AutoPot/AutoSoup/AutoGap/AutoHead (Memeware, Rise 5.99, Rise 6.x, Sigma) spam the item-use form to consume faster than vanilla allows. Rise 6.2.4 even wraps placement in PlayBlockPlacementC2SPacket for its script/NetworkAPI layer. November Recode 2.0 drives AutoPot, autoblock and noslow through C08 and clicks the BLOCKS_MC paper with it in AutoPlay; LiquidSense Dev eats heads and equips armor with the C09/C08/C09 packet triple.

Exploit surface

The 255-use form has no cooldown server-side in 1.8.9, so item-use spam is only throttled by client ticks; anti-cheats flag the resulting consumption rate. The invalid-position form (pos -1,-1,-1, face 255) is silently accepted by vanilla (it falls into the item-use branch when direction == 255) but stands out to anti-cheats that track block-place patterns around the player's head. Scaffold places at the feet with yaw-derived face values, which NCP and Vulcan correlate against the player's rotation. C08 is also sent at 20+ per second by Rise 6.2.4 WatchdogDisabler as a fake water-bucket placement to reset watchdog's fall tracking, and by Speed/Fly modules to place blocks under the player mid-air.

Server-Side Handling

processPlayerBlockPlacement: if direction == 255, tryUseItem (no position checks); else enforce build limit, 8-block distance from the last confirmed position, world border and block protection before placing. Stack mismatch with the real inventory triggers an S2FPacketSetSlot resync. The server never validates that the client's held item matches the packet's stack for the 255 path beyond the slot resync.

Protocol Analysis

Fields: BlockPos (long), direction byte (255 = no face), ItemStack, three cursor bytes (0-16 mapped from floats). The item-use form still carries a position (usually BlockPos.ORIGIN or (-1,-1,-1)); vanilla ignores it when direction == 255. ViaVersion clients (Rise 6.2.4 BlockPlacementFixComponent) translate this to newer protocol versions where the packet was split into UseItemOn/UseItem.

Anti-Cheat Landscape

NCP flags scaffold rotations vs placement faces, Verus tracks placement frequency, Watchdog detects fake water-bucket placements when the inventory does not contain a bucket (Rise 6.2.4 WatchdogDisabler guards with BadPacketsComponent checks). AutoPot spam is caught by consumption-rate checks on popular servers; Noslow C08 spam is a classic Intave/Verus detection vector, hence the many per-AC modes in Rise 6.x.

implementation Implementation Cases

The use/place workhorse. Clients split it into three dialects: the item-use form (direction 255) for AutoPot/NoSlow/autoblock, the placement form for Scaffold, and the invalid-position form as a fake-use trick for disablers and speed modules.

ScaffoldA (FlopAC) (JTXOfficial-FlopAC)

Hit-vector scaffold check: a real scaffold click sequence must vary the face and cursor vector as the player moves.

On BLOCK_PLACE it reads the cursor vector (vecX, vecY, vecZ) and the face ordinal from the wrapped packet. When the yaw is changing and the block below the target position is air, it expects a non-constant click pattern: a face between 0 and 3 with a perpetual 0.5/0.5 vector is the scaffold signature, accumulating a violation level that flags at 4 consecutive hits, otherwise the level decays.

Detects: Scaffold cheats that always click the same face center, and tower/scaffold modules that keep a constant hit vector while moving.
