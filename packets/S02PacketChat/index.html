Deep Dive

Role in the protocol

The single channel for every server-to-client message in the PLAY state: player chat, command output, kill feed, actionbar text, plugin announcements, and anti-cheat notices. The payload is a JSON ChatComponent plus a byte position (0 chat box, 1 system message, 2 actionbar above the hotbar). Vanilla routing is trivial: NetHandlerPlayClient.handleChat sends type 2 to the ingame GUI overlay and everything else to GuiNewChat.printChatMessage. Because every server plugin funnels text through it, it is the most-intercepted clientbound packet in the corpus: 25 non-vanilla file hits across 6 of the 8 clients.

Vanilla handling

handleChat runs PacketThreadUtil.checkThreadAndEnqueue, then branches on the position byte: if (packetIn.func_179841_c() == 2) this.gameController.ingameGUI.func_175188_a(component, false); else this.gameController.ingameGUI.getChatGUI().printChatMessage(component). The component is parsed leniently from JSON; malformed components degrade to plain text rather than disconnecting. Server-side, S02PacketChat is the delivery vehicle: ServerConfigurationManager.sendChatMsgImpl broadcasts it, EntityPlayerMP.addChatMessage sends it per player, and kick/actionbar paths construct it directly.

Why clients touch it

Six families in the corpus. Game-end and lobby automation: Sigma AutoGG, Rise 5.99 AutoHypixel, Rise 6.x AutoPlay (parse the kill feed and the /play click actions in the component's siblings). Staff and identity: Rise 5.99 StaffAlert (captures the Hypixel API key line), Sigma StreamerMode, Spicy HideName, Rise 5.99 Denicker, Rise 6.x Streamer (rewrite or cancel messages that contain the player's name). Kill-feed banter: Memeware DeathInsult, Spicy KillSults. Request automation: Sigma AutoTPA, Rise 5.99 FightBot and BedwarsTP, Tenacity TPKiller, Rise 6.x WatchdogAutoPhase. Auth: Rise 5.99 AutoAuthme reacts to auth-me prompt text. The rest of the field is heterogeneous: Rise Nuker, PlayerHacks, Phase, Disabler, Translator and Ranking, Rise 6.x APIKeyComponent, IRCInfoComponent, AdaptiveRefreshRateComponent (uses S02 as a frame-rate hint), LoggerRCECheck, and the Spicy meme modules. Nekoware v1 is the only client with zero module hits.

Exploit surface

The JSON component is attacker-controlled server text, and the Log4Shell era made that concrete: Rise 6.x ships LoggerRCECheck, a SecurityFeature that pattern-matches ${...} in the unformatted and formatted text of every S02PacketChat (and in S29 sound names) and blocks the packet before it reaches the logger. Beyond RCE, the component's click events carry runCommand actions, which AutoPlay extracts programmatically instead of waiting for a user click. Cancel-and-rerender name protection (StreamerMode) hides the player's name from the local log while the original packet never renders. DeathInsult appends a random hex suffix so message-spam filters cannot match the repeated insult string. Position matters: modules that must react to actionbar text (AutoPlay skips non-chat via isChat()) filter on the type byte.

Server-Side Handling

Server emission points: ServerConfigurationManager.sendChatMsgImpl builds S02PacketChat and broadcasts to all players; EntityPlayerMP.addChatMessage sends to one player; NetHandlerPlayServer wraps kick reasons and actionbar messages. Nothing validates the component server-side because the server is the author of it. The client parses it leniently; the only client-side failure mode is a giant JSON string approaching the 32767-byte String cap, which degrades to a truncated render.

Protocol Analysis

Wire layout: ChatComponent serialized as JSON (String, VarInt length + UTF-8), then a byte position (0 chat, 1 system/singleplayer, 2 actionbar). Components are trees: getFormattedText() includes color codes, getUnformattedText() strips them, getSiblings() exposes the child components where click actions (runCommand/suggestCommand) and hover events live. AutoPlay reads /play commands by splitting a sibling's toString() on quotes. Position 2 messages bypass the chat history and render above the hotbar; isChat() (type == 0) is the standard filter before pattern matching.

Anti-Cheat Landscape

No anti-cheat measures chat content or rate, but anti-cheat messages themselves are data for modules: Tenacity TPKiller and Rise 6.x WatchdogAutoPhase and Nuker read server notices from this packet to trigger or reset their behavior. Server-side, the same channel is the delivery path for ban/kick notices, so watchdog-style anti-cheats both emit through it and are blind to its client-side consumption. The only hard security boundary is injection: LoggerRCECheck exists because a ${...} payload inside a chat component could reach the logging pipeline; the pattern match on both text forms is the mitigation.

implementation Implementation Cases

Nekoware v1 alone has zero module hits.

anticheat Anti-Cheat Checks

S02 is the outbound chat packet: anticheats send their own alerts through it, but they cannot see what the client renders, so none of them validate the packet's payload on the server side. The chat checks that exist in the corpus run on the INBOUND chat packet or Bukkit chat events and then talk back through S02: Grim flags blank tab-complete and impossible chat, NCP gates chat behind a captcha, Photon flags chat while sprinting or with an open inventory, and BetterAnticheat flags chat while chat is set to hidden. From the anticheat's point of view S02 is the delivery channel, not the input.
