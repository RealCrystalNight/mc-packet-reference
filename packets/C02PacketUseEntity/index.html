Notes

Deep Dive

Role in the protocol

C02PacketUseEntity is the only serverbound channel in 1.8.9 by which the client tells the server it interacted with an entity. The wire form is a VarInt entityId, a VarInt enum action (INTERACT, ATTACK, INTERACT_AT) and, for INTERACT_AT only, three floats for the hit position on the target. Every attack, mount, item-frame edit and armor-stand manipulation goes through it. Because the packet carries no position, rotation or timestamp, the server validates it purely against its own copy of player and entity state, which is exactly what makes it trivial to spoof from a modified client.

Vanilla handling

NetHandlerPlayServer.processUseEntity resolves the target from the packet's entity id, then enforces a distance gate: squared distance must be under 36.0 (6 blocks) when the target is visible to the player, or 9.0 (3 blocks) when it is not. INTERACT routes to playerEntity.interactWith, INTERACT_AT to the per-vector entity handler, and ATTACK first kicks the player for targeting EntityItem, EntityXPOrb, EntityArrow or self ("Attempting to attack an invalid entity"), then calls attackTargetEntityWithCurrentItem. There is no rate limit and no attack-cooldown validation; the 1.8.9 swing cooldown is enforced only client-side in PlayerControllerMP and EntityPlayerSP.

Why clients touch it

All eight clients ship combat modules that live on this packet. Aura and KillAura variants send ATTACK in every client: Memeware and Nekoware split Single/Multi/Hypixel/Switch auras, Rise 5.99 and 6.x use Aura and KillAura, Sigma, Spicy and Tenacity each have Killaura modules. Criticals exists in Memeware, Nekoware, Rise 5.99, Sigma and Spicy, injecting C04 offset packets before the ATTACK. TPAura and TeleportAura in Memeware, Rise 5.99, Rise 6.x and Tenacity walk the server-side player to the target before attacking. ComboOneHit (Rise 5.99 and 6.x) floods ATTACK packets, and Spicy's TriggerBot and Wtap round out the combat surface. Freecam (Rise), Infinite (Rise 5.99), WorldGuardRegen, GodMode and AntiFireBall (Rise 6.x), PlayerHacks (Rise 5.99) and Sigma's AntiFreeze all filter or forge C02 as a secondary effect.

Exploit surface

The server trusts three things: the entity id, the distance, and the action. Attack rate is unbounded, so ComboOneHit's 50-1000 packet bursts are legal wire traffic. INTERACT_AT's hitVec is client-chosen and unvalidated, which is why Sigma and Spicy Killaura spam INTERACT_AT with random hitVecs plus INTERACT as a disabler sequence, and why Rise 5.99's BedwarsTP can mount entities from outside reach. Friend protection is purely a client courtesy: Rise 5.99's Aura consults its friends list, Sigma's Killaura checks FriendManager.isFriend, Tenacity's KillAuraModule checks FriendCommand.isFriend, but nothing server-side knows about friends, so a client that skips the check can hit anyone. Anti-cheats counter with reach math, attack-rate caps, rotation-motion correlation, and ghost-interact detection.

Server-Side Handling

processUseEntity runs on the main thread via PacketThreadUtil and calls markPlayerActive, which resets the idle-kick timer. The entity lookup uses packetIn.getEntityFromWorld(worldServerForDimension(player.dimension)). Distance is checked as squared distance: 36.0 when canEntityBeSeen passes, 9.0 otherwise, with no horizontal/vertical split and no per-axis clamp. For ATTACK the invalid-target kick fires before any damage is dealt. There is no vanilla per-tick attack limit: the swing cooldown and the 20-tick hit cooldown live in client-side code (PlayerControllerMP.attackEntity and EntityPlayer.attackEntityAsMob), so a forged client can emit arbitrarily many attacks per tick and the server will process them all.

Protocol Analysis

The action is serialized with readEnumValue/writeEnumValue, a VarInt ordinal (0=INTERACT, 1=ATTACK, 2=INTERACT_AT). INTERACT_AT adds three floats read after the enum; the other two actions carry no payload, so the packet length varies by action. The Entity-based constructors resolve the entity id at construction time (entity.getEntityId), so modules that queue C02 after the target dies or unloads send a stale id that the server resolves to null and silently ignores. The Vec3 constructor always selects INTERACT_AT. The packet is registered at 0x02 in the SERVERBOUND play state table.

Anti-Cheat Landscape

NCP flags reach by comparing the server-side player position against the target at ATTACK time and tracks hit rates per second; ComboOneHit-style floods are its primary target. Rotation-aware checks flag attacks whose preceding C05/C06 rotation does not point at the target, which is why Memeware-style auras that send ATTACK without a rotation packet get flagged on newer anti-cheats while rotation-injecting auras pass. The INTERACT_AT plus INTERACT disabler sequence (Sigma, Spicy) is detected by anti-cheats that count ghost interacts. TPAura is trivially caught by movement checks, because the unconfirmed C04 walk trips the vanilla 'moved too quickly' math when the path is skipped. Friend checks are invisible to the server and exist purely as client-side target filtering.

implementation Implementation Cases

The combat funnel of 1.8.9: a VarInt entity id and an action enum are all the server needs to apply damage. KillAura family targets and attacks, Criticals injects C04 fall arcs ahead of the ATTACK, TPAura teleports the server-side player to the target first, ComboOneHit floods the channel, and TriggerBot/Wtap automate the last bits of the attack loop. Friend protection exists only inside the aura target filters, never as a standalone module, across the 8 clients.

anticheat Anti-Cheat Checks

Server-side combat anticheats see the use-entity packet as the attack trigger. The 50-cloned-anticheat corpus splits into two families: modern simulation checks (Grim Reach, Kauri Hitbox, Artemis Reach2) that rebuild the client's view of the world and measure the exact attack vector, and classic statistical checks (Frequency KillAura, NCP fight.reach, AutoEye Reach) that score the attack angle, hitbox distance, and packet rhythm. The use-entity packet carries the entity id and action, so every killaura and reach check in the corpus keys off it.

Reach (Grim) (GrimAnticheat-Grim)

The reference modern reach check: verifies the attack vector against a simulated copy of the client's world state.

Listens to the ATTACK packet (WrapperPlayClientAttack) and the INTERACT_ENTITY packet, then computes the distance from the player's interpolated eye position to the entity's exact collision box. Attack range is taken from the held item's attack range attribute, and the threshold is 3.0 + reach attribute with buffer. It cancels impossible hits outright and runs a cancel buffer for 4 hits after a flagged reach attack.

Detects: Reach cheats, killaura with extended range, hitbox-based auras, and any client that fakes attacks from beyond attribute reach.
