Deep Dive

Role in the protocol

C07PacketPlayerDigging is the serverbound mining and item-use control channel. The wire form is a packed BlockPos (long), a facing byte, and a status enum byte: START_DESTROY_BLOCK, ABORT_DESTROY_BLOCK, STOP_DESTROY_BLOCK, DROP_ALL_ITEMS, DROP_ITEM, RELEASE_USE_ITEM. It is the only way the server learns that the player began mining, finished or cancelled a dig, dropped an item, or released a use-item action such as a bow draw, eating, or blocking. Client-side it is emitted from PlayerControllerMP.clickBlock (START), onPlayerDamageBlock (ABORT), onPlayerDestroyBlock (STOP), EntityPlayerSP.dropOneItem (DROP) and PlayerControllerMP.onStoppedUsingItem (RELEASE_USE_ITEM).

Vanilla handling

NetHandlerPlayServer.processPlayerDigging switches on the status. DROP_ITEM and DROP_ALL_ITEMS call dropOneItem(false/true) unless the player is a spectator. RELEASE_USE_ITEM calls stopUsingItem, which ends the bow draw or eating and computes the fired arrow or consumed food server-side. The three dig actions share a distance gate: squared distance from the player to the block center (with a +1.5 Y bias) must be under 36.0 and the block Y below the build limit. START calls ItemInWorldManager.tryHarvestBlock when the block is not protected and inside the world border, otherwise the server replies with an S23 block change. STOP calls onPlayerDestroyBlock and ABORT cancels the dig; after STOP or ABORT an S23 is re-sent if the block is not air. There is no per-action rate limit.

Why clients touch it

Four families dominate the corpus. Mining automation: Nuker in Rise 5.99 and 6.x sends START+STOP pairs around every block in a radius, with Teleport and Area modes that walk to the target first; Breaker in Memeware, Rise 5.99 and the Rise 6.x Breaker/NewBreaker/NewNewBreaker suite destroys cake, beds and targeted blocks; Tenacity's SpeedMine accumulates block damage client-side and finishes the dig itself. Item-use automation: FastBow in Memeware, Rise 5.99 and Sigma fires fully charged arrows by releasing early; the Rise 5.99 AutoGap/AutoPot/AutoHead/AutoSoup family and Sigma's FastUse use RELEASE_USE_ITEM to end eating, potting and item use instantly. NoSlow lives in Memeware, Rise 5.99, Rise 6.x (Legit/NCP/Intave), Sigma and Spicy, pairing RELEASE_USE_ITEM with a C08 re-place to cancel the slow. Combat auras in every client use RELEASE_USE_ITEM for autoblock, and Rise 6.x velocity and disabler modules spoof dig state for anti-cheat bypasses.

Exploit surface

The server processes a START+STOP pair as a complete break with no client-side damage accounting, so any module can mine instantly at the packet level; the only server-side evidence is the block's hardness versus the reported dig duration. RELEASE_USE_ITEM ignores the BlockPos entirely, so Spicy's NoSlow can send it with a random double-range position and the server reads only the status. The 36.0 distance gate is generous versus the client's 6-block reach, and Teleport-mode Nuker satisfies it by walking before digging. DROP_ITEM is a free inventory channel. Anti-cheats counter with dig-speed measurement (hardness versus START-to-STOP gap), per-second block counts for nuker patterns, and the release+re-place gap for NoSlow.

Server-Side Handling

processPlayerDigging resolves the block position, then switches on the status ordinal. Drop actions skip the distance check entirely and go straight to dropOneItem; the spectator gate is the only guard. RELEASE_USE_ITEM also skips position validation and calls stopUsingItem, which is why the random-position trick works: the server reads the enum and nothing else. Dig actions enforce the 36.0 squared-distance gate with the +1.5 Y bias, the build-limit clamp, the world-border check and the block-protection check (an S23 is sent back when the dig is refused). STOP_DESTROY_BLOCK is what actually breaks the block via onPlayerDestroyBlock; START only enters the mining state. The ItemInWorldManager tracks the dig progress server-side, but a module that sends START then STOP back-to-back completes the state machine in one round trip.

Protocol Analysis

The BlockPos is packed into a single long as ((x & 0x3FFFFFF) << 38) | ((y & 0xFFF) << 26) | (z & 0x3FFFFFF). The facing byte and the status byte follow; MCP reads both via readEnumValue, so both are VarInts on the wire. Status ordinals: 0 START_DESTROY_BLOCK, 1 ABORT_DESTROY_BLOCK, 2 STOP_DESTROY_BLOCK, 3 DROP_ALL_ITEMS, 4 DROP_ITEM, 5 RELEASE_USE_ITEM. Drop packets conventionally use BlockPos.ORIGIN with EnumFacing.DOWN; modules copy that convention even for release packets, and Spicy's NoSlow deliberately breaks it with random coordinates. The packet is registered at 0x07 in the SERVERBOUND play state table.

Anti-Cheat Landscape

NCP and Matrix measure the START-to-STOP gap against the block's hardness and flag instant breaks; Nuker patterns are caught by counting unique blocks destroyed per second, which is why Rise 5.99's Nuker ships a Tick throttle and an Instant Only mode that refuses hardness above 0. SpeedMine avoids the dig-speed flag by never lying about the gap: it finishes the client-side damage model and only then sends STOP. NoSlow is detected by the release+re-place packet pattern and by position comparison on the C07, which is what Spicy's random BlockPos defeats. GrimVelocity and StandardVelocity in Rise 6.x spoof START/STOP to satisfy mining-state checks during knockback, and the CubeCraft and Vulcan disablers send STOP/START at the player's own position to reset server dig state. The item-use family (FastBow, FastUse) is flagged by charge-time measurement between the C08 use and the C07 release.

anticheat Anti-Cheat Checks

The digging packet is the block-break trigger: it carries start, stop, abort and item-release actions with a block position and face. Server-side anticheats treat it as the point to validate break duration against block hardness and tool speed, break reach, swing correlation, and the number of blocks broken per second. The corpus splits into modern simulation checks (Grim FastBreak, Intave CompletionDurationCheck) that recompute the expected mining time, and classic rate checks (NCP blockbreak suite, Arc Nuker) that score break frequency and packet rhythm.

FastBreak (Grim) (GrimAnticheat-Grim)

The reference modern fast-break check: verifies that the time between start-digging and finish-digging is long enough for the held tool to break the block.

Implements BlockBreakListener and PreViaPacketReceiveListener. On START_DIGGING it records the target block and the maximum block damage per 50 ms tick computed from the held item and block properties (BlockBreakSpeed), then on STOP_DIGGING it measures the elapsed time against the accumulated damage. A balance tracks how far the player finished early, and a separate delay balance enforces the 300 ms minimum between non-instant breaks. It cancels the finish-digging packet and flags when the client breaks faster than the simulated damage allows.

Detects: FastBreak and speedmine modules, nuker variants that break blocks in a single instant, and clients that skip the mining animation timing entirely.

BreakSpeedLimiter / CompletionDurationCheck (Intave) (intave-intave)
