Deep Dive

Role in the protocol

Keepalive is the protocol's liveness and latency probe. The server sends S00PacketKeepAlive with a monotonically increasing key (server tick-based), the client must echo it back as C00PacketKeepAlive with the same key. NetHandlerPlayServer.processKeepAlive compares the echoed key to the stored field_147378_h and folds the round-trip time into the player's ping EMA: ping = (ping * 3 + delta) / 4. It is the only packet in the play state whose sole purpose is timing, which makes it the backbone of ping spoofing, disconnect-detection, and timer-based disabler modes.

Vanilla handling

Client side, NetHandlerPlayClient.handleKeepAlive immediately echoes: this.addToSendQueue(new C00PacketKeepAlive(packetIn.func_149134_c()));. Server side, processKeepAlive is a pure timing check: if the key matches, it recomputes ping; otherwise it silently ignores. Note there is no per-connection timeout in vanilla 1.8.9 server code for a missing keepalive response; timeouts are enforced by the network layer (read timeout) or by anti-cheat plugins. This asymmetry is exactly what ping-spoof modules exploit.

Why clients touch it

The 8 clients show three distinct families. (1) Ping spoofers (Rise 5.99 PingSpoof, Rise 6.x PingSpoofComponent, Sigma 4.11 PingSpoof, Spicy PingSpoof) buffer the packet and release it late. (2) Disablers (Memeware 7.3 Disabler, Sigma 4.11 Disabler, Rise 6.x KeepAliveDisabler/DynamicPVPDisabler/LunarDisabler/Verus2Disabler, Spicy Disabler, Tenacity 6.0 AdvancedDisablerModule) cancel or mutate the key to break server-side timing heuristics on specific anti-cheats. (3) Movement modules that need to reset the server-side timer or cancel all stateful packets (Nekoware v1 Fly, Spicy Bhop/BackupFly/Fly, Rise 5.99 Fly/LongJump/Speed, Sigma Blink, Spicy Blink, Rise BlinkAntiVoid/WatchdogAntiVoid).

Exploit surface

Delaying the echo inflates the server's measured ping. Mutating the key (Memeware's Mineplex Combat mode subtracts a random 3..127 from the key) makes the server's key comparison fail, so the ping EMA is never updated, freezing the displayed ping and confusing plugins that use keepalive gaps to estimate lag or detect timer. Cancelling keepalive outright is the crude version: safe only while the server has no keepalive timeout, which is why disabler modes pair the cancel with periodic re-sends (Sigma's Erisium mode re-sends lastKey every 1500 ms).

Server-Side Handling

NetHandlerPlayServer.processKeepAlive (line ~1015 in the bundled 1.8.9 sources): if packetIn.getKey() == field_147378_h, ping = (ping * 3 + (now - lastPingTime)) / 4. No response to a wrong or missing key: the packet is simply ignored. The client handler echoes unconditionally. Because wrong keys are silently dropped, mutating the key is undetectable from the packet stream alone: the server just never updates ping.

Protocol Analysis

Serverbound C00 and clientbound S00 share the same int key field (writeVarIntToBuffer / readVarIntFromBuffer in 1.8.9 MCP; the key is a plain int). S00 is sent roughly every second of play time (server tick counter). C00 must be sent on the same connection before the next S00 for the ping EMA to converge. In practice modules intercept C00 in PacketSendEvent and S00 in PacketReceiveEvent.

Anti-Cheat Landscape

NCP and AAC track keepalive timing to distinguish real latency from timer abuse; a frozen or wildly inflated ping is a classic timer/fly flag. Verus-era servers (the Rise 6.x Verus2Disabler, Memeware's 'Latest Verus' mode) correlate keepalive gaps with transaction (C0F) gaps, so disablers buffer C00 and C0F together and flush them together after a fixed delay. The risk trade-off: pure delay is stealthy but does nothing against servers that timeout dead connections; cancellation is strong but requires knowing the server has no keepalive timeout.

anticheat Anti-Cheat Checks

The keepalive echo is the anticheat's latency reference.
