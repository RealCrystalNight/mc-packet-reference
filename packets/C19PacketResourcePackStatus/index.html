Deep Dive

Role in the protocol

C19 is the client's reply to S48PacketResourcePackSend: a hash String plus an Action enum (SUCCESSFULLY_LOADED, DECLINED, FAILED_DOWNLOAD, ACCEPTED). Vanilla sends ACCEPTED when the user confirms the download prompt, then SUCCESSFULLY_LOADED or FAILED_DOWNLOAD after the download resolves. Servers that require a pack gate features or membership on the ACCEPTED reply.

Vanilla handling

The bundled 1.8.9 server handler, handleResourcePackStatus, is an empty method; decline kicks and pack-required logic are plugin territory. Client-side, NetHandlerPlayClient.handleResourcePackSend downloads the pack and reports the outcome through C19, and the download itself is a URL fetch with no scheme validation in vanilla, which is the hole the security modules patch.

Why clients touch it

Two families. (1) Security: Rise 6.x ResourcePackCheck (a SecurityFeature) and Tenacity's AntiExploit module and Enhancements utility intercept S48, validate the URL scheme, block level:// traversal and non-http hosts, and answer C19 with FAILED_DOWNLOAD so the server's state machine stays consistent. (2) Disabler: Rise 5.99's c19 mode sends C19 with an empty hash and ACCEPTED to unlock pack-gated features without downloading. LiquidSense Dev adds a third family: a mixin on NetHandlerPlayClient's handleResourcePack performs the same scheme guard as family (1), answering C19 with FAILED_DOWNLOAD and the real hash. November Recode 2.0 only registers C19 in its Lua scripting id map (0x19).

Exploit surface

The level:// protocol reads files from the server's save directory; a malicious pack URL with path traversal is a server-to-client file disclosure vector, which is exactly what both security implementations check for. The empty-hash ACCEPTED spoof exploits plugins that match the hash against the last S48; a strict plugin sees the mismatch, a sloppy one unlocks the feature. Because the vanilla server handler is empty, declined packs never kick in vanilla; the whole battlefield is plugin-side.

Server-Side Handling

handleResourcePackStatus is an empty no-op in the bundled 1.8.9 sources; pack-required kicks and feature gating live in plugins that read the Action. The client handler performs an unvalidated URL fetch, making S48 the disclosure vector and C19 the acknowledgment channel.

Protocol Analysis

String hash + VarInt enum action. The hash must echo the one from the triggering S48 for strict plugins. The enum order on the wire is SUCCESSFULLY_LOADED=0, DECLINED=1, FAILED_DOWNLOAD=2, ACCEPTED=3. C19 is only meaningful after an S48; a serverbound C19 with a hash the server never sent is the spoof signature.

Anti-Cheat Landscape

No anti-cheat measures C19. Anti-exploit plugins validate pack URLs server-side and match C19 hashes against their own S48 log; an empty-hash ACCEPTED or a FAILED_DOWNLOAD for a pack the server never sent is the detectable pattern. The security modules' FAILED_DOWNLOAD replies are indistinguishable from a genuine failed download, which is what makes them stealthy.

implementation Implementation Cases

The resource-pack handshake reply. Security layers in Rise 6.x and Tenacity block malicious pack URLs and answer FAILED_DOWNLOAD, while Rise 5.99's Disabler spoofs ACCEPTED with an empty hash to unlock pack-gated features without downloading anything. LiquidSense Dev ships the same scheme guard as a mixin on the vanilla handler.

ResourcePackCheck (Rise 6.1.30, Rise 6.2.4)

Block malicious level:// resource packs and reply FAILED_DOWNLOAD to keep the server state machine consistent.

As a SecurityFeature it intercepts S48, validates scheme and path (no traversal, must end in /resources.zip), and on violation sends C19 FAILED_DOWNLOAD via sendNoEvent and cancels the pack.

ResourcePackTickHandler (Artemis) (artemisac-artemis-minecraft-anticheat)

Turn resource-pack status into a tick counter for the connection.

On 1.8 servers, pushes a level:// resource pack whose hash encodes a numeric id, and accepts only FAILED_DOWNLOAD responses whose URL is numeric and contains the player name. The parsed id is stored as the player's resourcePackTick.

Detects: Nothing directly. It feeds the tick-confirmation infrastructure that other Artemis checks use to measure connection state.
