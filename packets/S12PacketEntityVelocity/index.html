Deep Dive

Role in the protocol

The velocity/knockback packet: entity id plus three motion shorts at x8000. The server emits it in three situations: EntityTrackerEntry broadcasts when a tracked entity's motion changes beyond a threshold (sendVelocityUpdates with lastTrackedEntityMotionX/Y/Z), EntityPlayer.attackEntityFrom sends it to the damaged player with the knockback vector, and explosions apply their push through S27. handleEntityVelocity overwrites the target entity's motion directly, which makes this the single most important clientbound packet for anti-knockback work.

Vanilla handling

EntityTrackerEntry compares the tracked entity's current motion to the last tracked values each tick and sends S12 when the delta crosses the threshold; EntityPlayer.attackEntityFrom sends the knockback vector straight to the damaged player's connection. On the client, handleEntityVelocity sets motionX/Y/Z = value / 8000.0 with no interpolation and no validation, so the packet is a direct write into the physics state that every movement check in the tick loop reads.

Why clients touch it

The most-handled clientbound packet in the corpus after S08. Four families: (1) cancel-or-scale anti-knockback (Memeware, Nekoware, Spicy, Tenacity, Rise 5.99 Custom); (2) per-anticheat timing games that cancel selectively or replay the knockback the way the anticheat expects (Rise 5.99 Vulcan/Tick Cancel/Stack/Follow First Tick/Ground, Sigma AACPush/AACFlag, the Rise 6.x ten-mode Velocity suite); (3) movement modules that consume S12 as a boost trigger (Rise 6.x GrimFlight TNT, WatchdogLongJump, WatchdogFireball, MatrixFlight, MineLandFlight, WatchdogBowLongJump; Rise 5.99 Fly Minemenclub and LongJump Hycraft/Vulcan; Sigma Fly; Tenacity FlightModule); (4) infrastructure: Rise's PingSpoofComponent buffers S12 in the velocity class, EntityTickComponent and ItemDamageComponent observe it, and Timer/Breaker/HurtCamera cancel it as collateral.

Exploit surface

The server recomputes knockback from attack packets and expects the resulting motion to appear in the player's reported positions over the next ticks. Cancelling S12 desyncs those reports, which is exactly what velocity checks measure, so the arms race is about timing: Tick Cancel and Stack modes cancel the first N velocity packets and let one through to satisfy the check, Sigma's AACFlag injects a NaN position to blind the check, and WatchdogVelocity modes apply the knockback client-side exactly as the server computes it. The companion S27PacketExplosion carries its own knockback and must be handled separately, which is why every serious module pairs S12 and S27. Rise 5.99 even ships an anticheat-side velocity recorder in dev/rise/anticheat/data/PlayerData.java and a dcOnVeloCheck disconnect in AutoHypixel that reacts to velocity-based server checks.

Server-Side Handling

EntityTrackerEntry keeps lastTrackedEntityMotionX/Y/Z and sends S12 to tracked players when the entity's motion changes beyond a threshold (sendVelocityUpdates). EntityPlayer.attackEntityFrom sends S12 to the damaged player with the knockback vector from the attacker's motion. The client applies value / 8000.0 directly to motionX/Y/Z with no validation, so the packet is a trusted write into the physics state. Explosion knockback travels separately in S27 and is not covered by S12.

Protocol Analysis

VarInt entity id plus three shorts at x8000, no rotations, no metadata. Values are signed, so negative motion (pulled, pushed back) encodes naturally. The client divides by 8000.0 on apply; the short range limits motion to roughly -4.096 to 4.096 blocks/tick. Because the write is direct, packet order matters: an S12 arriving after the tick's movement code runs applies one tick late, which knockback-timing modules exploit.

Anti-Cheat Landscape

Velocity checks reconcile the knockback vector with the player's reported position over the following ticks. Cancelling S12 is instantly measurable, so modern modes instead cancel selectively (first N packets, then pass one), reverse the vector (Sigma AACPush converts it into a strafe boost), or replay the exact server motion (WatchdogVelocity). Grim and Vulcan are sensitive to delayed application, which is why Rise 6.x splits the Velocity module into per-anticheat modes (GrimVelocity, VulcanVelocity, MMCVelocity, RedeskyVelocity, UniversoCraftVelocity, WatchdogPredictionVelocity) and why Rise 5.99's own anticheat records S12 in PlayerData.java for its checks.

anticheat Anti-Cheat Checks

S12 is the server telling the client to apply a velocity vector, normally knockback, and every anticheat treats it as a promise: the client's next movement ticks must reflect the vector it was sent. The corpus splits into direct statistical checks (Azure VelocityA compares the vertical delta against the sent vector) and transaction-ordered simulation checks (Grim KnockbackHandler, Artemis VelocityPreProcessor, Frequency VelocityManager) that know exactly when the packet arrived at the client and require the knockback in the following prediction. This packet is the reason anti-knockback cheats cancel or alter S12 specifically.

KnockbackHandler / AntiKB (Grim) (GrimAnticheat-Grim)

Requires the client's simulated motion to include the exact knockback vector the server sent, flagging any reduction or delay.

On the OUT side, wraps each entity-velocity packet for the player (or their vehicle) between two transaction packets, recording the vector with the first transaction id. As client transactions arrive, knockbacks move from a future queue into known-taken state; the prediction engine then compares the player's actual movement against the required knockback, accumulating a threshold-bounded buffer and triggering a setback above the immediate threshold.

Detects: Anti-knockback, velocity cancel and velocity reduction cheats, including selective cancels that take partial knockback.
