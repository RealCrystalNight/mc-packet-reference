Deep Dive

Role in the protocol

Spawns a particle burst at a world position with random offset, speed, and count. The particle name is a String that the client maps to an EnumParticleTypes; a trailing varint array carries iconcrack/blockcrack item and block data. Server-side it is the workhorse of WorldServer.spawnParticle, which batches particles into a single packet and sends it with a long-distance flag when the emitter is far from the viewer. The client handler walks the count in a loop, so a large count is a direct CPU/GPU cost on the receiving machine.

Vanilla handling

NetHandlerPlayClient.handleParticles marshals to the main thread, then calls clientWorldController.spawnParticle. When count is 0 the offset floats are treated as a single particle's velocity; otherwise the offsets are random spread and count particles are spawned. A Throwable around the spawn call logs 'Could not spawn particle effect' instead of crashing. The server path (WorldServer.spawnParticle) constructs one S2A per batch and uses sendToAllNear with a 512-block radius when longDistance is set.

Why clients touch it

Five distinct uses in the 8 clients. (1) Memeware 7.3 Disabler cancels every S2A unconditionally, an anti-lag/anti-crash blanket filter. (2) Rise 5.99 Disabler cancels only SLIME-type particles in its HypixelSlime mode. (3) Rise 6.x ParticleDistanceComponent, a performance component, drops any particle further than 6 blocks from the player. (4) Rise 6.x ParticleCheck, a security feature, token-buckets particle counts and drops floods. (5) Tenacity 6.0 AntiExploit cancels particles with extreme speed or count, and Sigma 4.11 Criticals skips S2A inside its own packet state machine so the crit-trigger logic is not disturbed.

Exploit surface

Particle floods are a classic client-crash vector: a server sends one S2A with a huge count or repeated packets, and the client spawns thousands of entities per tick. Anti-cheat servers also use particle bursts as visual flags for cheaters (crit particles on KillAura, etc.). Client defenses range from blanket cancellation (Memeware) to rate limiting (Rise ParticleCheck: accumulate count, drain 6 per packet, cap 150, drop over 100) to heuristic drops (Tenacity: speed >= 1 or count > 1). The trade-off is visibility: aggressive cancellation hides legitimate gameplay effects.

Server-Side Handling

WorldServer.spawnParticle builds one S2APacketParticles per batch with particle type, longDistance flag, x/y/z floats, three offset floats, speed, count, and a varint data array. It sends via ConfigurationManager.sendToAllNear (radius 512 when longDistance, else 32). NetHandlerPlayClient.handleParticles then loops count times through clientWorldController.spawnParticle, which is where a flood becomes a client-side hang. No server-side cap exists on count in vanilla 1.8.9.

Protocol Analysis

Encoding: String particle name, boolean longDistance, float x, float y, float z, float offsetX, float offsetY, float offsetZ, float speed, int count, then a varint-length int array of particle arguments used only by iconcrack and blockcrack. The name is read with readStringFromBuffer(64). Count 0 is special: offsets become velocity for a single particle. The packet was introduced in 1.8 with the EnumParticleTypes refactor that replaced the older string-only effect packets.

Anti-Cheat Landscape

Anti-cheats use particles as a side channel rather than flagging the packet itself: critical-hit particles around a target are evidence for killaura checks on servers that render them. The client-side countermeasures here are defensive, not evasive. The interesting tension is Rise ParticleCheck's accumulator: it treats particle arrival as a budget (drain 6 per packet, cap 150, drop when the bucket exceeds 100), which keeps normal combat particles while killing flood attempts. Blanket cancels (Memeware) trade all particle feedback for stability.

implementation Implementation Cases

The particle broadcast packet, and the only one of the six where client defense depth actually shows: blanket cancel (Memeware), selective cancel (Rise 5.99 slime mode), distance culling (Rise 6.x performance component), flood rate limiting (Rise 6.x ParticleCheck), and crash heuristics (Tenacity AntiExploit). Sigma's Criticals skips it inside its packet state machine.

ParticleDistanceComponent (performance) (Rise 6.2.4, Rise 6.1.30)

Drop particle packets whose origin is more than 6 blocks away to save GPU work.

A Component (non-module system) listening on PacketReceiveEvent. For each S2A it computes the squared distance from the player to the packet origin and cancels the packet when distanceSq >= 36, i.e. 6 blocks. Particles closer than 6 blocks pass through untouched.

ParticleCheck (security) (Rise 6.2.4, Rise 6.1.30)

Rate-limit inbound particle volume so a malicious server cannot crash the client with a flood.

A SecurityFeature. For each S2A it adds the packet's particle count to an accumulator, drains 6 per packet, and clamps the bucket at 150. The packet is dropped when the bucket exceeds 100, or when count is < 1, |count| > 20, or speed is negative or above 1000. Normal combat particles pass because their per-packet counts are small.
