Deep Dive

Role in the protocol

C16 carries one enum state: PERFORM_RESPAWN, REQUEST_STATS, or OPEN_INVENTORY_ACHIEVEMENT. It is the client's status signal for lifecycle events: respawn after death, stats/achievement screen state, and the open-inventory achievement that vanilla fires when the player presses E. The server's processClientStatus switches on the enum: PERFORM_RESPAWN recreates the player entity (with hardcore and end-conquest special cases), REQUEST_STATS flushes the stat file, OPEN_INVENTORY_ACHIEVEMENT triggers the openInventory achievement.

Vanilla handling

processClientStatus: for PERFORM_RESPAWN it checks the end-conquest flag, hardcore bans, and that the player's health is <= 0 before recreating the player entity. REQUEST_STATS calls getStatFile().func_150876_a. OPEN_INVENTORY_ACHIEVEMENT triggers AchievementList.openInventory. Notably the OPEN_INVENTORY_ACHIEVEMENT state has no state validation: the client can claim its inventory opened at any time, which is exactly what inventory managers and disablers abuse to fake the inventory-open state.

Why clients touch it

AutoArmor (Sigma, Spicy) sends OPEN_INVENTORY_ACHIEVEMENT in FakeInv mode so the server believes the inventory is open, letting shift-clicks register outside a real GUI. Inventory managers (Spicy InventoryManager, Rise Manager) track and force the open state with C16. InvMove/CancelInventoryMove (Rise 5.99, Rise 6.x) cancel the C16 open so the server never learns the player is in a GUI while moving. Disablers (Rise 5.99 Disabler sends PERFORM_RESPAWN; Rise 6.2.4 WatchdogDisabler sends OPEN_INVENTORY_ACHIEVEMENT before click-window abuse) use the status packet to reset server-side player state. Spicy ChestStealer and Bhop reference C16 for the open-inventory close trick.

Exploit surface

PERFORM_RESPAWN resets the player entity: position, health, and the hasMoved flag. Sending it outside death (Rise 5.99 Disabler c16 mode) recreates the player and can clear server-side tracking state, which is a classic anti-cheat reset vector. OPEN_INVENTORY_ACHIEVEMENT with no real GUI open desyncs the server's inventory-open flag; clients then move and click while the server thinks the container is open, which InventoryMove modules pair with C0E clicks. The achievement trigger also fires a stat, so spam shows up in stat logs.

Server-Side Handling

processClientStatus switches on the enum. PERFORM_RESPAWN: end-conquest recreate, hardcore ban/kick paths, then recreatePlayerEntity only when health <= 0. REQUEST_STATS: flush stat file. OPEN_INVENTORY_ACHIEVEMENT: trigger the achievement; no check that a GUI is actually open. markPlayerActive is called on every status packet.

Protocol Analysis

Fields: VarInt enum ordinal (0 = PERFORM_RESPAWN, 1 = REQUEST_STATS, 2 = OPEN_INVENTORY_ACHIEVEMENT). Sent in PLAY state. Vanilla fires OPEN_INVENTORY_ACHIEVEMENT from GuiInventory open; modules send it from tick handlers. The enum is the only payload, so spoofing is a one-int forge.

Anti-Cheat Landscape

Anti-cheats correlate OPEN_INVENTORY_ACHIEVEMENT with the actual GUI state: opening the inventory while moving is the InventoryMove flag, so CancelInventoryMove cancels the C16 rather than the movement. PERFORM_RESPAWN outside death is a strong reset-abuse signal on servers that track entity recreation; Rise 5.99 gates it behind a packet-cooldown so it does not spam. WatchdogDisabler pairs the C16 open with C0E clicks, and the PingSpoofComponent parks C16 in its blink class list so delayed status packets do not leak.

anticheat Anti-Cheat Checks

The client status packet is a lifecycle signal: PERFORM_RESPAWN after death and OPEN_INVENTORY_ACHIEVEMENT to open the statistics screen. Server-side anticheats use it in two ways. Respawn handling resets movement, inventory and combat state so the player starts clean after death, and a respawn command sent at the wrong time is a disabler signature. The open-inventory command also toggles the state that inventory-move and inv-tweak checks rely on, because moving while a screen is open is what inventory move cheats do.

InventoryWalk (AutoEye) (heirteir-AutoEye)

Flags position changes while the inventory event is active and the client should be frozen.

Check of type INVENTORY_EVENT: it fires when the client reports the open-inventory event. The check passes only if the player moved, lastFlying is zero, physics say the player is moving, the server velocity is zero on both horizontal axes, and less than 60 ms passed since the last move. On a pass it reverts by closing the player's inventory.

Detects: Inventory walk where the player moves while the inventory screen is open.
