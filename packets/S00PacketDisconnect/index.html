Deep Dive

Role in the protocol

S00PacketDisconnect is the LOGIN-state kick: the server sends it with a JSON IChatComponent reason whenever the handshake fails before the player exists. NetHandlerHandshakeTCP uses it for protocol version mismatches, NetHandlerLoginServer for banned, full, whitelisted or unverified players, and any plugin that rejects a join during login. The client's NetHandlerLoginClient.handleDisconnect closes the channel with the reason, which surfaces as the GuiDisconnected screen. Its PLAY-state sibling is S40PacketDisconnect, used for kicks after the world loads.

Vanilla handling

NetHandlerLoginClient.handleDisconnect calls field_147393_d.closeChannel(packetIn.func_149603_c()), which tears down the NetworkManager and shows the disconnect screen with the JSON reason rendered. The server side has no symmetric handler because this packet is server-to-client only; the server closes the connection after sending it. Because the client handler runs on the login thread path, a module hooking PacketReceiveEvent sees the packet before the channel close, which is the window the 8 clients use to clean up state.

Why clients touch it

Two families in the 8 clients use this packet as a state-hygiene signal. Rise 5.99 Speed (line 1917) and Timer (line 81) reset their balance accumulators on S00PacketDisconnect so the MMC timer-balance state starts clean on the next join attempt. Spicy Disabler clears its C0FPacketConfirmTransaction buffer on the packet so stale transactions are never flushed into a fresh connection. No true AutoReconnect module hooks it in this corpus: the auto-rejoin features of these clients key off the play-state disconnect path or onDisconnect, not the login kick, which is why the packet sees no reconnect logic.

Exploit surface

Cancelling the packet would suppress the kick screen, but the channel close is driven by the server's own side, so the client gains nothing. The useful behavior is the reverse: treat the packet as a reliable 'connection died' notification. Clearing buffered transactions on disconnect matters because a stale C0FPacketConfirmTransaction replayed after relog desyncs the new window/uid sequence and can trip transaction-based anti-cheats. Timer's balance reset is defensive in the same spirit: a leftover negative balance would gate timerSpeed to 1 on the next join for no reason.

Server-Side Handling

Sent by NetHandlerHandshakeTCP for protocol mismatch (lines 35/39), by NetHandlerLoginServer for banned/full/whitelist and auth failures (line 79), and by plugins during login. The server closes the connection after sending; the client's handleDisconnect closes the channel with the reason, showing GuiDisconnected.

Protocol Analysis

LOGIN state, id 0x00, one IChatComponent serialized as a JSON string with a VarInt length prefix. Clientbound only. Distinguished from the PLAY-state S40PacketDisconnect by connection state; the two share a name but are different classes. Because it arrives before the world exists, module event buses that only fire post-join never see it, which is why only receive-side state cleanup hooks it.

Anti-Cheat Landscape

Not an anti-cheat surface: the packet is server-initiated and carries no client-controlled data. Its relevance to anti-cheats is indirect, in what clients do in response: flushing buffered C0F transactions on disconnect keeps the exploit state machine clean, and a client that fails to do so can carry stale transaction state into the next session, which transaction-tracking anti-cheats (Verus-style) would flag.

implementation Implementation Cases

The LOGIN-state kick carrying the JSON reason. No module cancels it, because the server closes the channel anyway; Rise 5.99 Speed/Timer and Spicy's Disabler instead use it as a reliable connection-death signal to reset timer balance and flush buffered transactions before the next join.

Speed / Timer (balance reset) (Rise 5.99)

Reset the timer-balance accumulator when the server kills a login, so the MMC timer exploit restarts from zero on the next join attempt.

A PacketReceiveEvent handler checks instanceof S00PacketDisconnect. Timer.java zeroes balance, sentMessage and lastPreMotion; Speed.java zeroes balance at line 1917. Timer's MMC mode otherwise maintains a balance of 50ms per game tick minus real elapsed time, and only allows timerSpeed above 1 when the balance drops below -1000, so a stale balance would silently disable the exploit after a failed join.

Disabler (buffer flush on kick) (Spicy)

Drop the buffered C0FPacketConfirmTransaction queue when the connection dies, so no stale transaction is replayed into the next session.

EventPacket pre handler checks instanceof S00PacketDisconnect and clears C0FPackets. The same queue is cleared on C00Handshake (new connection) and otherwise drained at 500-1250ms intervals via sendPacketNoEvent while the disabler is active. The module also flushes the remainder on disable.

anticheat Anti-Cheat Checks

The anticheat corpus treats the disconnect packet as a punishment transport rather than a check surface: Grim and BetterAnticheat construct WrapperPlayServerDisconnect packets to kick flagged players, Artemis wraps PacketPlayOutKickDisconnect in its packet library, and a long tail of Bukkit-era anticheats (Negativity, NoCheatPlus, ThotPatrol, Daedalus, AutoEye, AntiCheatReloaded, AntiCheatPlus) react to kicks through PlayerKickEvent instead of the wire packet. No anticheat inspects the login-state kick itself, because the server initiates it and it carries no client-controlled data.

Kick disconnect wrapper (Artemis) (artemisac-artemis-minecraft-anticheat)

Wraps PacketPlayOutKickDisconnect in Artemis's packet library so the anticheat can read the kick packet on the wire instead of relying on Bukkit events.

GPacketPlayServerKickDisconnect is a GPacket annotated with @PacketLink to the PacketPlayServerKickDisconnect interface and implements ReadableBuffer. It is registered in PacketRepository at SERVER_PLAY + 39 and loaded by PacketExecutor and ProtocolGeneratorDirect, which keeps the play-state packet stream fully typed.

Detects: No detection logic. The wrapper lets Artemis observe every kick the server sends; punishment decisions live elsewhere.

Proxy-detection disconnect (PacketPluginMessage) (GrimAnticheat-Grim)

Kicks players who route through a ViaVersion proxy, using the disconnect packet as the punishment transport.
