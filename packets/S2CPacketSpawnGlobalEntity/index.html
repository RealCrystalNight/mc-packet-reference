Deep Dive

Role in the protocol

Spawns a globally visible entity, in 1.8.9 exclusively the lightning bolt. The server broadcasts it to every player within 512 blocks of the strike (WorldServer.addWeatherEffect via sendToAllNear). The client handler converts the x32 fixed-point coordinates and, when the type byte is 1, instantiates an EntityLightningBolt in the client world. Because the entity is server-created and broadcast, it is the only lightning representation the client ever sees.

Vanilla handling

NetHandlerPlayClient.handleSpawnGlobalEntity divides each coordinate by 32.0D and builds an EntityLightningBolt only when the type byte equals 1; any other type yields a null entity and is dropped. The bolt is then added to the client world, which drives its ambient light flash and thunder sound. Server-side the packet constructor derives entityId, coordinates and type from the Entity argument passed in by WorldServer.

Why clients touch it

Two module-grade consumers in the corpus. Rise 6.1.30 and 6.2.4 ship LightningTracker, an exploit-category module that prints the strike coordinates and distance to chat on every type-1 packet. LiquidSense Dev ships LightningCheck, a world-category module with the same read pattern: it divides the fixed-point coordinates back to blocks and posts them to chat, while also storing them in static x/y/z fields that other modules can read. Both are informational, not ESP. The remaining seven client dirs (Memeware, Nekoware, Rise 5.99, Sigma, Spicy, Tenacity, November Recode 2.0) reference the packet only through vanilla NetHandlerPlayClient.

Exploit surface

The packet is a broadcast with a server-chosen entityId and position, so a malicious server can spam it to fake lightning at arbitrary coordinates; there is no client-side validation beyond the type check. The 512-block broadcast radius means a strike far outside the client's render distance still spawns an entity. No client in the corpus abuses this for teleport hacks or lightning-based exploits, and none uses it for anti-cheat purposes.

Server-Side Handling

WorldServer.addWeatherEffect calls ConfigurationManager.sendToAllNear with a 512.0D radius on the strike position, same dimension, constructing S2CPacketSpawnGlobalEntity from the EntityLightningBolt. The packet's constructor copies entityId, x*32, y*32, z*32 and type (1 for lightning) from the entity. NetHandlerPlayClient only materializes the bolt when type == 1, ignoring the entityId for lookup since the client creates the entity fresh.

Protocol Analysis

Encoding: VarInt entityId, int x*32, int y*32, int z*32, byte type. Coordinates are fixed-point at 1/32 block resolution, finer than S29's 1/8. The type byte is the only discriminator; in 1.8.9 only 1 (lightning) is ever sent. The packet predates the generic Packet<T> signature in the older clients (raw Packet with double dispatch) while Rise 6.x uses Packet<INetHandlerPlayClient>.

Anti-Cheat Landscape

No anti-cheat touches this packet. Lightning is ambient weather; there is no cheat surface to measure. The only observable abuse would be server-side strike spam to distract or desync clients, which no module in the corpus defends against. The 512-block radius is worth noting for anyone building lightning-based radar: strikes beyond render distance still arrive.

LightningTracker (Rise 6.2.4, Rise 6.1.30)

Print a chat message with the coordinates and distance of every lightning strike.

A PacketReceiveEvent listener. For each S2C it divides the x32 coordinates back to blocks, rounds to two decimals, and when the type byte is 1 calls ChatUtil.display with the position and the player's distance to the strike. It is an exploit-category module but performs no world manipulation.

LightningCheck (LiquidSense Dev)

Report lightning strikes to chat and expose their coordinates in static fields for other modules.

An @EventTarget onPacket handler on the LiquidBounce PacketEvent bus. For each S2CPacketSpawnGlobalEntity whose type byte is 1 it divides the x32 fixed-point coordinates by 32.0D, stores them in public static x/y/z fields, and prints a prefixed chat line with the strike position. The unused C07PacketPlayerDigging import is dead weight carried over from a copy-paste skeleton.
