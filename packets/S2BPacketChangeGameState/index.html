Notes

Reason 0: bed can't be set (respawn). Reason 1/2: rain toggle. Reason 3: gamemode change (value=0-3). Reason 4: credits. Reason 5: demo. Reason 6: arrow hitting entity. Reason 7/8: fade values. Reason 9: elder guardian effect.

Deep Dive

Role in the protocol

A two-field state toggle: an unsigned byte reason and a float value. It is the server's mechanism for global client state that has no dedicated packet: rain start/stop and strength, gamemode changes, the end-game credits screen, the demo screen and its help messages, arrow-hit feedback, and the elder guardian mob-appearance effect. EntityPlayerMP sends reason 4 on end-game and reason 3 with the new GameType ID on gamemode change; WorldServer and ServerConfigurationManager drive reasons 1, 2, 7 and 8 for weather.

Vanilla handling

NetHandlerPlayClient.handleChangeGameState switches on the reason. Reason 1 sets raining true, 2 sets raining false, 3 calls playerController.setGameType(GameType.getByID(value)), 4 opens GuiWinGame, 5 routes the demo screen (value 0) or demo help messages (101/102/103), 6 plays the successful-hit sound, 7 sets rain strength, 8 sets thunder strength, 10 spawns the mob-appearance particle and guardian curse sound. Reasons with a MESSAGE_NAMES entry also push a translated chat line.

Why clients touch it

Two Rise 6.x handlers, both defensive. Ambience, a render module, cancels reasons 1 and 2 whenever the user has forced a custom weather mode, so server rain toggles cannot override the client's chosen sky. DemoCheck, a security feature, drops reason 5 with value 0, which is the demo-mode screen: a malicious or griefing server can lock a player into the demo overlay, and the check removes that lever. No client in the corpus uses this packet for AutoGG-style game-end detection; reason 4 is ignored everywhere.

Exploit surface

The demo screen (reason 5, value 0) is the abuse vector: it swaps the HUD and movement handling to demo mode, which hostile servers use to grief players. Rain reasons are a nuisance vector on weather-cycling servers, which is exactly why Ambience filters them. Reason 3 gamemode changes are server-authoritative and no client in the corpus fights them; overriding setGameType client-side desyncs the player controller and is a known crash/flag source, which is why it is absent.

Server-Side Handling

Server senders: WorldServer.updateWeather sends reason 7/8 (strengths) per dimension and reason 1/2 (rain stop/start) globally; ServerConfigurationManager sends reason 1 plus 7/8 on player join; EntityPlayerMP sends 4 on end-game and 3 with GameType.getID on gamemode change; EntityArrow sends 6 to the shooter on a successful hit; EntityGuardian sends 10 on the elder guardian effect; DemoWorldManager sends 5 with 0/101/102/103. The client handler applies each reason directly to client world state, with no validation of value ranges.

Protocol Analysis

Encoding: unsigned byte reason, float value. The value is only meaningful for reasons 3 (gamemode id), 5 (demo sub-state), 7 and 8 (weather strengths). Reasons 0, 4, 6, 9, 10 carry value 0.0F. MESSAGE_NAMES maps reasons 1, 3, 4, 5 to chat translations, so some reasons produce both a state change and a chat line. Reason 9 is defined but unused in 1.8.9; reason 10 is the elder guardian variant.

Anti-Cheat Landscape

No anti-cheat measures this packet. Gamemode changes are server-authoritative and instant, so client-side gamemode spoofing is a desync crash rather than a cheat. The defensive angle is server trust: DemoCheck exists because a hostile server can emit reason 5 to disable normal gameplay, and Ambience exists because weather packets fight user-selected ambience. Both are filters on server-controlled state, not evasions.

implementation Implementation Cases

The catch-all state toggle: rain, gamemode, credits, demo, arrow feedback, guardian effect. The 8 clients use it only defensively: Rise 6.x Ambience filters rain toggles under forced weather, and Rise 6.x DemoCheck kills the demo-screen lockout. No game-end (credits) detection exists in this corpus.

Ambience (weather override) (Rise 6.2.4, Rise 6.1.30)

Force a chosen weather and stop server rain toggles from overriding it.

When the Weather mode is not Unchanged, the PacketReceiveEvent handler cancels every S2B whose reason is 1 or 2 (begin/end rain). A PreMotionEvent branch re-applies the forced state every 20 ticks via WorldInfo setters, and onDisable resets rain strength and weather flags to defaults.

DemoCheck (security) (Rise 6.2.4, Rise 6.1.30)

Drop the demo-mode packet so a server cannot lock the client into the demo screen.

A SecurityFeature on the packet receive chain. It drops any S2B where reason is 5 and value is 0, which is exactly the packet DemoWorldManager sends to open GuiScreenDemo. The demo help messages (values 101-103) are not blocked, only the screen-opening state.
