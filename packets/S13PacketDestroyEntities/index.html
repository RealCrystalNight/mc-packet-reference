Notes

This is how entities are removed when they die, despawn, or players disconnect.

Deep Dive

Role in the protocol

The batch removal packet: a VarInt count followed by that many VarInt entity ids. The server flushes it from EntityPlayerMP.destroyEntitiesInWorld each tick with the accumulated destroy list, and sends the single-id form when a specific entity is removed (player disconnect, entity despawn). The client removes each id from the world's loaded entity list and clears the render manager's entry in handleDestroyEntities, which is how dead mobs, picked-up items and left players vanish.

Vanilla handling

EntityPlayerMP accumulates entity ids to destroy and sends one S13 per tick in destroyEntitiesInWorld; the single-id constructor is used by removeEntity and on player disconnects. NetHandlerPlayClient.handleDestroyEntities iterates the ids, removes each from world.loadedEntityList, clears the entity's render state and drops it from the client's entity lookup. Because removal is id-based and immediate, any client cache keyed by entity id must prune itself on S13 or it will hold stale entries.

Why clients touch it

Cleanup is the theme. Sigma 4.11 Ranking removes hit and prosecutor records for destroyed ids so a kill stat cannot fire after the target despawns. Rise's TranslationComponent maps S13 through the DESTROY_ENTITY entry of its PacketType enum, deleting the entity's position from the bypass map. Rise's PingSpoofComponent buffers S13 inside the players tuple so destruction stays ordered relative to held entity updates. KillAura and ESP target lists in these clients hold entity objects from the world list, so the vanilla removal handles them with no packet hook.

Exploit surface

S13 is a pure removal vector: the server despawns arbitrary ids, and the client has no say in it. The abuse angle is timing: entities destroyed on the server remain attackable client-side only if the client delays the packet, which is exactly what buffering S13 in PingSpoofComponent does, keeping ghost entities alive for the spoof window. Anti-cheats watch for players attacking ids that were destroyed server-side (attack-after-desync), the signature of ghost-entity kill aura; a client that buffers S13 must also stop targeting those ids when the flush lands.

Server-Side Handling

EntityPlayerMP.destroyEntitiesInWorld collects pending entity ids and sends a single S13 per tick; the single-id form is sent by removeEntity and on player disconnects. The client handler iterates the ids, removes each entity from world.loadedEntityList, clears its render state and drops it from the entity lookup. No validation is applied to the id list, so ids that do not exist are ignored.

Protocol Analysis

VarInt count, then count VarInt entity ids. The count field makes the packet self-describing; 1.8 clients accept any count including 0. Entity ids are server-assigned and unique per world session, which is why id-keyed caches (Sigma's hit maps, Rise's translation map) can prune by id without ambiguity. The packet is emitted every tick the destroy list is non-empty, so it arrives in bursts.

Anti-Cheat Landscape

The packet itself is never flagged; its timing is. Attack-after-desync detection compares the ids a client attacks with the ids the server destroyed, so any buffering or replay of S13 that outlives the destroy is the detectable pattern. Ping-spoof buffering of S13 is safe only while the flush stays inside the anticheat's entity-desync tolerance, which is why Rise pairs the component with per-anticheat velocity and teleport handling.

implementation Implementation Cases

The batch entity-removal packet. In the 8-client corpus its handlers are all cache pruning: Sigma's Ranking drops hit/prosecutor records, Rise's TranslationComponent removes map entries through DESTROY_ENTITY, and Rise's PingSpoofComponent buffers it with the entity stream so destruction stays ordered while ping spoofing. KillAura and ESP need no hook because their target lists are world-entity objects.
