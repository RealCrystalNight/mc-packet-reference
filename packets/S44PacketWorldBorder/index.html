Deep Dive

Role in the protocol

World border state machine with six actions: SET_SIZE, LERP_SIZE, SET_CENTER, INITIALIZE, SET_WARNING_TIME and SET_WARNING_BLOCKS. ServerConfigurationManager broadcasts the five change actions to all players on border mutation (lines 245-261 in the MCP builds) and sends INITIALIZE to each player on join (line 786). INITIALIZE is the only action carrying the full state: center, current and target diameter, transition time, and both warning values.

Vanilla handling

The client handler func_175093_a delegates to packet.func_179788_a(worldBorder), which mutates the single WorldBorder object owned by the client world: setCenter, setTransition, setWarningDistance and setWarningTime. The border then feeds the renderer's red vignette and the camera clamp in EntityRenderer. It is one of the few packets whose handler mutates shared world state instead of copying values into local fields.

Why clients touch it

No module in the 8 clients references S44. Border tracking would matter for movement modules pathing around a shrinking border or for border-bypass claims, but none exists in the corpus. The border is server-enforced: EntityPlayerMP movement validation and WorldBorder.intersects run server-side and teleport or damage players who cross it, so the client's copy is purely cosmetic and modules gain nothing by intercepting it.

Exploit surface

All six actions deserialize doubles and a VarLong transition time with no sanity bounds; a hostile server can inject NaN or extreme diameters into the client WorldBorder, which the renderer then lerps against, producing visual glitches (the classic NaN border). Because enforcement is server-side, corrupting the client border changes nothing gameplay-relevant. The notable quirk is LERP_SIZE's VarLong time field, which is milliseconds server-side, not ticks.

Server-Side Handling

ServerConfigurationManager registers a WorldBorder listener that broadcasts SET_SIZE, LERP_SIZE, SET_CENTER, SET_WARNING_TIME and SET_WARNING_BLOCKS to all players on mutation (lines 245-261, MCP numbering), and sends INITIALIZE in initializeConnectionToPlayer (line 786). INITIALIZE serializes the whole border: center X/Z doubles, diameter and target doubles, VarLong transition time, warning distance and warning time ints.

Protocol Analysis

Action is a VarInt enum; payload depends on action. SET_SIZE: one double (target diameter). LERP_SIZE: old diameter double, target double, VarLong transition time in milliseconds. SET_CENTER: two doubles. SET_WARNING_TIME and SET_WARNING_BLOCKS: one int each. INITIALIZE: center doubles, both diameters, VarLong, and both warning ints. readEnumValue can return null on an out-of-range action, which NPEs in the read switch.

Anti-Cheat Landscape

No anti-cheat measures border packets. The server enforces the border in its own movement pipeline (EntityPlayerMP position validation against WorldBorder.intersects), so client-side border state has no bearing on any server-side check. The only client-visible effect of tampering is rendering artifacts.

implementation Implementation Cases

Six-action world border state machine, broadcast on change and fully initialized on join. Server-enforced, so the client copy is cosmetic; none of the 8 clients has a module that references it. The interesting wire details are the mixed field widths and the VarLong transition time.

anticheat Anti-Cheat Checks

The world border packet is the one clientbound world-state packet anticheats genuinely consume. Grim decodes all five actions into a border state and feeds it into the collision pipeline so phase checks treat the border as a solid wall, and intave decodes the same actions into the border model its movement simulation runs against. NCP and Artemis implement the border-as-wall idea too, but they read Bukkit's server-side WorldBorder instead of the packet. Negativity and Artemis also register the packet type.

PacketWorldBorder (Grim) (GrimAnticheat-Grim)

Mirror the server's world border state on the compensation side so collision and movement checks know where the border is.

A PacketSendListener that wraps the five border packet forms (WORLD_BORDER action packet, INITIALIZE_WORLD_BORDER, WORLD_BORDER_CENTER, WORLD_BORDER_SIZE, WORLD_BORDER_LERP_SIZE) and mutates a BorderExtent: SET_SIZE and WORLD_BORDER_SIZE set the diameter, LERP_SIZE and WORLD_BORDER_LERP_SIZE build a moving extent with the transition duration, SET_CENTER and WORLD_BORDER_CENTER move the center, and INITIALIZE fills the whole state plus the portal teleport boundary. Each update is transaction-bracketed and applied on the next real-time task, and tickBorder() advances the lerp on movement ticks.

Detects: Nothing directly. It is the data foundation for the border collision check.

Treat the world border as an axis-aligned collision wall so phase and clipping checks cannot move a player through it.
