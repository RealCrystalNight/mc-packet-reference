Notes

S14 is the abstract base — the actual packet IDs are 0x15 (S15), 0x16 (S16), 0x17 (S17). All share the same class hierarchy. The client adds the relative deltas to the entity's current server position to get the new position.

Deep Dive

Role in the protocol

S14PacketEntity is the abstract base for the three relative entity-movement packets. The wire IDs are S15PacketEntityRelMove (0x15), S16PacketEntityLook (0x16) and S17PacketEntityLookMove (0x17); the base class itself is never registered as a sendable ID and EnumConnectionState registers only the subclasses. Every variant carries a VarInt entityId and an onGround flag, plus byte deltas (x 32) and/or rotation bytes (x 256/360). The client accumulates the deltas onto the entity's last server position, so a position error in one tick carries into every later tick until the server sends an absolute S18.

Vanilla handling

NetHandlerPlayClient.handleEntityMovement (Memeware 7.3 bundle, line 551) is shared by all three subclasses: it adds the packet's posX/posY/posZ to entity.serverPosX/Y/Z, recomputes the position as serverPos / 32.0, keeps the current yaw/pitch unless the packet carries rotation (S16/S17), then calls setPositionAndRotation2 with interpolation factor 3 and teleport flag false, and finally writes packetIn.onGround into entity.onGround. Server-side, EntityTrackerEntry picks the variant by motion magnitude: look-move when both position and rotation changed, rel-move when only position changed, look when only rotation changed (corpus lines 213-217, 265).

Why clients touch it

The 8-client corpus shows three consumer families, none of them ESP. Rise 6.x combat: LegitReach accumulates a server-truth realPosition from S14 deltas for its ping-spoof reach, and WatchdogVelocity buffers the S15/S16/S17 subclasses and replays them for its Watchdog Backtrack mode. Rise 6.x infrastructure: the translation component's PacketType enum maps ENTITY_REL_MOVE, ENTITY_LOOK_MOVE and ENTITY_LOOK into a per-entity position cache, and PingSpoofComponent classifies all S14 subclasses in its players tuple. Rise 5.99 anticheat: PlayerData re-derives position, deltas and onGround from S15/S17 and feeds KeepSprintA, SpeedA, EagleA and GroundSpoofA/B. Memeware, Nekoware, Sigma, Spicy and Tenacity reference the packet only through the vanilla handler.

Exploit surface

Relative deltas are trusted per packet and corrected only by S18, which makes the S14 stream the raw material of every position-based client-side simulation: reach modules reconstruct the opponent's true position, anticheats reconstruct it to verify onGround transitions and speed. The onGround bit is authoritative for the tick it arrives in, which is exactly what GroundSpoofA/B and EagleA test. Reach exploits work through latency: LegitReach delays all player-class packets so the server keeps a stale player position while the client attacks from a closer interpolated one. Dropping or reordering S14 packets is invisible to the server because they are clientbound state announcements with no acknowledgement.

Server-Side Handling

The server never processes S14 on receive; it is purely clientbound. The client handler accumulates: entity.serverPosX += posX (and Y/Z), position = serverPos / 32.0, rotation kept unless S16/S17 carry bytes, then setPositionAndRotation2(..., 3, false) and entity.onGround = packet onGround. Because the accumulation never resets, any dropped packet permanently shifts the entity by its delta until an S18 arrives. EntityTrackerEntry emits S15/S16/S17 at the tracking update rate (every 2 ticks for players, more often for fast entities) and switches to S18 once the one-tick displacement exceeds the 4-block threshold.

Protocol Analysis

Deltas are signed bytes x 32, so a single packet moves an entity at most 3.97 blocks per axis; rotation bytes decode as yaw * 360 / 256. The onGround flag is present on the base class and therefore on all three subclasses. S16 (look) and S17 (look-move) are the only places the body yaw/pitch of a tracked entity changes; S19PacketEntityHeadLook separately updates only the head yaw. There is no ordering guarantee between S14 and S18 for the same entity; a teleport supersedes any pending deltas because it overwrites serverPosX/Y/Z.

Anti-Cheat Landscape

Client-side anticheats (Rise 5.99) and server anticheats both treat the S14 stream as ground truth for movement verification. Ground-spoof detection keys on the onGround flag combined with block probes; eagle detection on the sneak flag in the S1C metadata stream timed against S14 ticks; keepsprint on the speed delta around S0B animations. For cheat clients, the S14 stream is what makes ping-spoof reach and backtrack possible: buffering it has zero server cost, and the server cannot distinguish a delayed entity stream from lag. The trade-off is visual, not statistical: held entity packets produce stutter and frozen-head artifacts that staff can spot.

Velocity cancel combined with an entity backtrack: the S14 subclasses are held and replayed to keep the client and server entity timelines deliberately divergent.

anticheat Anti-Cheat Checks

Server-side anticheats never see S14 on the wire: it is a clientbound announcement of entity relative movement, rotation and ground state. What they do see is the same stream on the send side, and the richest anticheats use it to keep a lag-compensated copy of every tracked entity's position so reach, phase and velocity checks compare the player against where the server actually believes entities are. The corpus splits into position-replication trackers (Hydro, Kauri, AntiHaxerman), wrappers that classify the S14 subclasses into a packet pipeline (Frequency, Artemis, FlopAC), and reach checks that either consume the replicated positions or, in ThotPatrol's case, admit that rel-move plus AABB would beat their own Bukkit-based math.

ReachD (reach against player positions) (freppp-ThotPatrol)

Classic 1.8 reach check; the corpus hit is the author's own TODO comment stating that tracking PacketPlayOutRelEntityMove and testing the AABB would be far more accurate than the Bukkit-position math the check actually uses.

On PacketAttackEvent the check measures the distance between attacker and victim eye locations, subtracts the vertical difference and a fixed 0.32 hitbox accommodation, and compares the result against maxReach. The threshold is inflated by ground state, yaw difference, recent horizontal speed (tracked on PlayerMoveEvent), the average ping of both players, TPS and the attacker's speed potion level. Three consecutive exceedances log a cheat.

Detects: Blatant reach abuse against players, with tolerance for lag, elevation and speed.
