Notes

Unlike S14 (Entity Relative Move), S18 sets ABSOLUTE position — the entity moves to this exact location regardless of where it was. Used when players teleport (ender pearls, chorus fruit), mobs teleport (endermen), or when S14 cumulative errors need correction.

Deep Dive

Role in the protocol

S18PacketEntityTeleport carries an absolute fixed-point position (ints x 32), rotation bytes and an onGround flag for one entity. It is the only entity-position packet with full coordinates, so it is both the correction mechanism for accumulated S14 error and the transport for genuine jumps: ender pearls, endermen, dimension changes and anything that moves more than 4 blocks in one tick. EntityTrackerEntry constructs it when the tracked entity's one-tick displacement exceeds the relative-move threshold (corpus line 222), and NetHandlerPlayServer sends it to a player on teleport (line 259).

Vanilla handling

NetHandlerPlayClient.handleEntityTeleport (Memeware 7.3 bundle, line 511) overwrites serverPosX/Y/Z with the absolute values, computes position as serverPos / 32.0 with y + 0.015625 (half a block in fixed point, the eye-height accommodation), decodes yaw/pitch as * 360 / 256, and calls setPositionAndRotation2 with interpolation 3 and the teleport flag. If the entity is already within 0.03125 blocks (x/z) and 0.015625 (y) of the target it keeps the current position and applies only rotation, which prevents micro-jitter on repeated teleports.

Why clients touch it

Five distinct consumers in the corpus. Rise 6.x: LegitReach snaps its realPosition to the absolute coordinates, WatchdogVelocity includes S18 in its spoof packet set and re-anchors on it, and PingSpoofComponent classifies it in the players tuple so teleports are delayed with the rest of the entity stream. Rise 5.99: PlayerData re-anchors serverPosX/Y/Z and zeroes ticksSinceLastTeleport so checks skip the teleport tick. Sigma 4.11: Ranking treats S18 as an entity-removal signal that finalizes kill/death records. Tenacity 6.0: AntiExploit cancels S18 with any coordinate beyond 30,000,000. Spicy: NoClip and Phase import the class but never branch on it, a leftover from their Sigma 2 lineage.

Exploit surface

S18 is clientbound and absolute, so the abuse direction is server to client: a malicious server can emit fixed-point coordinates that corrupt client-side position bookkeeping or trigger bounds bugs, which is exactly what Tenacity's AntiExploit threshold mitigates. For cheats, S18 is the epoch boundary of every position-based state machine: accumulated S14 error resets here, so reach and backtrack modules must re-anchor their reconstructed positions on it. The S08PacketPlayerPosLook + S18 pair is the server's complete teleport vocabulary, and disablers and reach modules watch both because a missed teleport poisons every later delta.

Server-Side Handling

The server side only emits S18, never validates it on receive. EntityTrackerEntry chooses it when the tracked entity moved 4+ blocks in a tick, and NetHandlerPlayServer sends it to a player being teleported. The client handler overwrites the entity's serverPosX/Y/Z, applies the +0.015625 y offset, keeps the current position when the entity is already within a 32nd of a block (rotation-only update), then interpolates with the teleport flag set. Because the client trusts the coordinates, a server can move an entity anywhere in the fixed-point range, which is the abuse AntiExploit guards against.

Protocol Analysis

Three ints (x 32), two bytes (x 256/360) and a boolean follow the VarInt entityId. The y offset of 0.015625 (0.5 / 32) is applied only on the client and is not part of the wire value. S18 supersedes any pending S14 deltas for the same entity because it overwrites the accumulated serverPosX/Y/Z. The packet is also sent to a player on respawn and dimension change, which is why Ranking's S08 + S18 combination distinguishes death from mere teleport.

Anti-Cheat Landscape

Server anticheats emit S18 as a correction and watch whether the client's later C03 positions rejoin the corrected location; a client that ignores the teleport or desyncs after it flags as position desync. The S08+S18 pair is the standard disabler/reach watch point: modules that delay clientbound traffic must flush on it or their position cache goes permanently stale. The client-side mirror (Rise 5.99 PlayerData) uses ticksSinceLastTeleport to suppress checks for a tick, an acknowledgment that even legitimate teleports produce movement anomalies.
