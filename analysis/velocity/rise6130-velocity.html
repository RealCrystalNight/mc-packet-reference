Overview

Rise 6.1.30's Velocity is a thin module class that holds a ModeValue with nineteen per-mode classes plus an On Swing boolean, moving every implementation into its own file under the velocity subpackage. The modes are Standard (percentage scaling), Buffer Abuse (cancel the first N knockbacks), Delay (ping-spoof the movement window), Legit/Jump Reset (inject a jump on the knockback tick), Ground (fake onGround one tick after the hit), Intave, Matrix, AAC, Vulcan (scale plus C0F cancellation), Redesky, Tick (stop motion after a delay), Bounce (invert the knockback), Karhu, MMC, Universocraft, Watchdog (cancel but keep grounded knockback), Grim Reduce (attack to satisfy Grim's velocity tracking) and Grim (cancel the velocity that follows the damage status). Each mode registers its own event listeners against the shared parent module, so the module's surface is the sum of the per-mode listeners.

Architecture

The parent Velocity class only builds the ModeValue and the onSwing boolean. Each mode is a Mode<Velocity> subclass in the velocity package that registers its own EventLink listeners, so enabling a mode activates exactly that mode's listeners. The onSwing boolean is read by most modes as a gate: when enabled, the listener returns unless the player is mid-swing, which ties anti-knockback to an attack animation. The modes fall into three families: packet-rewriting modes (Standard, Buffer Abuse, Vulcan, Redesky) that scale or cancel the S12 and S27 packets on receive, motion-timing modes (Tick, Bounce, Ground, Delay, Watchdog, Legit) that act from PreMotion or PreUpdate events against the hurtTime and ticksSinceVelocity counters, and anticheat-specific modes (Grim, Grim Reduce, Intave, Matrix, AAC, Karhu, MMC, Universocraft) that exploit a particular check's model.

Key techniques

The scaling modes share one pattern: on the S12 for the player entity, multiply motionX and motionZ by horizontal over 100 and motionY by vertical over 100 and replace the packet, or cancel outright when both are zero. Standard adds a guard that returns when motionY over 8000 exceeds 0.6, so heavy knockback is never touched, and an Explosion Ignore toggle that cancels S27 packets. Buffer Abuse cancels the first N knockbacks (Buffer setting) and scales the rest, resetting the counter after a scaled one. Vulcan adds a C0F cancellation on PacketSend while hurtTime equals 10, desyncing the transaction stream around the hit. Tick and Bounce act from PreMotion: Tick calls MoveUtil.stop() when hurtTime reaches 10 minus the setting, and Bounce inverts motionX/motionZ (or strafes while moving) and optionally motionY when hurtTime reaches 9 minus the setting.

Mode-specific streams

Delay is a ping-spoof: every PreUpdate it calls PingSpoofComponent.spoof with the delay setting times 50 milliseconds, so the server measures the player's ping as delayed and the knockback window stretches. Legit is a jump-reset: on the S12 while on the ground with positive motionY (and the legitTiming gates), it arms a jump flag that MoveInputEvent turns into a jump, with a Chance percentage. Ground fakes onGround one tick after the velocity and blocks the jump the next tick. Watchdog cancels the S12 but re-applies the real vertical motion when the player is near the last ground Y, keeping grounded knockback while removing airborne knockback. Grim waits for the S19 damage status (opcode 2) and cancels the velocity packet that follows, then sends a C07 digging packet so Grim's velocity tracking sees a block interaction. Grim Reduce attacks the target while ticksSinceVelocity is under 14 to satisfy Grim's knockback prediction.

What this file does

The module file is deliberately minimal: it declares the ModuleInfo, builds the ModeValue with all nineteen modes and sets Standard as the default, and exposes the onSwing BooleanValue. Every behavior lives in the mode classes, which register their own listeners, so this file is only the wiring. The mode list is the specification of what the module can do: Standard, Buffer Abuse, Delay, Legit (registered twice as Legit/Jump Reset and Polar), Ground, Intave, Matrix, AAC, Vulcan, Redesky, Tick, Bounce, Karhu, MMC, Universocraft, Watchdog, Grim Reduce and Grim.

The onSwing boolean is the one piece of shared state. It is read at the top of the receive handlers in Standard, Buffer Abuse, Vulcan, Redesky, Legit, Watchdog, Tick, Bounce and Ground, and in each case it gates the whole listener on mc.thePlayer.isSwingInProgress, so when enabled the module only suppresses knockback while the player is attacking. This is what makes the module look legitimate to velocity checks that expect knockback to be missing only during combat.

The mode registration is also where the two LegitVelocity instances differ: both use the same class with different names, so Legit/Jump Reset and Polar are the same jump-reset behavior under two labels. The default Standard mode is the safe baseline, and the Grim and Grim Reduce modes are the anticheat-specific answers to Grim's velocity prediction.

What this file does

StandardVelocity is the default and the template for the scaling family. Its PacketReceiveEvent listener, at VERY_LOW priority, first checks the onSwing gate and the cancelled state, then handles S12 and S27. For the player's S12 it returns early when motionY over 8000 exceeds 0.6, so a heavy hit passes untouched; when horizontal is 0 it cancels the packet and, if vertical is nonzero, applies the raw vertical motion directly to the player so the rise happens without a scaled packet; otherwise it scales the three motion components by the horizontal and vertical percentages and replaces the packet. The S27 branch scales the explosion offsets the same way, or cancels when the Explosion Ignore toggle is on.

The 0.6 guard is the interesting design choice. It means Standard only suppresses weak-to-medium knockback, which is the range where a velocity check's tolerance is small enough to flag; strong hits that would produce a visible missing-motion violation are left alone. The horizontal-zero branch shows the same logic: rather than scaling to zero, it cancels the packet and manually applies the vertical component, so the horizontal knockback is removed while the vertical rise still happens.

The listener is registered at VERY_LOW priority, which matters for the event bus: lower priority listeners run later, so Standard observes the packet after other modules have had their chance to cancel or modify it, and its own cancellation is the last word. The class holds only the three NumberValues and the BooleanValue, so all state is the settings themselves.

How it counteracts this module

Grim's KnockbackHandler is a PacketSendListener on ENTITY_VELOCITY that sandwiches the packet between two server transactions: one sent before the velocity and a second through tasksAfterSend after it. The velocity is recorded into firstBreadMap keyed by the first transaction id, and tickKnockback promotes an entry into lastKnockbackKnownTaken once a transaction with a larger id arrives, which proves the packet reached the client. From that moment the knockback vector is required movement: the prediction engine must see it in the player's motion, and onPredictionComplete compares the prediction offset against a threshold, set-backing the player when the offset accumulates past the maximum advantage.

The scaling modes are the direct targets. Standard at 0/0, Buffer Abuse while the counter is below the buffer, Vulcan at 0/0 and Watchdog's cancel path all remove the required vector, so the offset is the full knockback and the set-back fires. Standard's 0.6 guard only protects strong hits, which is exactly the range where Grim's threshold (default 0.001) is proportionally small. Tick's delayed stop loses because the vector was required from the moment the sandwich confirmed, before the tick window elapses. Bounce's inversion is also caught, since the prediction expects the original vector, not its negation.

The Grim mode is the honest answer to this check: it cancels the velocity that follows the S19 damage status and sends a C07 digging packet, and Grim's velocity tracking accepts the block interaction as the reason the knockback never appeared in motion. Grim Reduce attacks the target within 14 ticks of the velocity, which Grim's prediction consumes as the knockback being taken. Delay's ping spoofing only stretches the window, it does not remove the requirement, so it still flags against Grim.

How it counteracts this module

Hawk's MoveEvent matches every move's current velocity against the list of pending knockbacks. Each pending entry is a vector plus the time the server sent it, and it stays eligible while the elapsed time is within the player's ping plus 200ms. A match requires the move's Y to be within 0.01 of the knockback's Y (unless the player collides, jumps, swims or steps) and X and Z to fall inside a maxDiscrepancy window computed from walk speed, potions and the sprint multiplier, plus an epsilon. When a knockback entry becomes older than ping plus 200ms without any move matching it, failedKnockback is set and the check punishes at 5 VL.

Every cancel mode leaves the entry unmatched. Standard at 0/0, Buffer Abuse for the first N hits, Vulcan at 0/0, Redesky at 0/0 and Watchdog's cancel all produce moves with no knockback component, so the entry expires and flags. A partial reduction (Standard at 50/50) stays under the tolerance only when the scaled-down remainder still sits inside maxDiscrepancy; the stronger the original hit, the larger the absolute gap a fixed percentage leaves, so moderate to heavy reductions flag. Tick and Bounce are also caught: Tick's stop comes after the Y match window, and Bounce's inverted vector fails the Y and X/Z matches outright.

Hawk's tolerance is the bypass surface: small reductions that keep the movement inside maxDiscrepancy pass, and the ping-plus-200ms window forgives a knockback the player has not moved into yet. Among the Rise modes, tiny percentage reductions in Standard sit inside the window, and the Grim mode's C07 digging may satisfy Hawk's block-collision exemption for the Y match, but the cancel family is uniformly flagged.

How it counteracts this module

NCP's movement model queues the vertical velocity the server applies and later consumes it to explain the player's actual movement. SurvivalFly calls checkUnusedVelocity on every move, and the method reads the pos and neg UnusedTracker instances of the SimpleAxisVelocity tracker. UnusedTracker.addValue records a violation amount only when the direction has been blocked since the entry was added, meaning the server pushed velocity in a direction the player never moved, and quickCheckDirection reports the violation count, accumulated amount and update count before resetting.

In this build the check is a debug ledger: quickCheckDirection logs through DebugUtil and returns false with a TODO for a real frequency or amount check, so the player cannot fail it yet. The mechanism it would enforce is the queue model: getOrUseVerticalVelocity consumes queued velocity to explain a vertical move, and a cancelled knockback leaves the queued velocity unused, which is exactly the violation the tracker accumulates. Every Rise cancel mode (Standard at 0/0, Vulcan, Redesky, Watchdog, Buffer Abuse, Tick's stop, Bounce's inversion) would trip that ledger once it is enabled, because the vertical push is never consumed.

The honest statement is the debug-only status itself: a velocity module today faces NCP's SurvivalFly envelope, not this check, and unused velocity only appears in debug output until the TODO is implemented. Partial reductions leave a partial unused remainder, so the ledger would catch them too; the check as shipped cannot flag anything, which is why this entry documents the direction NCP is heading rather than an active counter.
