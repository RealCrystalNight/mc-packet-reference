Analysis

Overview

Tenacity's ResetVL is a bounded hop-and-timer burst that runs for exactly 25 ground hops and switches itself off. While the counter is under 25, every on-ground tick sets motionY to 0.11, re-pins the client's Y to the position captured at enable, and drives the vanilla tick multiplier to 2.25, so the client executes 2.25 ticks per real tick and every tick-driven outgoing cadence compresses to 2.25 times its real-time rate. The server sees rapid, small vertical moves at an accelerated rate — the movement stream it integrates runs faster than real time, and the keepalive echo (C00) and its latency measurement ride the same accelerated clock. After 25 hops the multiplier returns to 1 and the module toggles itself off; onDisable restores the static Timer.timerSpeed regardless of where the burst stopped.

Architecture

The module keeps two fields: jumped, the hop counter, and y, the altitude captured in onEnable. The single MotionEvent listener runs the whole loop, and the module toggles itself off from inside its own listener after the 25th hop — an unusual self-disable pattern. onEnable resets the counter and captures the current Y; onDisable restores the static Timer.timerSpeed to 1 so a manual toggle-off never leaves the multiplier applied.

Hop-and-pin loop

While on the ground with jumped at or below 25, each tick sets motionY = 0.11 (a small hop impulse), increments the counter, and re-pins posY to the enable-time Y. The net client-side motion is a vertical oscillation around a fixed altitude: hop up 0.11 velocity, get pulled back to the pin, hop again. The server sees the corresponding stream of small vertical moves — legible, plausible movement, but arriving at an accelerated cadence.

Timer acceleration

The loop drives mc.timer.timerSpeed to 2.25. The vanilla Timer.updateTimer accumulates elapsedPartialTicks += d2 * timerSpeed * ticksPerSecond (capped at 10 elapsed ticks), so 2.25 means the client runs 2.25 game ticks per real tick: every tick-driven send compresses to 2.25 times its real-time rate, and the movement packets the server integrates arrive faster than real time. The keepalive echo is the protocol's timing anchor: the C00 round trip is what server latency ledgers are keyed to, so the accelerated client clock shows up in the timing model even though the module itself never constructs a packet. Note that the module writes the instance field through mc.timer in the loop and the static Timer.timerSpeed in onDisable — the same static field in vanilla 1.8.9.

Teardown

After 25 hops the branch sets timerSpeed back to 1 and calls toggle(), turning the module off from within its own event handler. onDisable then runs as part of that toggle and re-asserts timerSpeed = 1 through the static reference, so the multiplier is restored exactly once per burst. The bounded design is deliberate: 25 hops at 2.25x is roughly eleven real seconds of accelerated movement, after which the client returns to a normal clock and the server's rate windows see the burst as a bounded anomaly rather than a sustained one.

How it counteracts this module

Hawk's TickRate measures real time between MoveEvents.
