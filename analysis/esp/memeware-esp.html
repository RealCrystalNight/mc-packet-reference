Overview

Player ESP is a wall-hack renderer with a single registered event handler. On every Render3DEvent it walks mc.theWorld.loadedEntityList and, for each EntityPlayer other than the local player, calls RenderUtils.drawEsp(o, new Color(0, 0, 0, 21).getRGB()), which draws a 1x2 block axis-aligned box around the entity position (posX plus or minus 0.5, posY to posY + 2.0). The color is hardcoded near-transparent black: the module exposes no settings at all, no color picker, no box mode, no tracer option. It is wire-silent: the handler only reads the client-side entity mirror and issues GL11 calls, so no packet leaves the client and no server-side check can observe it.

Render path

The module is one Consumer<Render3DEvent> registered with the client event bus. Each fired event loops the loaded entity list, skips the local player and anything that is not an EntityPlayer, and renders the survivors with a fixed translucent color. drawEsp forwards to RenderUtils.box with the color object, and the surrounding enableGL2D and disableGL2D helpers configure GL11 blending (source 770, destination 771), line smoothing and depth state for the frame. There are no settings: the constructor registers only the keybind 0 and the render category.

Data source

The rendered state is the client's mirror of server broadcasts. S0C spawn-player packets create the EntityPlayer entries with position and rotation, and the entity-move and teleport packets (S14 family, S18) keep those entries current; the module draws each frame from that live state, so a player's current position is outlined regardless of occlusion. S0F spawn-mob packets populate non-player entries that the instanceof EntityPlayer filter discards, so the renderer is players-only by construction. The 1x2 box spans the standing entity bounds, posX plus or minus 0.5 to posY + 2.0.

Wire behavior

The module produces no network traffic of its own and changes no server-visible state. It cannot be inferred from the outside because the GL11 calls never leave the client, and the entity list it reads is data every vanilla client also receives and renders. The honest conclusion is that no server-side anticheat mechanism can detect this module; the countering entries below therefore describe the checks that police the data stream it consumes and the aim behavior it typically enables, each with the boundary stated explicitly.

PacketEntityReplication is Grim's consumer for the spawn and entity-update broadcasts, maintaining the server-side mirror of entity state that the prediction engine reads. How it counteracts this module

AimbotConvergence tracks whether a player's ray converges on a fixed point across consecutive moves, with convergence scored when the squared distance to the lock point falls below 1e-8; a smooth aim that repeatedly returns to the same point across ticks is the signature. An ESP-assisted aimbot locks onto the outline's center, which is a fixed point the server's own geometry never corroborates, so the convergence signature builds. As with the other boundary checks, ESP alone produces no rotation stream, so the check fires only on the companion aim module.
