Analysis

Overview

Sigma's PingSpoof is a keepalive buffer-and-flush cycle with no thread of its own. The outgoing-packet handler intercepts every C00PacketKeepAlive the vanilla client emits while the player is alive, cancels it and parks the original object in a CopyOnWriteArrayList. A timer gated on the WAIT setting (default 15 seconds, range 5-30) then flushes a randomly sized prefix of the buffer through sendPacketNoEvent, which bypasses the event bus so a flushed echo is never re-intercepted, and caps every flush with a fabricated C00PacketKeepAlive carrying the fixed key 10000.

Buffer and flush cycle

The park branch fires for every outgoing C00 while the player is alive: the packet object itself is appended to packetList and the event is cancelled, so the vanilla echo never reaches the wire at its natural time. The flush branch is a true period, not a latch: timer.delay(1000 * WAIT) with timer.reset() at the end of the branch, so the cycle repeats every WAIT seconds. The flush sends a random 0-10 of the parked echoes (MathUtils.getIncremental rounds a uniform 0-10 value to a whole number) before the fixed fake keepalive, and sendPacketNoEvent routes each replay straight to the network manager, keeping it out of the module's own event stream. CopyOnWriteArrayList makes the remove-during-iteration safe.

Server-side ping accounting

The fork's vanilla NetHandlerPlayServer.processKeepAlive (line 1044) only updates the player's ping when the echoed key equals the single stored key field_147378_h, folding the elapsed time as ping = (ping * 3 + elapsed) / 4; any other key is silently dropped with no kick. The server issues a fresh S00PacketKeepAlive every 40 network ticks (update() line 150, key = the send-time millis) and overwrites the stored key, so at the default 15-second WAIT only echoes still holding the current key can update the ping when the flush lands. The older parked echoes and the fabricated key-10000 packet are inert on a stock server; the module's real effect is inflating the measured round trip for the surviving echo, and the fake packet exists purely as noise for servers that count keepalives instead of matching keys.

Wire fingerprint

Every flush concentrates up to 11 C00 packets in a single tick after a 5-30 second silence, the opposite of the vanilla one-echo-per-2-seconds pattern. The fabricated key 10000 repeats on every flush, so an id-tracking server sees a duplicate unexpected reply at a fixed cadence, and a ledger server sees replies arriving seconds after their requests. The module never touches the C0F transaction stream, so the transaction round-trip ledger stays fast while the keepalive ledger is inflated; that divergence between the two ping estimates is the tell the dedicated ping checks are built around.

What this file does

The module is the whole mechanism: the EventPacket handler parks every outgoing C00 while the player is alive and cancels it, the timer period decides when the flush runs, and the flush drains a random prefix of the buffer through sendPacketNoEvent before injecting C00PacketKeepAlive(10000). The WAIT setting is the only configuration, converted to milliseconds inside timer.delay. The fake packet is constructed with the hardcoded key 10000, which never matches a server-issued key (the server's keys are send-time millis values), so on vanilla it is dropped at the key comparison while on NCP it registers as an unexpected reply.

The CopyOnWriteArrayList is the carrier for the parked echoes: each entry is the original C00 object, so its key survives unchanged and a server that still tracks that request accepts the late reply and measures the inflated round trip. The random 0-10 flush count keeps the pattern from being perfectly periodic, and timer.reset() at the end of the branch makes the gate a true repeating period rather than the one-shot latch seen in the sibling AutoSoup.

How it counteracts this module

PingSpoofB compares the two ping estimates Frequency maintains. keepAlivePing is the S00-to-C00 round trip: ConnectionManager.onKeepAlive looks up the echoed identification in the map of outstanding keepalive send times and stores now minus that timestamp. transactionPing is the C0F round trip measured the same way. The check runs on every C03 movement packet and fails when keepAlivePing exceeds transactionPing by more than 50ms, with the standard exemptions (lag, teleport, TPS, chunk) and a 10-tick post-join grace absent.

Sigma's PingSpoof inflates exactly the number this check keys on. The parked echoes keep their original keys, so the id lookup still succeeds when a replay lands, and the measured keepAlivePing becomes the 5-30 second delay instead of tens of milliseconds. transactionPing is untouched because the module never delays C0F transactions, which stay at their normal sub-100ms round trip. The divergence is seconds, orders of magnitude beyond the 50ms threshold, so the check fails on the first movement packet after a flush and on every flush thereafter. This is the direct counter to the module's core mechanism.

How it counteracts this module

NoCheatPlus replaces vanilla's accept-any-echo keepalive model with an id-tracked ledger. The ProtocolLib KeepAliveAdapter records every outgoing S00 id into NetData.keepAliveRequests with a 30-second age limit and a 40-entry cap, and recordKeepAlivePacket matches each incoming C00 against it. A reply that matches a still-pending request sets keepAliveExpectedResponse and the check bails, which means the module's delayed echoes pass as long as their ids are still live in the ledger. A reply with no pending request is counted into keepAliveFreq, a 1-second-bucket ActionFrequency, and the newest bucket scoring above 1f (2f without the duplicate-id path) triggers a violation with cancel actions from vl>10.

The fabricated key-10000 packet is the module's self-inflicted wound on this ledger: id 10000 never matches a server-issued request, so every flush counts an unexpected reply, and because the same key repeats on every flush the duplicate-id flag tightens the newest-bucket limit to 1f. Any flush that delivers a second counted reply in the same second trips the violation: an echo whose request aged past 30 seconds at the maximum WAIT setting, a request cleared by a world change or rejoin, or an overflow past the 40-entry cap. The default 15-second single-echo pattern sits inside the ledger's tolerance, so this check scores the burst and maximum-delay configurations rather than the benign default.

The honest conclusion is that no Grim check in the corpus scores C00 ping spoofing: the timer family guards the transaction side of the protocol, which is exactly the side this module leaves alone. The entry documents that boundary so the countering picture is complete: the module's surface is the keepalive stream, and the checks that live there are the Frequency pair and the NCP ledger.
