Rise 5.99 AutoBuild — Full Source Analysis

AutoBuild queues fixed decorative block patterns (Penis, Surround, Singular) through C08PacketPlayerBlockPlacement, firing them straight into the NetHandler's no-event queue so they skip the module event bus entirely. Normal mode builds at the player's feet on a configurable tick interval; Teleport mode waits for the use-item key, ray-traces to a looked-at block, computes a path with MainPathFinder on a separate thread, streams C04PacketPlayerPosition hops along it, builds at the target, then walks the path back in reverse. A blanket onPacketSend handler cancels every C08 that reaches the event bus, so the only placements the server ever sees are the module's own direct-queue packets.

Analysis

Overview

AutoBuild queues fixed decorative block patterns (Penis, Surround, Singular) through C08PacketPlayerBlockPlacement, firing them straight into the NetHandler's no-event queue so they skip the module event bus entirely. Normal mode builds at the player's feet on a configurable tick interval; Teleport mode waits for the use-item key, ray-traces to a looked-at block, computes a path with MainPathFinder on a separate thread, streams C04PacketPlayerPosition hops along it, builds at the target, then walks the path back in reverse. A blanket onPacketSend handler cancels every C08 that reaches the event bus, so the only placements the server ever sees are the module's own direct-queue packets.

Architecture

The module also owns an onPacketSend handler that cancels every C08PacketPlayerBlockPlacement arriving on the event bus. Because build() uses PacketUtil.sendPacketWithoutEvent, which calls addToSendQueueWithoutEvent and bypasses the bus, its own placements are untouched; the cancel only suppresses placements from vanilla right-clicks or other modules while AutoBuild is active.

Teleport mode

Teleport mode bypasses the tick gate: the outer condition fires whenever the mode is not Normal or Auto Disable is on, so the mode is driven purely by the key and the 100ms timer rather than the tick counter.

Placement patterns and the direct queue

All C08s go through sendPacketWithoutEvent, so they bypass onPacketSend's own cancel and reach the server as an unswung, same-tick burst of placements: one invocation emits between one and five C08s with no C0A animations in between.

How it counteracts this module

Hawk's BlockInteractSpeed records the server tick of every block interaction per player and punishes any second interaction landing in the same tick (pp.getCurrentTick() == lastPlaceTick), rewarding otherwise. AutoBuild's build() emits between one and five C08PacketPlayerBlockPlacement packets in a single invocation, all processed in the same tick, so every multi-block pattern trips the same-tick comparison immediately. Even the single-block Singular mode fails when Tick=1 because consecutive invocations arrive one tick apart - the minimum human cadence for block placement is several ticks per block.
