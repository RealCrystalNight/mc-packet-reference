Overview

AutoPot is a health-gated splash healer that routes instant healing potions from the inventory into the hotbar and throws them through a rotation-gated use-item ceremony. The handler runs on the PRE stage of MotionEvent and bails while the player is flying, in creative mode, while any container window is open, or while Aura holds a target, so a throw never competes with combat rotations. findPotion scans the hotbar (slots 36-45) first and then the inventory (9-36) for splash potions carrying instant health, regeneration when the effect is not active, or move speed when the buff is missing; the heal scan only runs while health is at or below the Health threshold (default 15). The hotbar path swaps to the potion with C09, arms a throw rotation with a random 80-90 pitch via RotationUtils, waits until serverRotation.pitch reaches 80, then sends the C08 use-item packet and a C09 restore in the same tick. The inventory path refills the hotbar with a simulated open-inventory ceremony: C16 OPEN_INVENTORY_ACHIEVEMENT, a window-0 shift-click C0E, and C0D close.

Gate chain and slot finder

onMotion rejects the whole routine while mc.thePlayer.capabilities has allowFlying and isFlying both set, while playerController.isInCreativeMode, while msTimer.hasTimePassed(delayValue) is false (Delay 500-1000, default 500, a real period because the timer is reset after every action), while the open container's windowId differs from 0, and while Aura.target is non-null. findPotion(36, 45) walks the hotbar container range and findPotion(9, 36) the main inventory, returning the first splash potion (ItemPotion.isSplash) whose effects match the priority list: instant heal when health <= Health, regeneration when the player is not already affected, then move speed when the buff is absent. The scan returns the container index or -1, and the hotbar index for the C09 is the container index minus 36.

Rotation-gated throw ceremony

With a hotbar potion and no GuiInventory open, the PRE stage records potion = slot - 36 and queues C09(potion). If the current pitch is at or below 80 degrees, RotationUtils.setTargetRotation is armed with the current yaw and a pitch drawn uniformly from 80 to 90 (RandomUtils.nextFloat); the actual C08PacketPlayerBlockPlacement(itemStack) fires only once RotationUtils.serverRotation.pitch has reached 80. serverRotation is refreshed from the last rotating C03/C06 the client actually sent (RotationUtils line 411), so the throw waits until the look change is on the wire rather than firing from the local aim. The single-argument C08 constructor serializes BlockPos.ORIGIN with face 255, the protocol's use-item form that routes to ItemPotion.onItemRightClick. Immediately after, C09(mc.thePlayer.inventory.currentItem) restores the held slot, potion resets to -1 and msTimer.reset() starts the cooldown. The Jump and Port modes modify the throw: onGround gates thePlayer.jump() or moveEntity(0.0, 0.42, 0.0) so the splash lands under a rising player instead of at the feet.

Simulated inventory refill

When a potion sits in the inventory (9-36) and the hotbar has space, the module refills it: with OpenInv on it returns unless a real GuiInventory is open, while with SimulateInventory on it fabricates the window. The fabrication sends C16PacketClientStatus(OPEN_INVENTORY_ACHIEVEMENT), performs mc.playerController.windowClick(0, slot, 0, 1), the C0E mode-1 shift-click, and closes with C0DPacketCloseWindow. The client never renders a GUI, so the window exists only in the server's container ledger. Whether the fork's windowClick also syncs the held slot with a C09 cannot be verified here: the LiquidSense Dev snapshot ships no net/minecraft tree, so the vanilla sync contract is the only claim.

How it counteracts this module

Arc v2's HELD_ITEM_SLOT and BLOCK_PLACE handlers are both gated on Material.MUSHROOM_SOUP, so the potion C09 and the face-255 C08 bypass the AutoHeal inventory feed entirely; the InventoryListener stamps consumeTime for POTION right-clicks, but FastConsume compares it on PlayerItemConsumeEvent, which splash throws never produce. The potion throw is invisible to Arc v2's inventory layer by construction, and its movement layer is where any real pressure would have to come from.
