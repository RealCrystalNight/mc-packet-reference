Rise 5.99 ClientSpoofer — Full Source Analysis

Rise 5.99's ClientSpoofer rewrites the client-brand and plugin-channel handshake so servers fingerprint a different client: onPacketSend intercepts every C17PacketCustomPayload and replaces the channel and payload according to the selected mode, and onEnable prints a notification telling the player to rejoin because the brand is only exchanged at login. The six modes are Forge (payload string 'FML'), Lunar (channel REGISTER, raw bytes 'Lunar-Client'), LabyMod ('LMC'), PvP Lounge ('PLC18'), CheatBreaker ('CB') and Geyser ('Geyser'). The module touches no other packet: the keepalive stream, transactions and the rest of the connection stay untouched.

Overview

Rise 5.99's ClientSpoofer rewrites the client-brand and plugin-channel handshake so servers fingerprint a different client: onPacketSend intercepts every C17PacketCustomPayload and replaces the channel and payload according to the selected mode, and onEnable prints a notification telling the player to rejoin because the brand is only exchanged at login. The six modes are Forge (payload string 'FML'), Lunar (channel REGISTER, raw bytes 'Lunar-Client'), LabyMod ('LMC'), PvP Lounge ('PLC18'), CheatBreaker ('CB') and Geyser ('Geyser'). The module touches no other packet: the keepalive stream, transactions and the rest of the connection stay untouched.

Dispatch and rewrite

onPacketSend tests for C17PacketCustomPayload and switches on the Mode setting. Every mode replaces the payload data, and the Lunar mode additionally replaces the channel with REGISTER while carrying the raw brand bytes as the payload; the other modes keep the original channel and only swap the data. The packet is mutated in place before it is queued, so the server sees a C17 that looks exactly like the spoofed client's announcement.

Payload encoding

createPacketBuffer distinguishes the two wire formats: with the string flag it writes a VarInt length prefix followed by the UTF-8 text (the FML, LMC, PLC18 and CB forms), and without it wraps the raw bytes with no length prefix (Lunar-Client and Geyser). The distinction mirrors how each real client announces itself: Forge registers the FML handshake with a length-prefixed string, while the Lunar and Geyser brands ride as raw channel names and payloads.

The rejoin contract and the untouched stream

The brand is sent once per connection during the login phase, as the MC|Brand payload and the FML handshake, so rewriting payloads mid-session never reaches the server; that is why the module demands a rejoin after enabling. C00 keepalives pass through unmodified, and the module never drops or reorders any packet, so the connection's timing and ordering stay vanilla. The practical consequence is that the spoof is only as good as the login-time payloads, and any server that recorded the pre-enable brand keeps the old fingerprint until the player rejoins.

How it counteracts this module

Grim's ClientBrand is the C17-side consumer of the brand claim. It listens for the MC|Brand plugin message (minecraft:brand on 1.13+), strips the length byte and color codes, records the brand string on the player, strips the Velocity suffix, and emits a staff alert in the configured client-brand format unless the brand is in the ignored-client list; a payload longer than 64 bytes or empty is recorded as 'sent N bytes as brand'.

Against the spoofer, the Forge mode makes the server record the brand 'FML' and alert 'joined using FML', and rewriting every C17 can produce the over-length path when a mode's data is written over a longer original payload. The honest limit is that the check validates the claim's shape, not its truth: it has no behavioral fingerprint to compare against, so a well-formed fake brand is recorded and alerted, and detection of the spoof itself falls to consistency checks outside this class.

How it counteracts this module

The C00 side is where the spoofer is provably invisible. NoCheatPlus's keepalive ledger records every outgoing S00 id, matches each incoming C00 echo against the pending list, and flags only unexpected or duplicate replies and bursts of two or more replies in one second.

The spoofer never touches keepalives, so the ledger sees a textbook 1:1 echo stream and stays silent by design; the entry is included as the honest boundary that delimits what a payload rewriter does not change. Any serverside detection of the brand spoof must therefore come from the C17 consumers (ClientBrand, BrandChannelData), never from connection-timing checks.
