Analysis

Overview

Spicy's Block Fly is a safe-walk block placer. It hijacks the EventSneaking hook inside Entity.moveEntity to force the sneak edge-clamp while the player is grounded, cancels incoming S2F set-slot packets so server inventory corrections never apply, rewrites every outbound C03 look to the last placement rotation, and, whenever the cell directly below the player is air with solid ground two cells down, picks a block from the hotbar, switches to it locally and places it at the feet through the vanilla player controller. The placement look is computed by an in-module aim routine that pins pitch toward 90 degrees, and the look latch makes the server see the player looking at each placement.

The sneak clamp

EventSneaking fires from Entity.moveEntity with the vanilla gate flag = onGround && isSneaking() && instanceof EntityPlayer, and the fork lets listeners override both the sneaking state and the offset used by the edge-clamp loop. The module forces sneaking true with offset -1 whenever the moving entity is grounded and an EntityPlayer, so the clamp loop tests the bounding box shifted one block down and the player cannot walk off an edge; the clamp is released in air, where the module sets sneaking false, and the whole handler skips while the client's killaura holds a target.

Under-foot placement

The EventMotion post handler checks the block state one cell below the player. When that cell is air and the cell two below is solid, it scans hotbar slots 36-44 for an ItemBlock whose localized name does not contain chest or table, switches to it through inventory.setCurrentItem, and calls mc.playerController.onPlayerRightClick at the under-below position with facing UP and a hit vector from RotationUtils.getVectorForRotation, which produces a real C08 placement and a swing. Side placements probe a position offset along motionZ and walk the facing search through findFacingAndBlockPosForBlock, which scans the block neighbors and their neighbors for a solid anchor. The event yaw and pitch are then set from getRotationsHypixel, an atan2 aim at the block center with pitch boosted by 30 degrees and clamped to 90, and the same values latch into lastYaw and lastPitch.

Wire shape

The EventSendPacket pre handler rewrites the yaw and pitch of every outbound C03PacketPlayer to lastYaw and lastPitch, so the server-side look stream reports the placement look while the module is placing. The S2F cancel drops every incoming set-slot packet, keeping the locally switched hotbar slot free of server corrections. The placement path emits at most one C08 per tick because every branch returns after its placement, and the C09 held-item change rides the vanilla syncCurrentPlayItem call when the tracked slot diverges. Motion itself is ordinary: the edge clamp is a client-side collision change and the C03 stream carries normal walk speeds.

What this file does

The module is four handlers. EventSneaking pre forces the grounded sneak clamp with offset -1, EventPacket pre cancels S2F set-slot packets, EventSendPacket pre rewrites every C03 yaw and pitch to the latched placement look, and EventMotion post runs the placement machine: the air-below check, the hotbar ItemBlock scan with the chest and table name filter, the local slot switch, the playerController.onPlayerRightClick call that emits the real C08, and the getRotationsHypixel aim latch.

The placement logic is strictly gated: the EventUpdate pre branch only runs the motion probes, and the actual placement fires only when the below cell is air and the two-below cell is solid (or a side anchor is found), so the module idles on flat ground and only places while crossing a gap or edge. Every branch returns after the first placement, capping the rate at one C08 per tick.

How it counteracts this module

NoCheatPlus's blockplace FastPlace is invoked from the Bukkit BlockPlaceEvent path, and the module's placements are genuine: playerController.onPlayerRightClick sends a real C08 with a block position and facing, the server places the block, and the event fires. The check scores into BlockPlaceData.fastPlaceBuckets, an ActionFrequency(2, 1000) two-second window, plus a config-driven short-term tick counter, with the violation being the larger of the full-window excess and the short-term excess.

While the module crosses gaps it can place once per tick, up to 20 placements per second, which is roughly five times the vanilla 4-per-second rate, so a sustained crossing scores around five times the vanilla baseline and trips both the window and the short-term path. The honest boundary is the gate: on flat ground with solid blocks below, the module idles and the stream stops, so the check only scores the crossing phases.

How it counteracts this module

NoCheatPlus's blockplace Reach measures the eye-to-block distance against the survival distance default of 5.2 blocks (5.6 creative) in this tree, cancelling placements beyond the limit and reducing repeat hits inside the reachMod band. The module places at the cell two below the feet, so the eye at roughly posY plus 1.62 to a block center at posY minus 1.5 sits around 3.6 blocks away, comfortably inside the survival bound.

The entry is a boundary in the same family as Direction: the module never extends reach because it only ever targets the cell under the player, and the under-foot geometry keeps every placement legal. A variant that reached several cells out for tower building would be the shape this check exists to cancel, and the module's own geometry avoids it by design.

How it counteracts this module

Hawk's BlockInteractSpeed punishes with vl 1 and cancel whenever a world interaction arrives on the same server tick as the previous one, keeping a per-player lastPlaceTick map and rewarding every interaction that lands on a later tick. The module caps at one C08 per tick because every placement branch returns immediately, so each interaction lands on a fresh tick and the check rewards the stream instead of punishing it.

This is the same-tick boundary that separates a per-tick placement module from a burst placement module: a stream of one placement per tick is exactly what BlockInteractSpeed does not flag, while two interactions in one tick (the shape a double-placement or a placement plus a use produces) trips it instantly. The honest statement is that this check is structurally blind to the module's cadence, and the real pressure comes from the FastPlace window ledger.
