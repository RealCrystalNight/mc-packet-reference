Overview

LiquidSense's Aura is a full-featured kill aura driven by the client event bus. Target selection runs from the pre-motion update, scoring every loaded entity by a configurable priority (Health, Distance, Direction, LivingTime) under FOV, hurt-time, range and team filters, then committing the first candidate whose rotations can be computed. The attack clock lives on Render3D, so clicks queue at the frame rate and are drained on the next update event, with the delay randomized between MinCPS and MaxCPS each cycle. Attacks leave as C02PacketUseEntity ATTACK behind an optional raycast hitable gate, and a six-mode autoblock subsystem (Vanilla, Pos, Both, Click, AAC, Interact) surrounds them with C08 block placements, keybind holds and C02 interacts. Silent rotations are the default, computed against the server rotation in RotationUtils and clamped by a randomized turn speed, with velocity prediction on the target bounding box and three rotation backends (Vanilla, BackTrack, Other).

Event-driven architecture

The module is split across five event handlers plus one packet interceptor. onMotion POST refreshes the hitable flag and starts blocking when the delayed-block switch is on, while the PRE phase calls update() which re-selects the target and binds currentTarget. onRender3D is the attack clock: when attackTimer has passed attackDelay and the target's hurtTime is at or below the HurtTime setting it increments the clicks counter and resets the timer with a fresh randomClickDelay between MinCPS and MaxCPS. onUpdate drains those clicks through runAttack() in a while loop, so the actual packet emission is decoupled from the render clock that schedules it. onStrafe rewrites strafe and forward inputs against the target rotation for the OldStrict, NewStrict and Silent strafe modes, and onEntityMove re-runs updateHitable whenever the tracked target changes its bounding box. onPacket intercepts C07PacketPlayerDigging only for the AAC autoblock mode, cancelling and re-queuing alternating release packets. A cancelRun guard (spectator, dead, Blink or FreeCam active) plus the NoInvAttack window freeze the whole pipeline, and the AAC mode also gates on the inventory screen state.

Target selection and rotation backends

updateTarget scans mc.theWorld.loadedEntityList and applies isEnemy, which composes the global EntityUtils filters with LiquidSense's own AntiBot, NoHurt, Teams and NoFriends checks, then keeps entities whose box distance is within maxRange (the larger of Range and BlockRange), whose rotation difference is within FOV, and whose hurtTime is at or below the threshold. The survivors are sorted by the Priority setting and each candidate is passed to updateRotations, which must succeed for the entity to become the target; when every candidate fails, prevTargetEntities is cleared and the scan retries. The Vanilla backend calls RotationUtils.searchCenter on the entity bounding box, optionally offset by the entity velocity times a random factor in [MinPredictSize, MaxPredictSize] when Predict is on, with random-center and outborder sampling; BackTrack uses RotationUtils.OtherRotation the same way; Other uses OtherRotationUtils.searchCenter and latches a Rotationhit boolean when the limited rotation lands within 5 degrees. Every backend funnels through limitAngleChange against serverRotation with a random per-tick cap between MinTurnSpeed and MaxTurnSpeed, and the result is applied either silently through setTargetRotation (with a 15ms lag when the AAC switch is on) or visibly by writing the angles into the player.

Attack execution and autoblock modes

runAttack checks the hitable flag, which is set by a RaycastUtils.raycastEntity sweep at reach = min(maxRange, box distance) + 1.4 when RayCast is on or by RotationUtils.isFaced otherwise, and randomly skips the hit when FailRate rolls, emitting only a swing when FakeSwing is enabled. A real hit sends swingItem plus C02PacketUseEntity ATTACK; the KeepSprint path plays the critical and enchantment particles locally, while the vanilla path calls attackTargetEntityWithCurrentItem. Multi mode iterates every enemy within range and attacks them in one pass, stopping at LimitedMultiTargets when set. The autoblock modes differ only in how the block state is asserted: Vanilla sends C08 with the held item, Pos sends C08 against BlockPos(-1,-1,-1) with facing 255, Both sends two C08 packets, Click holds the use-item key binding, and AAC toggles the binding and relies on the C07 cancellation flip. InteractAutoBlock additionally sends a C02 INTERACT with the entity position vector before blocking. The AAC mode also closes and re-opens the inventory around each attack (C0D close, C16 open) to mask the cooldown reset, and FakeSharp forces the enchantment critical effect even without a sharpness enchant.

What this file does

RotationUtils implements everything the Aura needs to aim: searchCenter picks a point inside the target bounding box (with outborder and random-center sampling), OtherRotation computes the alternative backtracking angle, limitAngleChange clamps a rotation to a maximum per-tick delta against the stored serverRotation, and setTargetRotation feeds the silent-rotation pipeline that rewrites the player's yaw and pitch in outgoing movement packets without moving the visual camera. getRotationDifference scores how far an entity sits from the current look direction and powers both the FOV filter and the Direction priority sort. isFaced is the fallback hitable test used when the RayCast switch is off. The class is shared with the client's other combat modules, but the Aura is the heaviest consumer: every attack cycle calls searchCenter or OtherRotation, limits the result, and applies it, which is exactly the rotation stream an aim-pattern check would analyze.

How it counteracts this module

NCP's fight.Reach validates every attack against a server-side distance limit. check() computes the player-to-entity distance lenpRel, picks distanceLimit from reachSurvivalDistance (with a separate 6.5 limit in creative), and flags when lenpRel exceeds the limit, optionally tightened by reachPrecision which compares the actual separation instead of the relaxed box margin. Repeated violations accumulate reachVL and drive a dynamic reduction: reachReduceDistance shrinks the effective limit step by step, and when the module cancels, reachPenalty applies an attack penalty that further suppresses the player's combat ability. The comparison runs on the server's own positions, so nothing the client claims about range or facing changes the measured distance.
