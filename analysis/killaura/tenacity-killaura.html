Overview

Tenacity 6.0's KillAura is a reach-extending melee aura with randomized CPS, optional auto-block and an optional rotation snap. On every MotionEvent pre-phase it rebuilds a target list of living entities within the Reach setting (default 4, up to 8) that pass canEntityBeSeen, are not invisible and are not friends, sorts it by distance, snaps the client's yaw to the closest target (pitch is left untouched in every rotation mode), and fires swingItem() plus a C02PacketUseEntity ATTACK whenever the per-attack TimerUtil has elapsed 1000 / cps milliseconds. CPS is a configurable 10-100 range (default 10) drawn per attack, optionally multiplied by a random 1-2x interval under 'Extra Randomization'. Auto-block supports Vanilla and Hurt Time modes that send the C08 use-item / C07 release pair around the attacks, and onDisable releases the sword if a block is still active. The 'Fake' auto-block mode and the HvH rotation mode are registered but have no implementing code path.

Architecture

KillAuraModule extends Module and wires all combat logic to a single IEventListener<MotionEvent> (onMotionEvent); a second UpdateEvent listener only updates the HUD suffix with the CPS. Settings are Minimum CPS / Maximum CPS (both default 10, range 1-100), Reach (default 4, range 3-8), Auto Block, Rotate, Enchant/Critical particle toggles, Extra Randomization, Auto Block Mode (Vanilla / Hurt Time / Fake) and Rotation Mode (Vanilla / HvH Mode). The constructor and every tick re-clamp minimumCPS against maximumCPS so the two settings cannot invert. Each motion event calls sortAndAddTargets: the loaded entity list is filtered to EntityLivingBase instances within reach.getCurrentValue() that are not the player, pass mc.thePlayer.canEntityBeSeen(entity) (a world ray trace - no wall hits), are not invisible, and are not on the friend list via FriendCommand.isFriend on the display name, then sorted by distance so the closest legal target is attacked. Packets go through mc.getNetHandler().addToSendQueue, the normal client queue, so they are sent with the tick's batch.

Rotation and auto-block

Rotation is applied only on the pre phase. Vanilla mode calls RotationUtil.getRotationFromTarget and writes only event.setYaw(rotations[0]) - the pitch component is computed by the helper but deliberately not applied, so vertical aim stays at the player's real pitch. The yaw is also quantized in a peculiar way: fixedYaw = rotations[0] - rotations[1] % sensitivityMultiplier is computed but never used, and the plain rotations[0] is what reaches the event, so the snap is a full instant yaw. HvH Mode computes fixedYaw = rotations[1] - rotations[0] % sensitivityMultiplier (a swapped expression) and clamps it with MathUtil.clamp(fixedYaw, 0, 10), pinning the yaw between 0 and 10 degrees - a near-constant bearing that makes the player appear to look in roughly one direction while still attacking, a deliberate anti-aim/HvH gimmick. Auto-block runs independently: Vanilla mode places C08PacketPlayerBlockPlacement(BlockPos(-1,-1,-1), 255, heldItem, 0,0,0) once when !wasBlocked and releases with C07 RELEASE_USE_ITEM when the target disappears or the module disables; Hurt Time mode places the block when mc.thePlayer.hurtTime == 9 (the tick after being hit) and releases when hurtTime == 0, with both releases skipped while isSwingInProgress. The Fake mode has no case in either switch, so it does nothing.

CPS timing and attack dispatch

Attacks are timed by a TimerUtil with hasTimeElapsed(1000 / cps, true), which resets the clock on every fire. With randomization off, cps is Math.round(MathUtil.getRandomInRange(min, max)) drawn per attack, so a 10-10 setting yields a perfectly regular 10 Hz; with Extra Randomization on, the interval becomes 1000 / cps * MathUtil.getRandomInRange(1, 2), so the effective rate alternates between the configured CPS and half of it. At the 100 CPS maximum the interval is 10ms, far shorter than a tick, so the actual rate is capped by the motion-event cadence - at most one attack per tick - but every eligible tick can fire. Each fire calls swingItem() then addToSendQueue(new C02PacketUseEntity(currentTarget, ATTACK)), and the optional particle toggles call mc.thePlayer.onEnchantmentCritical / onCriticalHit directly, which only spawns the client-side particle burst - no server packet - so they are purely cosmetic. The timer clock is shared with the rest of the module and onDisable resets Timer.timerSpeed to 1f, hinting the module normally drives game-speed via the global Timer elsewhere in the client.

How it counteracts this module

Arc v2's composite KillAura check runs from FightListener.onFight on the damage event at HIGHEST priority and applies five sub-checks with config defaults max-direction-angle 1.2 radians, max-swing-time 80ms, max-reach 4.2, max-attacks 16/s and max-attack-packets 20/s. Direction measures the angle between the player's look vector and the attacked entity, Multi compares the angles to two consecutive targets, NoSwing demands an arm swing within 80ms of the attack, Reach measures the distance to the entity position minus its velocity, and Speed counts attacks and attack packets per second with a per-second reset.\n\nAgainst Tenacity the reach sub-check bites as soon as the Reach setting exceeds 4.2 (the module allows up to 8), so the default 4 passes but any extension flags every hit with the measured distance. The speed sub-checks counter the CPS range: more than 16 attacks in a second (CPS 17+) trips max-attacks, and more than 20 attack packets in a second (CPS 21+) trips max-attack-packets, so the default 10 CPS passes but the upper half of the 1-100 range is exposed. Direction passes because the yaw is snapped onto the target, and NoSwing passes because swingItem() precedes every C02 - the same two components that let Memeware's blockhit aura pass those branches.
