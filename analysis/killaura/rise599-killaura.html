Analysis

Overview

Rise 5.99's Aura is a full-featured KillAura with Single, Switch and Multi attack modes, nine rotation modes (Custom, Custom Simple, Custom Advanced, Smooth, Sin Wave, Up, Down, Derp, None), eight block modes (None, Fake, Vanilla, Bypass, NCP, AAC, Interact, Hypixel), three target-sorting strategies (Distance, Health, Hurttime), and a large set of bypass settings: per-mode random rotations, GCD-fixed rotation deltas via RotationUtil, silent rotations with server yaw/pitch written into PreMotion, a movement-fix that rewrites EntityPlayer.movementYaw, target-position prediction, a client-side ray trace gate, a CPS timer with randomized delays, and an Extended Range mode that streams C04 position packets to walk the server-side position toward the target before attacking.

Architecture

The module is driven by four event handlers. onUpdate runs once per tick: it recomputes the target position (with optional ping-scaled prediction using the target's velocity doubled), picks an attack delay from the CPS settings via a TimeUtil timer, and calls the attack logic. onPreMotion applies the server rotations: with silentRotations enabled it overwrites the outgoing motion event's yaw and pitch with serverYaw/serverPitch and mirrors them into renderYawOffset and rotationYawHead, so the client view stays untouched while the server sees the aura aiming. onPostMotion fires the block-mode packets (C08 block placement, interact packets, C07 release for the Hypixel mode). onRender3DEvent calls update() to refresh the target and rotations each frame and draws the target ESP ring. A WorldChangedEvent handler disables the module when Disable On World Change is set.

Target selection and rotation math

getTargets() streams mc.theWorld.loadedEntityList, filters EntityLivingBase instances by the players/nonPlayers/invisibles/teams/dead toggles plus an AntiBot blacklist and a friend list, then applies a distance filter using the constant girth 0.5657 subtracted from getDistanceToEntity against rotationRange, and sorts by the selected sorting mode. updateTarget() takes the first entry as the static target field. getRotations() computes yaw from atan2 over the x/z delta to the predicted target position and pitch from atan2 of the vertical delta, clamps the pitch delta to [-1.4, 0.1] to keep aim near head level, applies per-mode rotation shaping (Custom clamps the per-frame delta to a random step before dividing by fps, Smooth divides by a randomized fps factor, Sin Wave clamps to a sine envelope, Derp forces pitch to 89-90), adds random jitter when the Random setting is nonzero, then feeds the result through RotationUtil.getFixedRotation, which snaps the delta to the mouse-sensitivity GCD so the server sees yaw/pitch steps that look like real mouse movement instead of arbitrary floats.

Attack dispatch and extended range

Attacks fire when the CPS timer hasReached. In Single mode the module sends C02PacketUseEntity directly through PacketUtil when keepSprint is on, otherwise calls mc.playerController.attackEntity, and calls onCriticalHit when falling. Switch mode cycles targetIndex over the sorted list; Multi mode loops the whole list, so one tick can emit several C02s at different entities. Extended Range is the notable bypass: before attacking, a loop streams up to 100 C04PacketPlayerPosition packets that step the local x/z toward the target until the distance shrinks below range minus 0.5657, then attacks, then re-sends the buffered C04s in reverse to pull the position back. The attack path also gates on a client-side ray trace: PlayerUtil.isMouseOver casts a ray from the eyes along the server yaw/pitch and requires the target's expanded AABB to intersect it, which with the Raytrace setting on prevents attacks when the aim direction does not actually cross the target. Block modes send C08 block placement (with a fake BlockPos(-1,-1,-1) in block()), C07 release, and interactWithEntitySendPacket in various per-server sequences.

The entire KillAura lives in this file. onUpdate is the tick driver: it computes targetPosX/Y/Z with the ping-scaled prediction formula (delta = (pos - lastTickPos) * 2, applied ping/50 times), evaluates the CPS timer (cps is randomized between minCps and maxCps every time the timer fires, with MathUtil.RANDOM jitter), and gates the attack on the ray-cast check and the range check against range minus the 0.5657 girth constant. The attack itself is a switch over mode: Single sends one C02 (or attackEntity), Switch iterates a targetIndex over getTargets(), Multi attacks every entity in the list, and each can emit onCriticalHit when fallDistance is positive. The onPreMotion handler is where silent rotations happen: it sets the event yaw/pitch to serverYaw/serverPitch and copies them into rotationYawHead/renderYawOffset, while the actual mouse-visible view is left alone. When the strafe setting is on it also writes serverYaw into EntityPlayer.movementYaw so movement follows the server-facing direction. What this file does

Aura calls RotationUtil.getFixedRotation(rotations, lastRotations) at the end of getRotations() on every target update. The utility computes the mouse sensitivity f = sensitivity * 0.6 + 0.2, then gcd = f^3 * 1.2, and snaps each yaw/pitch delta to a multiple of that gcd: fixedDelta = delta - (delta % gcd). This is the standard anti-aimbot smoothing: real mouse movement only ever changes the view by whole gcd steps, so a KillAura that emits arbitrary float rotations is statistically impossible for a human and is a classic heuristic flag. By rounding the deltas the module makes its rotation stream look like genuine mouse input, which is precisely the layer an anticheat's rotation-snapping or aim-heuristic check has to undo. The same class carries the static serverYaw/serverPitch fields that Aura reads in onPreMotion, so the utility is both the rotation shaper and the carrier of the server-facing angles.

What this file does

Aura holds a single TimeUtil instance as its attack clock. The CPS loop in onUpdate does: if (timer.hasReached(this.cps)) { compute new random cps; timer.reset(); attack = true; }. The cps field is a millisecond delay derived from the Min CPS and Max CPS settings scaled by 20, so hasReached returns true once the randomized delay has elapsed and the module fires the attack block. Because the delay is re-randomized on every hit within the configured bounds, the outgoing C02 rate wobbles instead of being a fixed integer rate, which is the module's defense against simple per-second attack-count checks. TimeUtil itself is a thin wrapper over System.currentTimeMillis() with a lastMS field, hasReached(time) comparing elapsed against the argument, and reset() restarting the clock, so it is the entire timing primitive the aura's fire-rate shaping is built on.

How it counteracts this module

Hawk's FightHitbox replays the attack server-side instead of trusting the client. On an InteractEntityEvent it stores the interaction and waits for the next MoveEvent, because in 1.8 the attack packet is sent before the yaw update that describes it. On that move it builds a ray from the attacker's eye position (1.62 above the lag-compensated position, or the vehicle history position) along MathPlus.getDirection(yaw, pitch), rewinds the victim to its position at ping ms ago via the lag compensator, expands the victim AABB by the 0.005 epsilon, and intersects the ray with the box. If the ray misses entirely and checkBoxIntersection is on it punishes with 'Did not hit hitbox.'; if it hits, the intersection distance is compared to MAX_REACH (default 3.1, +1.9 in creative) and punished as reach. With checkOccluding it also BlockIterates from the eye along the direction and flags hits whose ray crosses a solid block first. This directly defeats Aura's rotation cheat surface: the Derp, Up and Down rotation modes point pitch at 89-90 or -80, and the rotationRange/range settings allow attacking out to 6-12 blocks, so the reconstructed server ray frequently misses the rewinded hitbox or exceeds 3.1. The client-side PlayerUtil.isMouseOver gate cannot help because Hawk recomputes the ray from the packet-observed yaw/pitch it stored, not from the client's render view. Only a rotation stream that genuinely crosses the victim's rewound box inside 3.1 survives.

How it counteracts this module

NCP's Angle check treats KillAura as a statistical anomaly in the attack stream. Every C02 appends an AttackLocation recording the player position, yaw, victim id and timestamps, and the window (maxTimeDiff 1000ms) is scored for four signals: averageMove (the squared distance moved between attacks, flagged when under 0.2 blocks), averageTime (time between attacks, flagged under 150ms), averageYaw (total yaw change, flagged above 50 degrees, normalized by TickTask lag), and switchspeed (victim id changes with yawDiff over 30 degrees). Aura's Multi mode is the cleanest hit: one tick attacks every entity in the list, so consecutive AttackLocations share the same position (avgmove near zero) and nearly zero elapsed time (avgtime near zero), and every id change is a switch with large yaw deltas. The high-CPS settings (up to 20) with the 1.9 Delay disabled push averageTime well under 150ms even in Single mode. The rotation modes that swing wide (Derp, Custom with maxRotation 180, Sin Wave) push averageYaw past the 50-degree ceiling over the window. Each triggered signal adds its own partial violation and the check cancels once the accumulated angleVL crosses the configured action thresholds. The module's own CPS randomization only spreads hit timing; it cannot lower the per-window averages below the fixed thresholds when attacking at 8-20 CPS while standing still.

How it counteracts this module

NCP's Reach check measures the attack from the server's tracked player location to the victim and compares against reachSurvivalDistance (default 3.0, or 6.0 creative, plus entity size modifiers). With reachPrecision it subtracts a centertoedge inset computed by getinset(): the victim's half-width projected along the attack direction, so edge-hits at 3.0 center distance pass. The y reference is refined to the victim's eye height when the attacker's eyes are above the box. Any violation over the limit adds to reachVL and executes the configured actions (cancel/notify), with TickTask lag gating. The dynamic reachMod adaption then tightens the effective limit: repeated hits near the boundary step reachMod down toward distanceMin, so a cheater who consistently edges 3.1-3.4 gets silently cancelled even below the nominal 3.0 + inset. Aura's range setting goes to 6 and rotationRange to 12, so any hit at those distances is an immediate large violation. The Extended Range mode tries to defeat this by streaming C04 packets to shorten the server-side distance before attacking, but NCP measures from the last accepted position which the C04 flood itself moves, and the module's reverse-replay after the attack means the next attack starts from the restored position; plus the attack only fires once the distance check in onUpdate passes, which the server-side position lags by a tick, so the measured reach still exceeds the limit. The precision inset also removes the girth trick: the module's 0.5657 subtraction in its own distance check is not mirrored on the server, and getinset only gives back half the victim width, not 0.5657.

How it counteracts this module

Arc's KillAura check bundles five independent detections run from CombatPacketListener on every attack. Direction computes the angle between the vector to the attacked entity and the player's look direction (player.getLocation().getDirection()) and flags when it exceeds max-direction-angle. Multi compares the angle to the previously attacked entity and flags when the two angles differ by more than maxAngle while the entities are within maxReach of each other, which catches attacking two players in different directions in one tick. NoSwing flags when the time since the last arm-swing exceeds maxSwingTime, which hits Aura's alwaysSwing-off path where a failed ray cast suppresses the swing (the module only sends C0APacketAnimation when alwaysSwing is enabled and the range check fails). Reach measures the distance to the entity minus its velocity (so knockback does not cause false flags) against maxReach. Speed counts total attacks per second against maxAttacks, and checkFrequency counts raw attack packets per second against maxAttackPackets. Aura's Multi mode with maxTargets up to 50 and 20 CPS is defeated by the Direction, Multi and Speed branches simultaneously: the look vector can only point at one target, the angle difference between targets in the list is large, and the attack count per second exceeds the configured max. Single mode at 20 CPS with the module's 1.9 Delay off is caught by the Speed counter, and the Derp rotation mode is caught by the Direction angle since the forced pitch of 89-90 leaves the look vector far from the victim's body.
