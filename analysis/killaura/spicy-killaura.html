Analysis

Overview

Spicy's Killaura is a compact 1.8 combat module driven from a single EventMotion pre handler, with EventRenderGUI reserved for an on-screen target HUD (health bar, HP readout and a rendered entity preview). Every tick it rebuilds the candidate list by streaming loadedEntityList through a distance filter and a Players/Animals/Mobs/Everything type filter, keeps the last target in Switch mode until switchTime expires, optionally prunes Hypixel 'watchdog bots' by tab-list responseTime, writes the aim into the outgoing movement packet (lock mode: exact yaw minus 2 degrees plus a triangular pitch oscillation; smooth mode: updateRotation easing capped at 180 degrees per tick), and attacks on a real millisecond timer whose period is 1000 / (APS + a fresh random float), so inter-hit intervals jitter. The attack packet itself is preceded by an arm swing (or a direct C0APacketAnimation when noSwing is set) and followed by client-side critical particles when the Criticals module is on and the player is grounded, and the Hypixel autoblock flavor re-blocks with a sendPacketNoEvent burst of C02 vector-interact, C02 INTERACT and a C08 block placement at BlockPos(-1, -1, -1) with facing 255.

Architecture

The EventMotion pre branch is the whole brain. It first toggles the module off when disableOnDeath and the player is dead, then clears the target and rebuilds the candidate list every tick: loadedEntityList entities that are EntityLivingBase are streamed, sorted by distance, filtered to the range setting (and to alive entities with health > 0 when dontHitDeadEntitys is on), then run through the targetsSetting type filter (players-only, animals-only, mobs-only or everything) via a targetsToRemove pass. When the list is empty the module resets the render rotations (RenderUtils.resetPlayerYaw/Pitch), stops blocking and returns. Otherwise target = targets.get(0), with Switch mode holding lastTarget while it is still in range and only re-picking to targets.get(0) once targetSwitchTimer.hasTimeElapsed(switchTime * 1000). The Hypixel antibot branch removes a targeted player whose netHandler responseTime is greater than 1 (their heuristic for a watchdog bot) and returns. A position-equality guard skips rotation entirely when the target occupies the player's own coordinates, which the source comment says avoids the 'invalid player movement' kick.

Rotation and attack timing

lock mode writes yaw = rotations[0] - 2 every tick and drives pitch with upAndDownPitch, a 20-tick triangular wave: each tick adds 2 + random, below 10 the pitch is rotations[1] - upAndDownPitch, between 10 and 20 it is rotations[1] + 10 - (upAndDownPitch - 10), and at 20 the accumulator resets, with a -90 clamp at the end. The effect is a sawtooth sweep of up to 20 degrees across the target's vertical angle, re-synced every 20 ticks -- a periodic, machine-regular pitch pattern. smooth mode runs customRots: sYaw = updateRotation(lastSmoothYaw, targetYaw, 180) and sPitch likewise, then re-converges with updateRotation(..., 360), clamping pitch to +-90; updateRotation wraps the delta with MathHelper.wrapAngleTo180_float and clamps it to the factor, so the per-tick yaw delta is bounded at 180 degrees but still reaches the target within one or two packets. The attack gate is a Timer, not a tick counter: timer.hasTimeElapsed((long)(1000 / (aps + new Random().nextFloat())), true), so the inter-hit interval at 10 APS averages ~95ms with +-1ms of random dither, and at 20 APS drops to ~48-50ms. hitOnHurtTime returns early while target.hurtTime > 2, and the Sprint module's state is re-asserted with setSprinting(true) both before and after the attack so the server never sees sprint drop mid-combat.

Autoblock packet flow and target HUD

startBlocking is called every tick a target exists and routes by mode: Vanilla uses playerController.sendUseItem (the real use-item path, so the server sees a genuine item-use begin), Hypixel uses blockHypixel, which sends three packets through sendPacketNoEvent (bypassing the event bus): a C02PacketUseEntity with Action.INTERACT and a Vec3 built from RotationUtils.getVectorForRotation(rotations[0], rotations[1]) -- the aim vector itself as the interact point -- a second C02 with Action.INTERACT, and a C08PacketPlayerBlockPlacement at BlockPos(-1, -1, -1) with facing 255 and the held item. The negative-coordinate placement is the classic Hypixel sword-block spoof: the server treats it as blocking without a real block face. Before each attack stopBlocking sends a C07PacketPlayerDigging RELEASE_USE_ITEM at BlockPos.ORIGIN and clears keyBindUseItem.pressed, and onDisable unwinds Hypixel blocking with onStoppedUsingItem inside a try/catch. The EventRenderGUI branch draws the target HUD: a health bar whose position lerps toward the target value at /5 per frame (healthBar += (target - healthBar) / 5), an HSB or rainbowgui-driven color, the target name, an HP line, and a live entity preview via GuiInventory.drawEntityOnScreen.

How it counteracts this module

Grim's Reach is the modern reference for this module (Grim targets current versions, but the geometry it enforces is the same server-side reach the 1.8-era checks approximate). It derives maxReach from the entity-interaction attribute (3.0 base) plus a hitbox margin and a movement allowance, builds the victim box from ReachInterpolationData so the target's possible positions between movement packets are all unioned, fires a ray from the eye position along up to four look candidates (current/last yaw and pitch combinations, since the client's hit-scan can precede the rotation packet), and flags when the minimum distance to the box exceeds maxReach; Reach.threshold defaults to 0.0005 and block-impossible-hits cancels impossible rays. CheckManager lines 112/246 show Reach owning the flag with Hitboxes invoked from inside its verdict.

Spicy's range ceiling of 6 with a default of 4 defeats the check outright: any hit past ~3.1 (attribute 3.0 + margin) fails minDistance > maxReach, and because the module writes its rotation into the same tick's movement packet, all four look candidates resolve to the target direction, so there is no angle confusion to hide behind -- the reach term alone fires. The interpolation union also removes the classic latency dodge of attacking the client-side position of a moving target, since the box covers every server-possible location. The only pass path is range 3.0-3.1, which the module's 0.1-step setting can reach, at the cost of giving up its whole advantage.
