Analysis

Overview

Hitboxes is a settings-only ghost module: an expand NumberSetting (0 to 5, default 1, step 0.05) and an invis BooleanSetting, with no event handlers of its own. The expansion is consumed by the fork's client-side hit detection, where the mouse-over ray trace grows every targeted entity's bounding box by the configured amount on all three axes before intersecting it. The Rise lineage implements this in EntityRenderer.getMouseOver as the collision border plus an expand term for non-invisible players, a hook the 5.99 snapshot cannot show directly because its net/minecraft tree is absent. The inflated box lets attacks land at larger angular offsets and at up to the full block-reach ray distance, and the server never learns the box size: the effect is only observable in the C02 attack geometry it produces.

Settings surface

The module body is exactly two settings. Expand ranges 0 to 5 in 0.05 steps with a default of 1, which at default already adds one block to each side of the target box in the mouse-over trace; Invis decides whether invisible entities receive the same inflation. There are no handlers: no events are consumed, no packets are touched, and the module is only registered in ProtectedLaunch's module list like every other Rise module. The entire behavior is the settings' side effect in the fork's ray trace.

Fork-side consumption

Vanilla 1.8 EntityRenderer.getMouseOver iterates entities in the view cone, expands each entity's bounding box by its collision border on all three axes, and ray-traces from the eye along the look vector capped at blockReachDistance, 4.5 in survival. The Rise fork adds the module's expand value to that border for player entities that are not invisible, exactly as the 6.1.30 fork shows at EntityRenderer line 493. The result is a box up to 2*expand wider per axis, so the intercept succeeds at angular offsets and distances a vanilla box would reject. Because the check runs client-side only, the server computes reach and direction against the real 0.6-wide entity box and the reported attack look.

Wire fingerprint

Nothing is sent and nothing is received. The module's only observable is the C02 attack stream: a hit that the server-side geometry should reject, either because the look angle points off the real box or because the distance exceeds the survival bound. That asymmetry, client box versus server box, is the entire countering story: every check below revalidates the attack against the real entity geometry.

How it counteracts this module

NCP's fight Reach measures the eye-to-target distance against the real hitbox inset and compares it to reachSurvivalDistance, default 4.02 in this tree, with the reachMod reduce band below the limit silently cancelling repeat hits as the score climbs. The client-side border inflation transfers nothing to the server, so a hit landed through the expanded shell presents either an over-distance attack or an off-box attack measured against the real 0.6-wide box. At default expand 1 the intercept can sit beyond 4.02 on nearly every swing, making this a direct counter rather than a boundary.

How it counteracts this module

Arc v2's KillAura carries the reach and direction sub-checks: center distance minus victim velocity against max-reach 4.2, and the angle between the entity vector and the look direction against max-direction-angle 1.2. The border inflation produces exactly the profile these sub-checks score: hits that only intersect the phantom shell present an angular offset against the real box, and hits at the ray cap present an inflated distance. The knockback exemption applies only to the reach side, so the direction side keeps accumulating.
