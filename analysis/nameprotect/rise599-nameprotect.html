Overview

NameProtect is a render-only module whose entire implementation is a static enabled flag. The real behavior lives in the client's custom TTF font renderer: TTFFontRenderer.drawString replaces every occurrence of the player's own name in any string it renders with 'Rise User' while the flag is set, which covers nametags, chat lines and HUD text that route through the renderer. The module sends no packets and rewrites no incoming packets; the server already knows the name because it authored the messages. The C17 chip is the identity-carrying payload family the module is often grouped with, but the module never touches it.

Static flag surface

The module body is a boolean: onEnable sets the public static enabled flag, onDisable clears it, and nothing else exists. Rise's font pipeline reads the flag directly: TTFFontRenderer.drawString checks NameProtect.enabled at three call sites and substitutes the player name before the glyph pass. The sibling Streamer module follows the same pattern with a player list, replacing each listed name with 'Player'. The module is registered in ProtectedLaunch's module array like every other Rise module.

Replacement mechanics

The substitution is a regex replace: text.replaceAll(mc.thePlayer.getName(), "Rise User"). Because the name is treated as a regular expression pattern, a player name containing metacharacters such as a dot or a dollar sign makes the pattern malformed and the render call throws PatternSyntaxException, breaking the draw path for that frame; the module is only safe for plain alphanumeric names. The replacement applies anywhere the name appears in rendered strings, so nametags, the chat feed and scoreboard-style HUD lines all show the alias.

Wire silence

Nothing leaves the client and no inbound packet is modified: the S02 chat messages, S0C spawns and S3F team updates that carry the name pass through untouched, and the server-side identity, used by staff commands, chat formatting and scoreboards, is unaffected. The hiding is purely a local display transformation, which is why every server-side check below is an honest gap.
