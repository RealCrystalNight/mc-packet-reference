Overview

Spicy's TriggerBot attacks whatever the crosshair is already pointing at: on every EventMotion, if the client's mouse-over target is an entity and the attack timer has elapsed, it swings and sends one C02 ATTACK on that entity. The module never rotates, never extends reach, and never changes the player's position, so its attacks are geometrically identical to a player clicking on the hovered entity. The only distinguishing signal is cadence: the timer is a strictly periodic System.currentTimeMillis gate at the configured APS (0 to 20, default 10).

Crosshair gating

The handler runs from EventMotion, which Spicy fires PRE inside the fork's onUpdateWalkingPlayer before the movement packet is sent. The gate is mc.objectMouseOver, the vanilla camera ray trace updated per frame by the renderer: only an ENTITY hit passes, and the attack target is exactly entityHit. Because the trace is the player's own aim, every attack is in reach by construction and faces the victim, and the module contributes no rotation of its own to hide or fake.

Cadence

The Timer uses System.currentTimeMillis with a reset on every fire, so the inter-attack gap is a constant 1000 divided by the APS setting: 100ms at the 10 default, 50ms at 20. The periodicity is exact, with no jitter, no randomization, and no human variance, which is the one server-observable property that separates the module from a fast clicking player. The commented-out C08 use-item branch would have added a block-use attack, but it is dead code and the module's wire footprint is swing plus C02 only.

Attack semantics

Each attack sends the C02 with the default attack action after a swing, through addToSendQueue, so the pair is event-visible and ordered swing before attack. At 20 APS the module sustains a rate that a human cannot hold, and at any APS the gaps are perfectly uniform, which is what the rate and window checks key on rather than any geometry. The APS setting steps by 1 from 0 to 20 with a default of 10.

What this file does

The Timer is the module's only clock: hasTimeElapsed returns true when System.currentTimeMillis minus the stored lastMS exceeds the argument, and resets lastMS on every true return. TriggerBot calls it with 1000 divided by the APS setting, so the cadence is a strict period with no accumulation and no drift correction. The same class backs several Spicy modules, and its free-running nature is why the attack stream is perfectly periodic.

How it counteracts this module

FightSpeed is the one check in the set that scores the module's real tell. It logs an attack only when the inter-attack gap is at most RECORD_SENSITIVITY (4 ticks), keeps a 10-sample window, and punishes when the average CPS exceeds MAX_CPS (16 default). At 20 APS the gaps are exactly one tick, every attack is logged, and the average of 20 trips the cap on the first full window, adding a violation with the measured CPS in the message.

The default 10 APS sits under the cap and passes the window, which is the honest boundary: a triggerbot run at 10 to 16 APS is indistinguishable from a fast clicker by rate alone. The perfect periodicity is the deeper tell, but this check measures averages, not variance, so it catches the high end of the setting range and misses the middle. NCP's window check below is the complementary pressure for the lower end.

How it counteracts this module

Every triggerbot attack passes this check by construction, and the explanation is the point. The client ray trace only resolves an entity hit within the vanilla interaction range, so the server-side distance measured from the tracked position stays under about 3 blocks, against the survival limit of 4.02 in this tree (DefaultConfig line 366). The reachMod adaption reinforces the pass: the reduce band (0.8 wide, starting at the limit) only steps reachMod down for hits between roughly 3.22 and 4.02 blocks, and the module's hits sit below the band, so the silent-cancel path never engages and reachMod recovers toward 1.0.

This makes reach a non-signal for the module, which is exactly what a crosshair-gated design buys: the geometry is legitimate because the aim is legitimate. The check only becomes relevant against killaura variants that attack off-aim or past the band, and its absence of flags here is the honest baseline that the cadence checks above are designed around.

How it counteracts this module

Angle scores the stream over a 1000ms window: average movement between attacks, average time between attacks, average yaw change, and switch speed, accumulated into angleVL with a 0.98 decay. A standing triggerbot maximizes the first three signals, because avgmove is near zero, the gaps at 10 to 20 APS sit under the 150ms time threshold, and the yaw never changes between attacks. The fourth signal, switching victims without turning, also feeds when the crosshair moves off one entity onto another between fires.

The stock thresholds in this tree (move 100, time 150, yaw 60, switch 50) cap the per-call scores at 20-30, so at defaults the check is dormant and the module passes; this is the same config-gating that applies to every killaura analysis on this site. Detection configs that lower the thresholds turn the standing-still attack pattern into a constant flag source, which is the deployment where the module actually gets caught. The honest framing is that Angle is a threat on hardened servers, not on stock ones.

How it counteracts this module

The direction cone passes every triggerbot attack, and again the reason is the module's design. The check requires the victim's AABB, expanded by 0.2, to lie between the current and previous direction rays built from the server-observed yaw and pitch. The triggerbot only attacks the entity the player's own ray trace hit, so the victim is on the direction ray by definition, and since the module never spoofs rotations, the server-observed yaw matches the client's aim.

This entry documents the boundary that makes the module hard to catch: the client-side and server-side ray traces agree because there is nothing to disagree about. The check exists to defeat silent rotations and multi-target sweeps that aim at one entity and hit another, and it is precisely those patterns that this module avoids. Its place in the countering set is to show why geometry-only detection cannot see a crosshair-gated attacker, which leaves cadence as the remaining signal.
