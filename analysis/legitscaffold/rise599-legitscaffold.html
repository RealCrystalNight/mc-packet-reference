Analysis

Overview

LegitScaffold is an edge-sneak module, not a block placer. On every PreMotionEvent it decides whether the player is standing on a block edge: if the block below is air while onGround, it presses the sneak key under the Blocks Only and Directional Check gates, and the vanilla key-state mirror emits C0B sneak toggles to the server. Once the player is back over solid ground, a TimeUtil gate is reset and the key is released after delay times a randomized 0.95 to 1.05 factor, default 50ms, restoring the physical key state. The result is the classic safe-bridge behavior: sneak while over air, walk normally over blocks, with no placement packets anywhere in the cycle.

Edge-sneak state machine

The handler is a two-branch if/else-if per pre-motion. The air branch runs when the feet block is air and the player is onGround: it presses keyBindSneak and latches wasOverBlock. The ground branch runs when onGround over a solid block: it resets the timer if the player just left an edge, and after the randomized delay passes hasReached it restores the key to its physical state. onDisable unconditionally restores the key, so a mid-edge disable releases sneak. The delay expression multiplies the setting by Math.random()*0.1+0.95, a 10 percent jitter band around the configured value that decorrelates release timing from the tick grid.

Gate logic

The entry condition is three clauses under operator precedence: the module always runs when Blocks Only is off; with Blocks Only on it runs when the held item is an ItemBlock and Directional Check is off; and it always runs when moveForward is negative, so walking backwards toward an edge sneaks even with a non-block item held. The intended default behavior, Blocks Only on and Directional Check on, means the sneak only engages while holding a placeable block, which is exactly the bridging posture.

Wire presence

The sneak presses reach the server as C0B START_SNEAKING and STOP_SNEAKING pairs through the vanilla setSneaking mirror in EntityPlayerSP. The C03 stream carries the vanilla sneak movement profile: the 30 percent speed multiplier, the edge clamp applied client-side, and the lowered pose. No C08 placement is ever emitted, so the C08 chip in the packet list is the scaffold archetype rather than the module's real traffic, and the look is never touched. The whole cycle is vanilla key simulation.

How it counteracts this module

Hawk's ActionToggleSpeed tracks SNEAK_START and SNEAK_STOP events per player and punishes any toggle that lands less than one tick after the previous one, sharing one ledger for both directions. LegitScaffold's pairs are always separated by at least one server tick: the press happens on the air tick and the release only after the randomized delay, default 47.5 to 52.5ms, at least one 50ms tick, while over a block, so the gap test passes. The check is the honest boundary for this technique: it exists precisely to catch same-tick sneak spam, and the module's design keeps the gap at the minimum legal value.
