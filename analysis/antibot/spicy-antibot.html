Overview

Spicy's Antibot is a two-mode entity filter that descends from the same lineage as Sigma 4.11's AntiBot. The single AntibotMode setting only ever resolves to Advanced, and the mode label shown in the HUD switches on the server IP: Hypixel runs hypixelAntibot(), a per-tick scan that classifies watchdog clones, shop stands and lobby NPCs by name and invisibility state and removes the marked players from the client world on the post update; every other server runs the Advanced path, which cancels S0CPacketSpawnPlayer spawns within 17 blocks above the player and sweeps the loaded entity list for invisible entities, removing each one it finds. The module keeps two private lists, dontRemove and removeThese, so genuine NPCs and shop stands are whitelisted before anything is removed, and removal is deferred to the post phase inside a try/catch so a ConcurrentModificationException on the world's entity list cannot crash the tick. It also publishes a static target field that other combat modules read as the filtered combat target.

Architecture

The module declares a single ModeSetting, AntibotMode, whose options list contains only the value Advanced, so the setting is effectively a label. onEvent handles EventUpdate and EventPacket: the packet branch only acts in Advanced mode and only on servers whose IP does not contain hypixel, cancelling inbound S0CPacketSpawnPlayer packets; the update branch decides between hypixelAntibot() and the Advanced invisible-entity sweep with the same server-IP test. onEnable and onDisable both clear the two persistent lists, dontRemove and removeThese, so no entity survives a toggle as a stale candidate. The static EntityLivingBase target field is the module's exported state: other combat features read it as the current filtered target, which makes the bot filter a shared input to the client's aim and attack logic.

Advanced mode

The Advanced path has two layers. The packet layer (line 76) decodes S0CPacketSpawnPlayer fixed-point coordinates and cancels the spawn when it is within 17 blocks of the player, more than one block above it, and not exactly at the player's own coordinates, the identical predicate to Sigma 4.11's Packet mode, which marks this code as a direct port. The tick layer (line 122) iterates mc.theWorld.loadedEntityList and removes every invisible entity that is not the local player, posting a private-chat message per removal. The sweep mutates the world's entity list inside the loop, and unlike the Hypixel path it does not defer or guard the removal, so the module depends on the iteration behavior of the loaded list; the Hypixel path exists precisely because that pattern can throw, and it wraps the same operation in an explicit try/catch that reports ConcurrentModificationException to the user.

Hypixel mode

hypixelAntibot() (line 184) walks the loaded entity list and classifies every remote player with the same signature chain as the Sigma original: an invisible player whose formatted display name lacks a red prefix but ends with a reset marker, whose custom name tag equals the entity name, positioned 10-13 blocks above and within 3 blocks horizontally of the local player, and absent from the tab list (PlayerUtils.getTabPlayerList) is queued for removal; an invisible entity whose custom tag contains a doubled red marker while the name contains a red marker is also queued; a display name with a section prefix that is not invisible and does not contain 'npc' is kept, and anything else is queued; a custom tag containing both red and reset markers queues the entity as a watchdog bot with a chat message. Display names containing the lobby NPC prefix go to dontRemove instead, as do entities with a non-empty custom tag that lacks a red marker and bedwars shop stands (no section prefix, reset suffix). The pre phase fills the lists, the post phase drains removeThese through mc.theWorld.removeEntity inside the try/catch, and the dontRemove whitelist is what keeps genuine NPCs and shop entities alive.

How it counteracts this module

network-dev's AntiBotDetection probes the client that classifies entities as bots and then refuses to attack the server-planted decoy. Spicy's Hypixel path is a direct target: the probe is invisible, its custom name equals its entity name, and it never appears in any tab list, which is exactly the primary watchdog signature hypixelAntibot classifies. Tolerance and bypass surface: the check only arms after two hits within the 10-tick combat window and skips players with flight enabled. Attacking the probe once to clear it and then filtering it passes this check, at the cost of a decoy hit that the companion BotHit check scores.

How it counteracts this module

BotHit is the complementary probe: it watches for the client that attacks the decoy at all. On the first damage event it spawns an invisible NPC one block in front of the player and re-teleports it to two blocks in front every tick; each USE_ENTITY packet targeting its entity id increments NPCHits, and every 20 ticks more than 2 hits yields a KillAura violation carrying the hit count. The probe is spawned once and follows the player for his whole session.

Spicy's Hypixel autoblock and killaura run their own target selection on the loaded entity list. If the antibot filter has not yet classified the probe (its name rules require either a missing custom tag or a specific format, and the probe's name equals the player's), the NPC remains a valid in-range target and the aura attacks it: the module's own default APS of 10 puts three hits inside the 20-tick window in under half a second. The Advanced path's invisible sweep normally removes the NPC first, so BotHit tends to fire only in the gap between spawn and sweep, but that gap is exactly where an unfiltered aura is exposed.

The two probes together bracket the design space: a killaura that filters the decoy fails AntiBotDetection, one that does not fails BotHit. Spicy survives only if its filter reaches every target decision while the aura never touches the decoy, which requires the static target field and the removal lists to be consulted by every combat path.
