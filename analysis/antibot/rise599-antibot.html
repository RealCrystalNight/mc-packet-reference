Analysis

Overview

Rise 5.99's AntiBot is a configurable bot filter with nine independent boolean checks under a Custom mode and a fixed Hypixel preset, all evaluated from onPreMotion every tick. Each check writes the entity's bot flag, and every flagged player is collected into the static bots list that the Aura module consults when selecting targets. The Custom checks cover visibility ticks, movement, duplicate and invalid names, entity ids and tab-list ping; the Hypixel preset looks for invisible entities that teleported upward or hover above the player. onEnable conservatively marks every player as a bot, and onDisable clears all flags and the list.

Architecture

The module declares a ModeSetting with Custom and Hypixel values and nine BooleanSettings: noMove, duplicateName, ticksExisted, ticksVisible, invalidName, duplicateID, negativeID, distance and ping. onUpdateAlwaysInGui hides all nine unless Custom is selected, so the GUI only exposes what the current mode uses. onPreMotion clears the static bots list, then iterates mc.theWorld.playerEntities, skips the local player, applies the active mode's checks, and appends any player whose bot flag is set. The public static List<Entity> bots is the module's only output, and Aura reads it inside its target filter. onEnable marks every player in the world as a bot so nothing is attacked until the checks clear it, and onDisable resets every entity flag.

Bot detection heuristics

The Custom checks each set player.bot directly. ticksVisible flags anyone with ticksExisted at or below 160 or ticksVisible at or below 160, resetting the visible counter to 0 while the entity is invisible to the player or fully invisible. noMove flags players younger than 10 ticks and unflags them as soon as lastTickPosX or lastTickPosZ differs from the current position, so stationary spawns stay flagged. duplicateName flags the second player with a repeated name, invalidName flags any name containing a character outside A-Za-z0-9 and underscore, ticksExisted flags non-positive ages, duplicateID and negativeID flag repeated or negative entity ids, and distance unflags players more than 200 blocks away while flagging anyone younger than 5 ticks. ping flags players whose tab-list NetworkPlayerInfo reports a negative response time.

The Hypixel preset runs two rules, both requiring the entity to be invisible and on the ground: a rise in posY minus lastTickPosY greater than 1.5 marks a bot, as does a position between 4 and 10 blocks above the local player with a per-tick rise under 0.5. Both target the server's practice of spawning anti-cheat bots in the air above players and teleporting them into position. The checks are deliberately loose, and the module compensates by defaulting to the bot=true state for every player on enable, so a clean filter needs the movement or visibility checks to clear real players over the first few seconds.

Interaction with killaura targeting

Aura's target filter rejects any entity with ticksExisted below 2 and any entity contained in AntiBot.bots, so a flagged player is never selected by getTargets and never attacked by the Single, Switch or Multi paths. Because onPreMotion rebuilds the list every tick and onEnable starts from everyone-is-a-bot, the filter is a one-tick-deep snapshot: an entity is excluded only while a check keeps its flag set in the same tick the aura selects. The multi-target path benefits the most, since a bot that slips into the list would otherwise receive a C02 in the same tick as a real player, and the Multi-mode angle signature would include the bogus target.

What this file does

The whole module is this one class. The ModeSetting chooses Custom or Hypixel, onUpdateAlwaysInGui toggles the visibility of the nine BooleanSettings, and onPreMotion clears bots and re-runs the selected mode's checks over mc.theWorld.playerEntities, excluding the local player. Every check writes the entity's bot field, and any player with bot set is appended to the static bots list that the combat modules read. The module imports no utility classes: name scanning, id comparison and the ping lookup through mc.getNetHandler().getPlayerInfo are all inlined.

The toggle lifecycle is part of the filter's behavior. onEnable sets bot = true on every player in the world, so the filter starts maximally conservative and relies on the per-tick checks to clear real players; onDisable clears bots and resets every entity flag, so a toggle-off restores normal targeting immediately. The Hypixel mode is the only branch that reads positions: it needs invisible, grounded entities that either jumped more than 1.5 blocks or hover 4 to 10 blocks above the local player with minimal vertical movement.

How it counteracts this module

NCP's Angle check records every attack as an AttackLocation holding the player location, the damaged entity's unique id and the timestamp, and compares consecutive entries. Each new attack adds the squared movement between locations, the absolute yaw difference between the attack frames, and the elapsed time; a target switch counts when the unique id differs and the yaw difference exceeds 30 degrees. Entries older than maxTimeDiff are dropped, and the averages are scaled by server lag.

The violation logic then compares the average yaw change against the average movement and time: a player who stays nearly still while snapping the view between targets accumulates yaw deltas with almost no movement, which is the rotation signature of an aura. The check needs at least two attacks in the window to fire, and target switching with yaw changes over 30 degrees is the strongest signal.

Rise's Multi mode emits several C02 attacks at different entities within the same tick, and even Single mode snaps serverYaw and serverPitch into PreMotion so the server observes full-speed rotation changes while the position barely moves. With default snap rotations the per-attack yaw delta between distinct targets is large and the movement between attacks is near zero, exactly the averageYaw-versus-averageMove imbalance the check scores. The bot filter trims the candidate list, but Multi mode still cycles real targets at full rotation speed, so the signature survives filtering.

How it counteracts this module

Grim's Reach validates each attack against the entity box as reconstructed from spawn and move packets, with lag compensation. The check enumerates the possible look directions from the current and previous yaw and pitch, extends each ray to the reach limit plus 3 blocks, and requires an intersection with the box through ReachUtils.calculateIntercept. The minimum reach to the box is computed by ReachUtils.getMinReachToBox, and the threshold for a violation is 0.0005, with block-impossible-hits cancelling attacks no look direction could have landed.

Rise's Extended Range mode depends on moving the server-side position with C04 streams, which changes the eye position Grim uses, so the walk genuinely shrinks the measured distance while it is in effect. The counter is the reconstruction itself: the entity box is interpolated between replicated positions, the look is taken from the movement packets, and an attack must intersect the box within the limit, so a through-wall hit or a hit from beyond the box fails. The threshold makes borderline hits measurable rather than binary.

The bot filter reduces which entities produce C02 packets, but every packet that survives is checked against the replicated box, and the aura's bypass settings do not alter the geometry Grim sees. Filtered-out bots simply produce no packets, which is the same as not attacking them at all.
