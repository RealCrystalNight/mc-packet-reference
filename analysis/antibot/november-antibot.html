Overview

November Recode 2.0's AntiBot module is a spawn-and-tab-list bot filter with three modes: WATCHDOG, TAB_TICKS and NPC. It keeps a concurrent set of flagged entity ids, rebuilt from the player entity list on every walking update, and exposes a public bot(int) predicate that the KillAura module calls from its validTarget filter. WATCHDOG flags invisible players missing from the tab list and then picks one bot within 10 blocks vertically to watch, with a packet listener that reacts to its destroy or spawn; TAB_TICKS flags players older than a configured age that never appeared in the tab list; NPC flags names carrying CIT-, [NPC] or color-code markers plus players missing from the tab list.

Architecture

The module declares a Mode setting with WATCHDOG, TAB_TICKS and NPC values, plus a tabTicks number setting and a noTab boolean that are only visible for their modes. bots is a ConcurrentSet of entity ids, aboveEntityId and aboveDespawn track the watched bot in WATCHDOG mode, and disable() clears all three. The update listener skips the first five ticks after the player spawns, then rebuilds the set from mc.theWorld.playerEntities, and the packetIn listener handles S13PacketDestroyEntities and S0CPacketSpawnPlayer, both gated to WATCHDOG mode. The tabList helper scans the send queue's player info map for a matching game profile name, and bot(int) is the query the combat module calls.

Bot detection heuristics

WATCHDOG flags every invisible player that is not in the tab list, then scans the flagged set for the first entity within 10 blocks vertically of the local player, stores its id in aboveEntityId and prints a chat message naming it. The packet listener then reacts to that specific id: an S13 destroy prints 'was removed from the world. Staff?' and clears aboveEntityId, while an S0C spawn adds the new entity id to bots when aboveDespawn is set. aboveDespawn is never assigned true anywhere in the class, so the spawn branch is unreachable dead code, and the 'todo i have no clue' comment marks the mode as unfinished.

TAB_TICKS flags any player whose ticksExisted exceeds the tabTicks setting (default 50) while the tab list never contained their name, which targets bots that are spawned server-side and never registered as players. NPC mode flags names starting with CIT-, containing [NPC], or containing a section-sign color code, plus any player missing from the tab list when noTab is on, which covers NPC plugins and renamed entities. All three modes share the tabList scan, so a player that appears in the tab list under the same name is always treated as real.

Interaction with killaura targeting

KillAuraModule.validTarget fetches the AntiBotModule instance from the November module registry and rejects any entity whose id is in the bot set while the module is toggled on. The check runs before the range and line-of-sight tests, so a flagged entity is removed from the candidate stream entirely and never influences the sort comparator. Because the bot set is keyed by entity id and rebuilt every walking tick, an entity that stops matching its mode's heuristic, for example by appearing in the tab list, is attackable on the next tick. The WATCHDOG autoblock interaction is separate: the killaura's own WATCHDOG block mode cancels C02 attacks during hurt time, while this module only removes candidates.

What this file does

The entire module is this one class. The Mode setting and the tabTicks and noTab settings define the three filter modes, the update listener rebuilds the bots set from mc.theWorld.playerEntities every walking tick after a five-tick grace period, and the packetIn listener handles the WATCHDOG-mode entity lifecycle events. The dead code is part of the analysis: aboveDespawn is declared, cleared and tested, but never set to true, so the S0CPacketSpawnPlayer branch that would add a spawned entity id to bots can never execute. How it counteracts this module

FightHitbox re-checks each player-versus-player attack by ray tracing from the attacker's eye along the direction carried by the next movement packet. The victim's position is rewound through Hawk's lag compensator to match the ping at attack time, the hitbox is expanded by 0.005, and the ray must intersect it within 3.1 blocks, or 5.0 in creative. A miss with CHECK_BOX_INTERSECTION enabled punishes 'Did not hit hitbox.', an intersection beyond the reach reports the distance in meters, and the optional occlusion pass flags hits whose ray crosses a solid block first.

November's killaura spoofs rotations through the rotation manager at HIGH priority and attacks targets it cannot see at WallRange, so hits can be aimed through walls and at targets outside the visual cone. Hawk derives the direction from the movement packet that follows the C02, and the box is where the victim was when the attacker's view of it was formed, so a wall-hit either misses the box or lands beyond 3.1. The bot filter selects the target client-side, but the server-side ray test applies to every C02 that arrives.
