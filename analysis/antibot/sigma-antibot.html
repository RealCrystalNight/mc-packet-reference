Overview

Sigma 4.11's AntiBot is a server-specific entity filter that decides which players the client's combat modules are allowed to target. It runs three independent modes behind a single MODE setting: the Hypixel mode classifies entities in the loaded world by spawn signature (invisible watchdog clones that spawn 10-13 blocks above the player, shop stands, named lobby bots) and records them into a static invalid list that every other module reads through getInvalid(); the Packet mode cancels S0CPacketSpawnPlayer at the event bus when a new player spawns within 17 blocks and more than one block above the local player; and the Mineplex mode flags any remote player whose custom name tag is empty. A fourth setting, HypixelKiller, upgrades the classification to physical removal: the entity is deleted from the client world with removeEntity while the invalid list is populated in the same pass. The module force-switches its own mode when the server IP contains hypixel or mineplex, and its onDisable re-enables itself on those servers with a protection notification so the filter cannot be left off mid-game.

Architecture

The module listens to EventPacket and EventUpdate through one @RegisterEvent handler. The EventPacket branch only acts in Packet mode, cancelling inbound S0C player-spawn packets. The EventUpdate branch handles the rest: on the pre phase it flushes the invalid list on a one-second timer whenever it is non-empty, removes sleeping players when the DEAD setting is on (it treats isPlayerSleeping as a corpse that should not be rendered), and runs the server-specific entity scans. The static invalid list is the module's public interface: getInvalid() returns it, and companion combat modules consume it so a marked bot is never selected as an aura target, never ray-traced by aim assist, and skipped by other combat features. The HypixelKiller setting is gated on a premiumAddon object; without it the module posts a warning notification every 400ms and flips the setting off, and with it the same classification pass that populates invalid also calls mc.theWorld.removeEntity on the spot.

Spawn-packet filter (Packet mode)

Packet mode runs on the incoming event stream and cancels S0CPacketSpawnPlayer outright. The decoded spawn position (the packet's fixed-point coordinates divided by 32) is compared to the local player's position in 3D; the packet is cancelled when the spawn point is within 17 blocks, sits more than one block above the player (entY > posY + 1), and does not coincide with the player's own coordinates. The height bias is the signature the mode hunts: watchdog-style bots are injected above the player, so the filter only attacks spawns that appear overhead. Because the packet is cancelled before the entity is added to the world, the bot never exists client-side at all: it is invisible to rendering, to the target list, and to any ray trace. The same predicate, byte for byte, ships in Spicy's Antibot under its Advanced mode, which marks this filter as the shared lineage point of the two modules.

Hypixel and Mineplex heuristics

The Hypixel mode is a chain of name-and-state tests over mc.theWorld.getLoadedEntityList. The primary watchdog signature is an invisible player whose formatted display name does not start with a red section symbol but does end with a reset marker, whose custom name tag equals its entity name (an unmodified name), and whose position is 10-13 blocks above the local player with a horizontal distance under 3 blocks; if that entity is also absent from the tab list (getTabPlayerList, built from GuiPlayerTabOverlay.field_175252_a.sortedCopy of the connection's player info map) it is marked invalid. The secondary rules are pure string tests: a display name with no section-symbol prefix that ends in a reset marker (bedwars shop stands), an invisible entity whose custom tag contains a doubled red marker while its name contains a red marker (in-game invisibles), a custom tag containing both a red and a reset marker (watchdog clones), a display name containing the lobby NPC prefix, and any non-empty custom tag that contains no red marker. Mineplex mode is coarser: after tick 40 it marks every remote player whose custom name tag is empty. All marks land in the shared invalid list, and the killer flag physically removes the entity from the world in the same pass.

The constructor declares four settings: DEAD (removes sleeping player bodies, on by default), MODE (the Hypixel/Packet/Mineplex options), and HypixelKiller, gated on a premiumAddon object. onEnable clears the static invalid list, and onDisable clears it again then re-toggles the module on Hypixel and Mineplex servers with a protection notification, so the filter cannot be left off on servers that spawn watchdog bots. The static invalid and removed lists are the module's shared state: other combat modules read getInvalid() to exclude marked entities from targeting, which is the entire purpose of the class.

The EventPacket branch is Packet mode: it decodes S0CPacketSpawnPlayer fixed-point coordinates (func_148942_f / 32 and friends), measures the 3D distance to the local player, and cancels the packet when the spawn is within 17 blocks, more than one block above the player, and not exactly at the player's position (line 93). The EventUpdate pre branch runs the DEAD sweep (removeEntity on sleeping players, line 117), then the mode-specific scans, with the Hypixel branch gated on em.isPre().

Mineplex mode (lines 125-137) marks every remote player with an empty custom name after tick 40, and getTabPlayerList (lines 237-249) rebuilds the server tab from the connection's player info map, sorted with GuiPlayerTabOverlay's comparator.

How it counteracts this module

network-dev's AntiBotDetection probes the exact behavior an antibot-filtered aura produces: a client that silently classifies entities as bots and then refuses to attack the server-planted decoy. On the second hit of a real player (Hits > 1, with CombatTimer reset on every damage event), the check spawns an invisible NPC named after the attacker one block behind him (PlayerUtil.getBlockBehindPlayer(player, -1)) and starts a 10-tick BotTimer. The NPC is delivered as a listed recipient only to that player, so only his client ever sees it. If the player attacks the NPC (onPacketReceiving matching the USE_ENTITY target id against the NPC's entity id), BotHit is set true and the probe is destroyed. If ten ticks pass with the bot untouched, the check adds a KillAura violation and destroys the probe.

This is a direct counter to the Hypixel mode's classification chain. Sigma's primary signature requires an invisible entity with a specific name format that is absent from the tab list; network-dev's NPC is invisible, carries the attacker's own player name (custom tag equal to entity name, the same equality Sigma's primary rule demands), and never appears in any tab list because it is a synthetic entity. The module therefore classifies it as a bot, adds it to the invalid list, and the killaura filters it out of targeting, which is precisely the state the probe rewards with a violation. The 10-tick window is long enough to span the module's own one-second invalid-list flush, so even a module that re-scans every second keeps the NPC filtered for the whole probe lifetime. The probe re-arms on every second hit, so a player who attacks once, waits, and attacks again is probed repeatedly.

Tolerance and bypass surface: the check only arms after two hits on a real player within the 10-tick combat window and only for players without flight enabled (player.getAllowFlight() returns early), so a fly-mode player is never probed. A killaura that does not filter invisible entities will hit the NPC and clear the probe (BotHit = true), which is exactly the outcome the antibot module is designed to prevent. A module that attacks the NPC once to clear the probe and then filters it can pass this check, but that single attack registers as a hit on a decoy entity, which the companion BotHit check scores.

How it counteracts this module

BotHit is the complementary probe: it watches for the client that attacks the decoy at all. On the first damage event from a player it spawns an invisible NPC one block in front of him (PlayerUtil.getLocationFront(player, 1)) and re-teleports it to two blocks in front on every tick (getLocationFront(player, -2)). Each USE_ENTITY packet targeting the NPC's entity id increments NPCHits. Every 20 ticks the counter is evaluated: more than 2 hits on the bot yields a KillAura violation carrying the hit count, then the counter resets. The probe is spawned once and never removed, so it follows the player for his whole session.

Where AntiBotDetection punishes filtering, BotHit punishes the opposite failure: a killaura whose targeting does not consult the antibot module's invalid list. Sigma's killer mode physically removes marked entities from the world, but an aura that runs its own distance sort against the loaded entity list will happily attack the invisible NPC standing one block in front of the player, because the NPC is a valid in-range entity. Three hits in 20 ticks is a very low bar for an aura attacking at 5-20 APS, so any configuration where the antibot filter does not reach the aura's target selection trips it immediately.

The two probes together bracket the design space: a killaura that filters the decoy fails AntiBotDetection, one that does not fails BotHit. The Sigma module only survives by guaranteeing its invalid list feeds the aura's target filter while the aura simultaneously avoids attacking the decoy, a combination that requires the two features to share state, which is exactly the integration the module's static getInvalid() list exists to provide but does not force.

How it counteracts this module

Kauri's KABot check is the server-side mirror of the client-side filter: instead of removing bots, the anticheat plants fake entities and watches what the client attacks. The world tracker mirrors every spawned entity into a TrackedEntity, and around tracked entities it attaches invisible fake mobs (three size-10 magma cubes at -1.25/0/+1.25 offsets plus a size-5 slime re-teleported along the player's aim ray), with the client's acknowledgement captured as clientHasEntity, an AtomicBoolean set on a keepalive action after the fake mobs spawn.

KABot's first branch (buffer) fires when the client attacks a tracked entity that carries fake mobs (or while clientHasEntity is set) more than 3 net times without ever attacking one of the fake mobs: each C02 on the real entity adds 1 to the buffer and each C0A arm swing subtracts only 0.05, so a filter that skips the fake mobs accumulates the buffer regardless of normal swing behavior, and the flag text is 'Attacked player without attacking bot!'. The second branch (buffer2) watches the per-player mob bait: APlayer carries a FakeMob field that is respawned on world change and re-teleported to follow the player's aim line; attacking that specific entity id more than 3 net times flags 'Player attacked bot' and preloads the first buffer to 2. Attacking a fake mob id clears the first buffer, so the check rewards exactly the behavior the antibot module suppresses.

For the Sigma module this is the hard counter: the Hypixel classifier marks invisible, untabbed, name-anomalous entities as bots, and Kauri's fake mobs match that profile (invisible metadata flag 0x20, no custom name, never in any tab list, entity ids in the 1.5-2 billion range). A client running the filter classifies them, excludes them from aura targeting, and keeps attacking the real entity, feeding buffer toward the 'without attacking bot' flag. The opposite misconfiguration, the filter not reaching the aura, attacks the slime bait glued to the player's own aim line and trips buffer2. Both outcomes are flagged, so the antibot module must push every fake entity through its filter and every real entity into the aura's list with perfect consistency across a server that actively reshuffles the bait.
