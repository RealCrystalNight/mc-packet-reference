Analysis

Overview

PacketDebugger is a wire-silent observer used to probe anticheat behavior. Its send handler timestamps C0F confirm-transaction packets (window id, uid and inter-packet interval in milliseconds) and C00 keepalives (key and interval), and its receive side prints the channel name of incoming S3F custom payloads, all through Rise.addChatMessage. It cancels nothing and rewrites nothing; the chat lines are the entire output. The tool is the manual counterpart of the server-side ledgers that anticheats run: keepalive cadence, transaction acks and plugin channels are the metrics a player watches to spot an anticheat's probing or a server's set-back pattern.

Observer design

The handler is an instanceof dispatch over the outgoing packet. C0F entries print the window id and uid plus the elapsed time since the previous transaction, computed from the module's own lastTransaction field; C00 entries print the keepalive key and the elapsed time since the previous keepalive; S3F entries print only the channel name, which is enough to identify plugin channels and anticheat payloads. The lastKeepAlive and lastTransaction fields are plain millisecond timestamps, so the printed intervals are the raw inter-packet gaps.

What the metrics expose

Keepalive intervals reveal the server's tick health and the player's ping, and their pattern changes when a keepalive-ledger plugin interferes with the vanilla echo exchange. Transaction uids and window ids expose confirm-transaction probing, the technique NCP and similar ledgers use to re-sync inventories, and the C0F cadence betrays the probe interval. S3F channel names identify the payload channels a server registers, which is how a player detects anticheat channels before they fire. None of this observation has a wire effect.

Detection surface

The module emits nothing, so no server-side check can detect it; the honest countering claim is that the checks which matter are the ones monitoring the traffic it observes. The pinned S02 and S08 chips are the response channels the tool is used to watch: S08 set-back teleports and S02 anticheat warning messages are what the debugger helps a player notice and time.

How it counteracts this module

KeepAliveFrequency is the server-side ledger for exactly the C00 data the debugger prints: every echoed key is matched against the pending request list, pruned after 30 seconds and capped at 40, replies are timestamped into ActionFrequency buckets, and the check flags more than one counted reply in a second with the duplicate-id path tightening the limit. How it counteracts this module

Arc v2's MorePackets is the rate ledger for the movement stream the debugger monitors: per-second flying and position counters read from MovingData, with max-packets, default 30, flagging and max-packets-kick, default 70, kicking for sending too many packets. The debugger itself contributes zero packets, so the counters never move on its account. The entry frames the check as the boundary a flooding test would trip, which is exactly what the tool is used to calibrate.
