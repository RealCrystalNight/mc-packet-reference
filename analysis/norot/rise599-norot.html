Overview

NoRot intercepts S08PacketPlayerPosLook and rewrites or delays the forced rotation so the camera never snaps to what the server orders. The Mode setting registers six values but only three have switch cases: Vanilla overwrites the S08 yaw and pitch fields with the client's current rotation before the vanilla handler runs, so the teleport applies position-only and the C06 ack the client sends immediately after carries the client's own look; Delay lets the S08 snap and restores the pre-teleport rotation on the next PreMotion; Legit rewrites the S08 like Vanilla, saves both the server rotation and the player's starting rotation, then reports the saved server rotation on every subsequent PreMotion while the player's view is unchanged, gated on the event yaw still matching the starting yaw. Packet, Edit and Hypixel have no case branches and are dead modes. The vanilla handler that consumes the modified packet (handlePlayerPosLook) sets position and rotation and immediately emits a C06 ack with the same position and look, which is why the module's field rewrite changes what the server measures.

Mode matrix

The switch in onPacketReceive runs before the vanilla handler, so field writes change what the client applies and acks. Vanilla stores the server's yaw and pitch into the module fields and overwrites the packet fields with mc.thePlayer.rotationYaw and rotationPitch; the stored values are never read again, making Vanilla a pure drop of the forced rotation. Delay does not touch the packet at all: it saves the client's current rotation and restores it in onPreMotion one tick later, so the snap exists for exactly one tick. Legit rewrites the packet like Vanilla, saves the server rotation and the player's starting rotation, and on later PreMotions reports the server rotation via event.setYaw and event.setPitch, but only while the event yaw still equals the starting yaw, so the first mouse movement clears the pin. Packet, Edit and Hypixel register no case and execute nothing.

Vanilla teleport contract

The fork's vanilla handler defines the wire effect. handlePlayerPosLook applies the packet's position and rotation to the player and immediately sends C06PacketPlayerPosLook with that same position, yaw and pitch, which the server treats as the teleport acknowledgement. NoRot's rewrite therefore does not just spare the camera: it changes the ack. In Vanilla and Legit the ack reports the client's pre-teleport rotation instead of the server's forced one, while the position part matches exactly. In Delay the ack reports the forced rotation (the packet was untouched) and the restore appears only on the next regular C03, one tick later.

Legit pin behavior

Legit is the mode with a persistent signature. Because the camera never snapped and the equality gate requires the event yaw and pitch to match the starting values, the pin survives until the mouse moves: every PreMotion in between reports the saved server rotation verbatim, so the C03 stream carries one constant yaw and pitch pair for potentially many ticks. The moment the player moves the view, the gate fails and all four saved fields are nulled, releasing the pin. The mode is a rotation desync rather than a freeze: the local camera stays at the player's rotation while the packets claim the server's.

intave's snap detector requires the yaw-motion triple (previous under 9 degrees, current over 40, next under 9) plus a swing or attack within 150 ms, more than 10 rotation packets processed and more than 7 ticks since the last teleport. Delay mode produces exactly a snap-and-restore: the S08 forces a rotation jump and the next PreMotion restores it, so the C03 stream shows a single over-40 spike between two quiet ticks. How it counteracts this module

NoCheatPlus queues every outbound S08 teleport and matches the client's next position-and-look packet against it with exact equality via isSamePosAndLook, so the acknowledgement must reproduce the teleport's yaw and pitch as well as its position. Vanilla and Legit rewrite the S08 fields before the vanilla handler acks, which means the C06 reports the client's rotation and never matches the queued entry: the ledger stays WAITING until the entry ages out at 4000 ms. On 1.8 the WAITING branch does not cancel the move (the cancel path is gated on the 1.9-plus CONFIRM_TELEPORT packet type), so the practical effect is a stale queue entry and the ack being treated as an ordinary move. Delay mode sends the correct forced look in its ack and closes the ledger normally, so the check separates the modes exactly along the rewrite boundary.
