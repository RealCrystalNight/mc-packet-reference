Sigma 4.11 InventoryWalk — Full Source Analysis

Sigma's InventoryWalk keeps the player moving while any GUI is open by re-asserting the five movement KeyBindings from the raw keyboard state every tick, so the vanilla movement code runs and the C03 stream continues through the window. Arrow keys rotate the view in addition (pitch 1, yaw 3 per key tick). Analysis

Overview

Sigma's InventoryWalk keeps the player moving while any GUI is open by re-asserting the five movement KeyBindings from the raw keyboard state every tick, so the vanilla movement code runs and the C03 stream continues through the window. Arrow keys rotate the view in addition (pitch 1, yaw 3 per key tick). The three modes differ in how they treat the open-window state: Basic just walks, AACP suppresses sprint while the window is open (one STOP_SPRINTING on open, START_SPRINTING on close, and every START_SPRINTING cancelled in between), and Cubecraft cancels the C0B OPEN_INVENTORY and C16 OPEN_INVENTORY_ACHIEVEMENT packets so the server never opens the vanilla inventory window at all. A separate CARRY toggle cancels outgoing C0D close-window packets, keeping the server-side window alive after the client GUI closes.

Key re-assertion

EventTick runs while mc.currentScreen is non-null and calls KeyBinding.setKeyBindState for forward, back, left, right and jump using Keyboard.isKeyDown, which makes the vanilla EntityPlayerSP movement code believe the keys are pressed even though the GUI owns the input. The arrow-key block mutates rotationPitch and rotationYaw directly (1 degree pitch, 3 degrees yaw per event) unless the open screen is Sigma's own GuiInvManager, and the mutated angles ride the next C03 look packet. The module bails entirely when the screen is a GuiChat, so chat typing never walks the player.

Mode-specific packet games

The inInventory flag tracks whether the module has seen the window open transition. On the first tick with a screen open, AACP sends one C0BPacketEntityAction STOP_SPRINTING; while inInventory it cancels every outgoing START_SPRINTING, so the server-side sprint flag never turns back on during the walk; on close it sends START_SPRINTING to restore the state it found. The Cubecraft mode cancels C0B OPEN_INVENTORY and C16 OPEN_INVENTORY_ACHIEVEMENT, which removes the client's announcement of the vanilla inventory open, so the server-side window bookkeeping never registers the screen the client is actually showing. The CARRY toggle cancels every outgoing C0D close-window packet, which is the classic carry exploit: the client closes the GUI, the server believes the window is still open, and items held in the cursor or crafting slots survive the close.

Detection surface

The wire signature is a normal C03 stream that simply continues while a window is open, plus mode-specific extras: the AACP C0B sprint toggle at each GUI boundary, the Cubecraft C0B/C16 cancellations, and the CARRY C0D cancellations. The open-state checks (NCP Open, Hawk InventoryMove) target the Basic behavior directly, the toggle-rate checks (NCP ToggleFrequency, Hawk ActionToggleSpeed) see the AACP C0B games, and the arrow-key look produces rotation updates while the window flag is set, which is precisely what Hawk InventoryMove flags.

What this file does

The module is three event handlers. EventTick owns the key re-assertion and the mode transitions: the move-key loop runs whenever a screen is open, the AACP STOP_SPRINTING/START_SPRINTING pair brackets the inInventory flag flip, and the arrow-key rotation runs for every screen except GuiInvManager. EventPacket handles the packet games: the CARRY toggle cancels outgoing C0D close-window packets, the AACP branch cancels START_SPRINTING while inInventory, and the Cubecraft branch cancels C0B OPEN_INVENTORY and C16 OPEN_INVENTORY_ACHIEVEMENT. EventUpdate is registered but its body is empty, a leftover shell from an earlier revision.

The GuiChat early return and the mode string suffix are the only UX details; the rest is pure packet manipulation. Note that the C0D cancel in the CARRY branch is gated on the CARRY setting only, so it applies to every window including chests, not just the crafting inventory the setting name implies.
