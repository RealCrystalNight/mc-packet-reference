Overview

KABot is Kauri's killaura check built on planted fake entities instead of statistics. The anticheat mirrors every entity the server spawns into a TrackedEntity inside a per-world tracker, attaches invisible fake mobs to tracked entities, and keeps a personal bait mob that follows each suspect's aim line; it then reads the client's C02 interact stream against those bait entity ids. Two independent buffers measure two failure modes: attacking a real entity whose surroundings carry fake mobs without ever touching the fake mobs (the signature of an entity filter, buffer above 3), and attacking the personal bait mob itself (the signature of an unfiltered aura, buffer2 above 3). Each C0A arm swing drains both buffers (0.05 and 0.25) so that vanilla's swing-per-attack cadence keeps a legitimate player's net change near zero. The check is flag-only: it feeds the violation system but never cancels packets or damage. The killaura package's calc/ directory (KACalc, RotationCheck, KAZero, KAGrid) is the sibling rotation-analysis machinery; KABot does not invoke it, but both halves read the same tracked-entity pipeline.

Bait infrastructure

APlayer.load() wires the tracker: worldTracker is a BlockUpdateHandler whose currentWorld AtomicReference holds the per-world mirror (a dev.brighten.ac.handler.block.World), and entityTrackHandler is an EntityTrackHandler that feeds it. PacketHandler inserts a TrackedEntity on every spawn packet (S0F mob spawns, S0C player spawns, S0E object spawns), and EntityTrackHandler processes the position stream (relative moves, position sync, teleports) into interpolated old/new EntityLocation states on the flying-packet cadence, with the apply ordered by keepalive actions so the client has actually received the packet. Each TrackedEntity carries a fakeMobs list. EntityTrackHandler.createFakeMob plants three invisible size-10 magma cubes at -1.25/0/+1.25 offsets around the tracked entity plus one invisible size-5 slime placed by ray-casting the player's eye direction 0.4 blocks ahead, and flips clientHasEntity (an AtomicBoolean) via a keepalive action once the client has acknowledged the spawns. APlayer also carries a single FakeMob field (mob): BlockUpdateHandler.onRespawn and the world-change teleport listener respawn it behind the player, and MovementHandler.processBotMove re-teleports it along the player's aim line on every movement packet so it stays inside the attack cone. FakeMob entity ids are drawn from 1.5-2 billion so they never collide with real server ids, and the invisible metadata flag (0x20) makes them render transparently.

Detection logic

Both branches are @Bind WActions. The arm action runs on every WrapperPlayClientAnimation (C0A) and drains buffer by 0.05 and buffer2 by 0.25, on the source's own reasoning that a vanilla 1.8.8 player swings with every attack, so a legitimate attack cadence leaves both buffers net-zero. The interact action runs on every WrapperPlayClientInteractEntity (C02). The first branch resolves the attacked id through the world tracker's getTrackedEntity; if the target is tracked and either clientHasEntity is set or its fakeMobs list is non-empty, buffer increments and above 3 the check flags 'Attacked player without attacking bot!', otherwise the buffer resets to 0, so attacking a fake mob (whose id is not in the tracked map) actively clears the buffer. The second branch compares the attacked id to player.getMob().getEntityId(); a match increments buffer2 and above 3 flags 'Player attacked bot' while preloading buffer to 2. The thresholds are effectively four net attacks: the swing drains are small relative to the +1 per attack, so a filter that never touches the bait flags after four attacks on the real entity, and an unfiltered aura flags after four hits on the personal bait. The check never cancels anything: it only feeds the flag pipeline, and server-side damage denial is handled elsewhere through the hitsToCancel counter in GeneralListener.

Killaura calc package

The calc/ directory holds the killaura package's rotation machinery. KACalc is a @Hook KListener that runs on every flying packet while the player has a target and the last attack is under 40ms old: it resolves the target's interpolated location, builds the eye origin (1.62, or 1.54 while sneaking), computes the yaw and pitch offsets between the eye line and the target's eye-height midpoint, accumulates the last 10 offsets, and hands the old/new EntityLocation pair, the standard deviations and the raw offsets to the RotationCheck implementations. KAZero (KillAura (Zero)) flags when the horizontal offset is exactly 0 with a buffer over 2, a perfect error-free aim line. KAGrid (KillAura (Grid)) accumulates the summed offsets into a 100-entry ring and runs a grid analysis once 50 samples exist. KABot shares the tracked-entity pipeline these checks read but does not invoke any of them: the two halves of the package attack killaura from opposite directions, statistical rotation analysis versus planted-entity bait.

What this file does

KACalc is the @Hook KListener that runs the rotation math for the killaura package's statistical checks. Its flying action only runs while the player has a current target and the last attack was under 40ms ago, which ties the analysis to actual combat windows. It resolves the target's interpolated EntityLocation, builds the attacker origin as the movement position plus 1.62 (1.54 while sneaking), and computes the yaw/pitch offset between that eye line and the target position plus half its eye height using MathUtils.getRotation and getOffsetFromLocation.

The last 10 offsets are kept in EvictingList buffers, and once both are full the action computes the standard deviation of the yaw and pitch offset series, packages the old/new locations, std devs, current offsets and rotations into a Tuple, and dispatches to the RotationCheck implementations found on the player, KAZero and KAGrid. This file is the shared pipeline entry that KABot's world lookups also sit on: KABot calls getTrackedEntity directly and never enters KACalc, but both read the same interpolated entity state that EntityTrackHandler maintains.

What this file does

EntityTrackHandler owns the fake-mob lifecycle. createFakeMob (lines 265-309) runs when a tracked entity moves non-relatively and no fake mobs exist yet, gated on canCreateMob: it spawns three invisible size-10 magma cubes at -1.25, 0 and +1.25 offsets on all axes around the entity and attaches them to its TrackedEntity, then ray-casts from the player's eye (eye height divided by 2.5) along the look direction, spawns one invisible size-5 slime at the 0.4-block collision point, attaches it to the player's own TrackedEntity, removes the entity id from canCreateMob, and flips clientHasEntity through a keepalive action so the flag is only set once the client has provably received the spawns.

processZombie (lines 311-333) runs on the flying cadence and keeps the bait aligned: if the player's tracked entity carries more than one fake mob they are all removed (a desync guard), and the slime among them is re-teleported to the current aim-ray collision point 0.4 blocks ahead, 0.6 above the player's position. processFakeMobs (lines 335-364) relocates the cluster when the real entity moves: relative moves are forwarded as relative moves, teleports reposition the three cubes with their offsets, and any count mismatch against offsets.length + 1 triggers a full remove. onEntityDestroy (lines 240-246) defers fake-mob despawn to a keepalive action and clears clientHasEntity. The allowedEntityTypes set (zombie, sheep, blaze, skeleton, player, villager, iron golem, witch, cow, creeper) gates which entities get bait at all.

removeFakeMob (lines 248-261) despawns every attached FakeMob, clears the list and sets clientHasEntity false, which is also the reset path KABot's first branch depends on: once the client attacks and destroys the fake mobs or the entity is destroyed server-side, the tracking state returns to a clean slate. The class also drives the interpolated-location aging on onFlying (lines 58-85) that KACalc's offset math consumes.

What this file does

FakeMob is the planted entity itself. The constructor draws the entity id from 1,500,000,000 to 2,000,000,000 (the source comment explains that real server ids start at 1 and can exceed 15,000 on long-running servers, so the old 15,000-20,000 range was unsafe). spawn() builds a WrapperPlayServerSpawnLivingEntity with a random UUID and the given type, optionally ORs the invisible metadata flag 0x20 into entity data index 0, sends it only to the watching players, and registers the mob in the global fake tracker so the anticheat knows which ids are its own.

despawn() sends WrapperPlayServerDestroyEntities to the watchers and unregisters; move() emits relative WPacketPlayOutEntity moves and teleport() emits absolute WrapperPlayServerEntityTeleport. These are the packets the client actually receives, which is what makes the bait observable: a killaura sees a valid in-range entity and targets it, while the antibot filter sees an invisible, name-less, untabbed entity and marks it. The per-player mob bait that KABot's second branch watches is one of these objects, held on APlayer and respawned on world changes.
