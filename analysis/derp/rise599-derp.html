Overview

Rise 5.99's Derp is a pre-motion look spoof that overwrites the yaw the C03 stream will carry on every tick. In the default mode the pitch is left at the player's real rotationPitch while a module-owned yaw field accumulates a fixed constantSpeed (default 10, configurable 10-180 in 0.1 steps) with no wrapping, and that value is written into event.setYaw, renderYawOffset and rotationYawHead so both the wire look and the visible body spin. Three modifier toggles replace parts of the default: Random draws both axes fresh from uniform distributions every tick, Down pins the pitch around 80 degrees, Headless pins it around 180 (the upside-down look), and Twerk forces the sneak key on alternating ticks, which emits C0B sneak entity-actions instead of touching the look. The spin is a constant-rate frozen-axis rotation, which is exactly the signature the C0A-mined rotation checks (Photon AimStep and PerfectRotation) were built to flag; the Random mode is the only configuration that breaks their step and multiple signatures.

Rotation rewrite

The handler runs on PreMotionEvent, which fires before the C03 variant is built and sent. The default branch keeps pitch as mc.thePlayer.rotationPitch (the player's real pitch, static while idle) and adds constantSpeed.getValue() to the module's static yaw field every tick. The value is never wrapped or normalized: yaw simply accumulates past 360, so the raw look deltas on the wire are a constant +10 degrees per tick (or whatever speed is configured, always a 0.1-step multiple). event.setYaw(yaw) and event.setPitch(pitch) rewrite the look the packet carries, and renderYawOffset plus rotationYawHead are set to the same yaw so the server-visible body and the client-side head both follow the spun value instead of the real mouse input.

Mode matrix

Random overrides both axes every tick with Math.random() draws: pitch in -90..90, yaw in 0..360, so consecutive deltas are large, arbitrary and unrelated. Down pins pitch to 80 plus a small random fraction, producing a fixed near-downward gaze with sub-0.02-degree jitter while yaw keeps the constant spin. Headless pins pitch to 180 plus an even smaller random fraction, the classic upside-down look, again with yaw untouched. Twerk is the odd one out: it does not rotate anything, it calls keyBindSneak.setKeyPressed(ticksExisted % 2 == 0), forcing the sneak key state on alternating ticks, which makes the vanilla client emit C0B sneak entity-action packets every other tick. Because the module writes the static fields directly, the look mutates before the send, and nothing in the module ever swings or attacks, so no C0A originates from Derp itself.

Detection surface

The default spin is a textbook frozen-axis pattern: pitch delta exactly 0 while yaw delta is a constant step above 1 degree, which trips Photon's AimStep every tick, and the 0.1-quantized step is an exact multiple of 0.1 and (for 10, 20, 30) of 0.25, which trips PerfectRotation's multiple detector. The Headless and Down modes do not save it: their pitch jitter is bounded well under 1 degree and AimStep only needs the moving axis above 1, and the yaw delta stays an exact multiple. Random mode is the real bypass: both axes move by large arbitrary amounts, so neither the frozen-axis nor the integer-multiple signature exists. Hawk's AimbotHeuristic and intave's RotationSnapHeuristic miss the module by construction: Rise never wraps yaw, so the -176 to +180 discontinuity AimbotHeuristic keys on never occurs, and the spin's uniform motion triple fails RotationSnap's near-static before/after gates.

PreMotionEvent is the pre-send carrier for the tick's look and position. Its fields yaw, pitch, ground, x, y and z are set from the player state before the event fires, and the C03 send path reads them back afterwards, so any setter call made in a handler rewrites the packet the server receives. The class itself is a plain data holder with Lombok getters, setters and an all-args constructor; all of its logic lives in the consumers that fire it.

How it counteracts this module

Photon's PerfectRotation flags rotation deltas that are exact integer multiples of 0.1 or 0.25 degrees, using an epsilon of 1e-10 and a conditionallyIncDec counter so isolated matches decay instead of flagging. Real mouse input almost never produces exact multiples repeatedly, which is why the consistency requirement exists.\n\nRise's constantSpeed setting is stepped at 0.1, so every allowed value is by construction an exact multiple of 0.1 (10/0.1 is 100; 10/0.25 is 40), and the spin produces the same exact delta every tick, so the counter increments every tick regardless of which speed is configured. The Headless and Down modes leave yaw untouched, so they do not disturb the multiples. Random mode breaks the pattern because its per-tick draws produce arbitrary deltas that are only rarely exact multiples. The module's use of a quantized accumulator with no jitter is precisely what feeds this check.

How it counteracts this module

Hawk's AimbotHeuristic samples the last four to five raw yaw and pitch deltas computed as plain subtraction without shortest-distance wrapping, and evaluates them only when a click or world interaction happened within the last two moves. The twitching and zig-zag branch flags when both the current and previous speeds exceed 20 degrees and the angle between the move vectors exceeds 2.86 radians.\n\nThe Rise spin is invisible to it for a structural reason: the module never wraps its yaw, so the wire stream is a constant +10 per tick with an angle of 0 between consecutive deltas, which matches none of the branches. Random mode can occasionally trip the twitch branch (large random deltas with large angles) but only while the player is also clicking, and a pure spin with no combat stays under the check's gates. This entry documents the miss rather than a catch: the no-wrap design is a deliberate or lucky evasion of the wrap heuristic.

How it counteracts this module

intave's snap heuristic subscribes to ARM_ANIMATION (the C0A packet, which is why the check is mined under the animation corpus), ATTACK_ENTITY and USE_ENTITY, POSITION_LOOK and LOOK, and FLYING. The snap signature is a single-tick yaw jump between two near-static rotations: previousYawMotion under 9 degrees, the jump over 40, and the following motion under 9, gated on a swing or attack within 150ms, more than 10 rotation packets, and more than 7 ticks since a teleport. A second lite path flags silent movement with key-input changes.\n\nThe uniform spin defeats it on both gates. The motion triple is constant (10, 10, 10 at default speed, or any other constant), so the before/after thresholds of under 9 degrees fail even at the value boundaries, and the combat gate is closed anyway: the module never swings or attacks, so recentSwingOrAttack stays false. The lite path needs a change in the strafe or forward keys that the module does not produce. Like Hawk's heuristic, this entry documents the miss: intave's rotation heuristics target one-tick aimbot retargets, and a constant-rate derp spin is outside their intended signature.
