Analysis

Overview

Spicy's HideName rewrites the player's own username in inbound display packets. On every pre EventPacket it strips the separator character from S02PacketChat chat text and S3CPacketUpdateScore scoreboard names, and when the result contains the session username it substitutes a picked alias from a six-option ModeSetting. The mutation happens in place before rendering, so the server never sees the substituted name and nothing is echoed back. The module is purely cosmetic: it hides the player's identity in chat and on scoreboards while contributing nothing to the wire.

Architecture

The module carries one ModeSetting (Name) with the aliases You, MooshroomMashUp, Fox_of_floof, lavaflowglow and _Floofy_Fox_, surfaced as the module's additionalInformation line in the HUD. The EventUpdate pre branch only refreshes that display string; all real work sits in the EventPacket pre branch. Two packet types are handled: S02PacketChat, where the chat component is rebuilt if its text contains the username, and S3CPacketUpdateScore, where the objective name and the entry name are rewritten via setObjective and setName. The imports also list S3BPacketScoreboardObjective and S3DPacketDisplayScoreboard, but no branch touches them.

Rewrite mechanics

Every string check first strips the separator character with replaceAll, then tests the result for the session username; when found, the same strip-and-replace is applied to the formatted text with the username swapped for the selected alias. The separator is the tell for the module's era: servers and plugins began inserting it into names to break naive substring replacement, and the module strips it before matching and before rewriting so the substitution still lands on display. Because the packet objects are mutated in place before the client renders them, the server never learns that a substitution happened: S02 and S3C are inbound display state with no serverbound counterpart.

Wire profile

The module emits no serverbound packet of any kind and touches no movement state. Its handlers are receive-side only, so the checks that matter for a hidden-name setup are the ones that enforce everything else the player does: movement envelopes, toggle rates and teleport ledgers all operate unchanged while the module is on. The rewrite itself is invisible to every anticheat, because the substituted name never leaves the client.

What this file does

The module is two receive-side rewrites behind one EventPacket pre branch. For S02PacketChat it tests whether the unformatted text, after stripping the separator, contains the session username, and if so rebuilds the component from the formatted text with the username replaced by the selected alias. For S3CPacketUpdateScore it applies the same strip-and-replace to the objective name and the entry name fields. The ModeSetting is exposed as the module's additionalInformation line in the HUD, and resetSettings re-registers it so config loads cannot add stale settings.

The separator strip is the notable detail: it runs before matching and before rewriting, so a server that inserts the character into the player's name to break string replacement still gets its name substituted on display. The rewrite mutates the packet objects in place before rendering, which is why the server never learns of the substitution: S02 and S3C are inbound display state and nothing is echoed back.

The imports list S3BPacketScoreboardObjective and S3DPacketDisplayScoreboard, but no handler branch touches them; they are dead imports. The module emits no serverbound packet and touches no movement state, so it is invisible on the wire in both directions.

How it counteracts this module

TeleportQueue is the net-side ledger behind NoCheatPlus movement enforcement. The class javadoc states the contract directly: it queues outgoing teleport locations so that other moving is cancelled until the client acknowledges the previous teleport location. Every S08PacketPlayerPosLook the server sends is recorded, and the movement checks only process moves once the client's C03 stream confirms the teleported position.

HideName never touches the teleport stream. Its two packet handlers are receive-side rewrites of S02PacketChat and S3CPacketUpdateScore, and it emits no serverbound packet of any kind, so the ledger sees zero difference while the module is active. The queue matters for a hidden-name setup only through the movement modules that usually accompany it: speed and bhop desyncs generate lag-back teleports, and the client must acknowledge each one in order before further moves are processed, so any movement cheat that fails to confirm the teleport position is set back immediately.

The honest boundary: the name rewriting itself is invisible to every server-side check. No anticheat validates chat or scoreboard rendering, because the rewrite happens after the packets are decoded and only affects the client's display. TeleportQueue is listed here because it is the enforcement layer that remains fully in force for everything else the player does while hidden.

The boundary is complete on the display side: no anticheat can see the username substitution, because it never reaches the server. The three checks in this entry list are the enforcement that remains for the rest of the cheat setup, and none of them is weakened by HideName being on.
