Analysis

Overview

Nekoware v1's FastPlace is a byte-for-byte port of the Memeware 7.3 module: one @Handler-flagged Consumer on the lwjeb bus that writes mc.rightClickDelayTimer = 0 on every UpdateEvent. Vanilla's gate sets the timer to 4 at the top of rightClickMouse(), decrements it once per tick, and only fires the held-use branch while it reads exactly 0, so the module collapses the 4-tick action cooldown and lifts right-click placement from 5 actions per second toward the 20/s tick ceiling. The only differences from the Memeware original are the package name, the module display name ('FastPlace' without a space) and the Category.MISC registration line; the mechanism, the timing profile and the server-visible fingerprint (a denser C08 placement stream) are identical.

Architecture

The module is a constructor plus one public Consumer field. The constructor registers the module as 'FastPlace' under Category.MISC with key 0, and eventConsumer0 is marked with the lwjeb @Handler marker so the bus invokes its accept() on every UpdateEvent. The lambda body is a single assignment: mc.rightClickDelayTimer = 0. There are no settings, no onEnable/onDisable, no mode system and no other handlers, so the module has exactly one behavior and it is always on while toggled.

The vanilla gate

The same Minecraft.java touchpoints as the Memeware original apply in this fork: rightClickMouse() writes rightClickDelayTimer = 4 at line 1327, the run-tick loop decrements at lines 1453-1454, and the held-use branch at line 1791 requires the timer to be exactly 0 and the player not already using an item. The module's per-tick write lands between the decrement and the poll, so the cooldown never accumulates and each tick is eligible for a right-click action. The isUsingItem guard still prevents double-fire inside an active use animation, which means the gain is exactly the elimination of the 4-tick inter-action wait.

Server-side effect

As with the Memeware parent, the observable effect is a placement-rate change, not a packet-content change: sustained right clicks collapse from one C08PacketPlayerBlockPlacement every 200ms to one per tick (sub-50ms scatter at full CPS), and the same cadence applies to item use. Because the payloads are vanilla-faithful, the module is only detectable through timing statistics, which is what makes the placement-rate family of checks (NCP's FastPlace window, short-term tick counters) the relevant countering surface rather than any payload validation.
