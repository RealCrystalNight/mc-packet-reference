Analysis

Overview

Sigma's FastPlace is a two-line EventTick handler that clamps mc.rightClickDelayTimer to a maximum of 1 every tick, the classic 1.8 right-click delay bypass. The vanilla gate in the fork's Minecraft.java arms the timer at 4 on every rightClickMouse call, decrements it once per game tick, and only lets the held-use branch fire while it sits at zero; the clamp collapses the 4-tick cooldown to a single tick, lifting placement and item-use cadence from the vanilla 5 per second toward the 20-per-second tick ceiling. The module constructs no packets of its own: the C08 placement stream is emitted by the vanilla PlayerControllerMP path that the timer gate throttles.

The vanilla gate

rightClickDelayTimer lives entirely in Minecraft.java: rightClickMouse() writes 4 at its top, the run-tick handler decrements it once per tick (lines 1499-1500), and the keyBindUseItem branch fires rightClickMouse() only when the timer reads zero and the player is not already using an item (line 1833). Each fire re-arms the timer at 4, so vanilla allows one use every four ticks, five per second. Sigma's EventTick fires from the top of EntityPlayer.onUpdate each tick, and the clamp Math.min(rightClickDelayTimer, 1) keeps the cooldown at a single tick, so a held right click re-fires the use path every tick instead of every four.

Dead configuration

The KEY_TIMES = "CLICKSPEED" constant is declared as a private static field but the constructor never registers it into the settings map, so no CLICKSPEED option exists in the GUI and the clamp runs unconditionally whenever the module is enabled. This is the same dead-setting family as the DROP toggle in the sibling AutoSoup, which is also registered but never read. The module has exactly one live behavior: the per-tick clamp.

Wire effect

With the clamp active, a held right click re-arms the placement path every tick, so PlayerControllerMP emits C08PacketPlayerBlockPlacement at up to the 20-per-second tick ceiling. Real block placements travel with a block face and coordinates, while the use-item form (facing 255 with a stack payload) is what food, potions and empty-hand uses emit; both are throttled by the same timer. The packet itself is vanilla, the module only removes the spacing, which is why the countering surface is the placement rate the server can measure rather than any packet the module fabricates.

What this file does

The module file is the complete implementation: an EventTick handler that runs Math.min(mc.rightClickDelayTimer, 1) once per tick. The clamp is a ceiling, not an assignment: it only ever lowers the timer, so a fire that sets 4 is immediately capped at 1 and the next tick's decrement reaches zero, re-enabling the use branch. The KEY_TIMES constant documents the intended CLICKSPEED slider that was never wired into the settings map.

Because the module sends nothing itself, the analysis rests on the fork vanilla gate: rightClickMouse() writes 4 (Minecraft.java line 1372), the run tick decrements once per tick, and the held-use branch requires the timer to read zero. The clamp compresses that four-tick cycle into one tick, which is the entire cheat.

How it counteracts this module

NCP's blockplace FastPlace is the direct counter to this module's only effect, the placement rate. It fires from the Bukkit BlockPlaceEvent path (BlockPlaceListener.onBlockPlace), so only real block placements reach it: use-item C08s with facing 255 and air coordinates never do. The long window is fastPlaceBuckets = ActionFrequency(2, 1000) against a 15-per-second limit (DefaultConfig line 184), and a short-term counter allows 6 placements inside 10 ticks (fastPlaceShortTermLimit and fastPlaceShortTermTicks) with cancel actions from vl>5.

The clamp's 20-per-second ceiling sits above the 15/s window, so a sustained placement burst while the module is on accumulates violations, and the 6-in-10-ticks short-term test is the faster trigger for click bursts. The honest boundary is human: the module permits up to 20/s but a real player rarely sustains that with actual block placement, so the check scores the sustained stream more reliably than occasional fast clicks.

How it counteracts this module

Direction validates the placement's declared facing against the player's actual look ray. It is an AbstractBlockDirectionCheck that accumulates a face-to-ray distance into a violation value with a 0.9 decay on valid hits, so placements whose declared face disagrees with the reported look build up. The module does not touch rotations at all, so a player who strafes or sweeps the cursor while spamming placements feeds the check exactly the mismatch it scores; placements made while standing still and looking straight at the target face stay within the decayed tolerance.

This makes Direction orthogonal to the rate check: it catches the moving-cursor placement spam that FastPlace's window also sees, while a stationary fast placer is invisible to it. The two NCP blockplace checks together cover rate and geometry, which is why a fastplace module that also spoofs its look (this one does not) is the harder target.

How it counteracts this module

Arc v2's BLOCK_PLACE packet listener does not validate placements at all: the only C08 logic in the tree is the MUSHROOM_SOUP AUTO_HEAL branch (PacketListener lines 134-142), which watches soup consumption for instant-consumption servers. There is no placement-rate, direction or reach check in Arc v2's blockplace handling, so a fastplace module faces nothing from this anticheat on the placement stream itself.

The entry is an honest gap: the real Arc v2 pressure on a fast placement player comes from the movement layer (its Flight and speed handling), not from anything that inspects the C08 stream. Servers running Arc v2 need the NCP or Hawk checks for placement rate, which is why the direct counters in this set are NCP.

How it counteracts this module

BlockInteractSpeed is Hawk's terrain-interaction rate check and it is an honest boundary for this module: it punishes only when two block interactions land in the same server tick (currentTick == lastPlaceTick after an InteractWorldEvent), the double-place signature of instant-click hacks. The rightClickDelayTimer clamp caps the client at one placement per tick by construction, so the module can never deliver two interactions in one tick and the punish branch never fires; the one-per-tick stream is exactly what the check rewards.

The check does score the misuse cases around fastplace: a module that removes the cooldown entirely and raw-sends placement pairs produces same-tick doubles and trips it, and combined with the NCP window it covers the placement-rate family from both sides. Sigma's conservative clamp stays under both, which is the honest framing: the module's 20/s ceiling is caught by NCP's 15/s window, not by Hawk's same-tick test.
