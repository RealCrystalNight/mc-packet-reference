Overview

Freelook is a ghost-category camera module that decouples the rendered view from the server-visible rotation. While the bound key is held it steals the mouse deltas that vanilla would fold into rotationYaw and rotationPitch, accumulates them into its own lastYaw and lastPitch fields through the vanilla sensitivity gain curve, and forces third-person view. The player's actual rotation never changes, so the C03 look stream is frozen at the enable-time values and every attack-side rotation check sees a perfectly static stream. The comment in the source is explicit about the intent: looking around in vanilla third person changes the wire rotation and legit players get flagged by rotation checks while doing it, and this module exists to prevent that. The only packet interaction is receive-side: an S08 teleport with a forced look re-anchors the camera origin so the view does not snap back after the vanilla handler applies the new look.

Camera versus wire rotation

The split is the whole design. onEnable snapshots rotationYaw, rotationPitch and the third-person view mode; onRender2DEvent, which fires every render frame, reads mc.mouseHelper.deltaX and deltaY, scales them by f1 = (mouseSensitivity * 0.6 + 0.2)^3 * 1.5, the vanilla mouse-look gain curve, and adds them to lastYaw and lastPitch with the pitch clamped to +-90 degrees. None of that touches the player's rotation fields, so the server-side look, and every C03 look field derived from it, stays constant for as long as the module is held. handleInput() returns the enabled state so the fork's EntityRenderer can skip the normal mouse-look path and drive the third-person camera from the module's fields instead; the 5.99 snapshot has no net/minecraft tree to show that hook, but the contract is unambiguous. Because 1.8 getMouseOver ray-traces from the player rotation rather than the camera, Freelook grants no aim advantage: it is a pure awareness tool.

S08 re-anchor

The single packet handler runs on the receive side. When an S08PacketPlayerPosLook arrives with a forced look, the vanilla handler writes its yaw and pitch into the player rotation and the client replies with a C06 ack. The module reads the same values and stores them as the new originalYaw and originalPitch, so the camera origin follows the forced look and the view does not snap back to a stale anchor after a teleport or set-back. The packet itself is neither cancelled nor modified, so the ack flow and the server-side teleport ledger behave exactly as vanilla.

Lifecycle

The module is hold-to-activate: onRender2DEvent toggles itself off whenever the key is released or no key is bound, which is what makes the accumulation loop self-terminating. onDisable restores the original rotation and the previous third-person view mode, so the camera returns exactly to where it was. The Invert Pitch setting negates the snapshot pitch on enable, flipping the camera's vertical origin. The mouse-delta accumulation runs per render frame rather than per tick, so camera speed scales with framerate, a client-side artifact that never reaches the wire.
