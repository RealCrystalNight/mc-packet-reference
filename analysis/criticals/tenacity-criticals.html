Overview

Tenacity 6.0's Criticals makes melee attacks land as crits by queueing C03 position-lift packets that claim a small upward offset with onGround false before the attack, so the server-side entity carries fall distance when the C02 arrives. The Watchdog mode (default) fires on every grounded MotionEvent and queues two lifts, 0.06 plus random jitter and 0.01 plus random jitter; the Packet mode gates three sub-pixel lifts, 0.006253453, 0.002253453 and 0.001253453, behind an on-ground target check and a hurt-resistance threshold. The Dev mode is present only as commented-out source that would add a fourth lift and a C18PacketSpectate with a random UUID. The module never sends the attack itself; it services the player's normal C02 clicks by pre-arming the fall distance.

Watchdog mode cadence

Watchdog runs from the MotionEvent listener with no attack gating at all: whenever e.isOnGround() is true it queues two C04PacketPlayerPosition packets at the current position plus 0.06 plus a random value below 0.001, and the same plus 0.01 plus jitter, both with onGround false. Because the event fires every tick while the player is grounded, the mode produces a continuous two-lift-per-tick stream that keeps the server-side fall distance nonzero at all times. The 0.06 lift is above the 1.8 minimum-move threshold of 0.03, so the server actually moves the entity up, while the 0.01 lift sits below it and only applies the onGround flag.

Packet mode gating

Packet mode adds three conditions before lifting: the object mouse-over must target an entity, the local player must be onGround, and the target's hurtResistantTime must exceed the Delay setting (default 1, range 0-20). When those hold it queues three C04 lifts at 0.006253453, 0.002253453 and 0.001253453, all below the 0.03 min-move, so the server ignores the coordinate deltas but applies the onGround false flag to each. The mode therefore produces the flag-only ground spoof signature rather than a visible position change, and the Delay setting doubles as the hurt-time threshold that spaces lift bursts around the hittable window.

Dead code and unused state

The Dev branch is fully commented out: it would queue four offsets up to 0.06253453 and then a C18PacketSpectate carrying a random UUID, a spectate packet that has no business in a criticals module and is the kind of leftover that points at a paste lineage. The TimerUtil field timer is declared but never referenced anywhere in the file, and PacketUtils is imported yet only the dead Dev branch would call sendPacketNoEvent; the live modes queue through mc.thePlayer.sendQueue.addToSendQueue directly. These are honest dead-code findings: the shipped module is Watchdog plus Packet, nothing more.

How it counteracts this module

NCP's fight.Critical runs whenever the server sees a crit delivered, and its rule 3 is the direct hit on packet lifts: it compares NCP's own fall-distance accounting, derived from real physics, against the fall distance the client's movement claims, and flags when the divergence exceeds 1e-5 while the move's origin is on ground or the touched-ground workaround applies. The Tenacity lifts claim onGround false from a standing position, so the server-side fall distance is fake by construction and the divergence check fires on the first crit after a lift burst. The jump-phase rule 2 also engages for the 0.06 Watchdog lift: a crit delivered while sfJumpPhase sits in 1..maxJumpPhase with no real jump motion is too early in a jump, and NCP's own comment notes SurvivalFly catches the low-jump shape.

The sub-pixel Packet-mode offsets are the honest gap: NCP's envelope machinery never sees them because they fall under the 0.03 min-move, so the coordinate delta is zero to the checker and only the flag is applied. Those modes are fought by the combat-side checks that read the attack itself rather than the movement, which is why the Arc and Hawk entries below matter for the Packet mode specifically.

How it counteracts this module

Grim's groundspoof.NoFall validates the onGround flag against collision: on a PLAYER_FLYING or ROTATION packet claiming onGround true without a position change, it expands the feet box by the movement threshold, and with no vertical collision it flags, sets back ten blocks and rewrites the claim to false. That is the mirror of what Tenacity does: the module claims onGround false while standing, so the flag-only sub-pixel lifts produce a stream of false ground claims that Grim's post-prediction ground check sees as a player who never lands.

The honest reading is that NoFall's true-claim direction is aimed at the Sigma-style Minis family that spoofs onGround true to avoid fall damage, while Tenacity's false-claim direction surfaces in Grim's prediction pipeline as a consistency problem rather than this specific check. The lift pattern is still visible to the prediction engine through the flag stream, and the position-bearing 0.06 Watchdog lift is subject to the full movement prediction on the next position update.
