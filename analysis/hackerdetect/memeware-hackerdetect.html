Overview

Memeware 7.3's Hacker Detect is a client-side observer that scans other players' rendered state for one anomaly: an out-of-range pitch. A single UpdateEvent handler iterates mc.theWorld.loadedEntityList every tick, and for each EntityPlayer other than the local player that has existed for more than 50 ticks, it checks whether rotationPitch falls outside [-90, 90]; offenders are reported with a '[MAC]'-tagged client-side chat line via ChatUtil.printChatFlag. The module reads only the client's own entity list - the state that arrived via spawn, entity-look and teleport packets - and emits no packets of its own, so its reports are local-only observations. The more ambitious speed heuristic (one-block-per-tick movement with ice-exemption logic) exists in the source only as commented-out code, and the isMoving helper it would use is never called.

Architecture

The module is one @Handler Consumer<UpdateEvent> plus an EntityLivingBase field reused as a scratch reference. Every tick it iterates the loaded entity list, skips anything that is not an EntityPlayer, skips the local player, and skips players with ticksExisted <= 50 - a grace period that keeps freshly spawned entities out of the check. The single active test is the pitch range: rotationPitch < -90 or rotationPitch > 90 triggers ChatUtil.printChatFlag with the offending player's name and a canned message. The imported movement utilities (MovementUtils), the ice-block and BlockPane types, and the isMoving helper are all vestiges of the disabled speed heuristic, which the author left in place as a comment block marked 'fixing my cancer code here later, lazy rn'. The module holds no per-player state, so the same player is re-flagged on every tick for as long as the bad pitch persists.

What the check actually observes

The rotation values come from the client's own entity simulation, not from any packet the module reads: other players' yaw and pitch are updated client-side from the spawn packet (S0C), entity-look/move packets (S14 family), and teleports (S18), each carrying byte-encoded angles that the client decodes into degrees. The pitch bound it enforces matches the vanilla server-side constraint, but the client never clamps remote entities, so a server or a hacked client that transmits an out-of-range pitch leaves the value visible in the world state - which is what the module detects. The comment block shows the intended second check: flag players whose x or z position moves more than 1 block per tick over non-ice ground while moving and visible, i.e. a crude speed threshold - but that path is dead code in this build. The output channel is printChatFlag, which renders the report locally with a '[MAC]' prefix and never sends a packet.

Wire behavior

Hacker Detect produces no network traffic of its own: it is a pure reader of client-side world state and a local chat renderer. That makes it invisible to server-side anticheats by construction - there is no packet, timing pattern, or server-visible state change to detect, and the module cannot even be inferred from the outside since its reports never leave the client. Its practical value is equally limited: it re-implements, on the observing client, a single narrow check that real anticheats already run server-side against each player's own movement packets, and it only sees what the server already accepted and broadcast. The commented-out speed check would have been equally redundant: the same '>1 block per tick' heuristic is the core of server-side speed validation, minus the ice and piston exemptions the comment block half-remembers.

How it counteracts this module

AimbotPrecision is the real rotation-validity check in Hawk's look package, and it shows how shallow the client module's pitch-range test is by comparison. The check collects absolute pitch deltas per player, keeps only deltas between 0 and PITCHRATE_LIMIT (0.96 by default) excluding exact +/-90 (lines 79-82), and once SAMPLES (default 10) are gathered computes the rational GCD of the samples via MathPlus.gcdRational (lines 88-90). A GCD that drifts by more than 0.001 from the player's previous GCD fails after one retry seeded with the prior value (lines 93-106), and a GCD below 0.00001 - 'practically unsolvable' - fails outright (lines 109-111). The theory is that human mouse sensitivity quantizes every rotation delta to multiples of a constant, so aim-assist rotations produce a mathematically impossible GCD.

For this module the relationship is illustrative rather than adversarial: Hacker Detect's pitch-range test is a crude client-side echo of the property class these checks police, catching only values the server already treats as impossible. AimbotPrecision catches the smooth, quantized rotations that a range test can never see, and it does so server-side on the cheater's own packets. How it counteracts this module

Hawk's Speed check is the server-side realization of the heuristic the module's author left commented out. It predicts each move from the previous speed, friction, jump/step state, knockback acceptance, and touched-block multipliers (soul sand, hit slowdown, item-use force limits), and accumulates the discrepancy between predicted and actual movement; when totalDiscrepancy exceeds DISCREPANCY_THRESHOLD (default 0.1) and the move is not a possible piston push, the player fails (lines 203-209). The position-only path even clamps stale speeds to MAX_NO_MOVE_DISTANCE so that a player who stopped updating position cannot bank speed (lines 92-96).

The module's dead code approximated the same idea with a 1-block-per-tick threshold over non-ice ground - vastly cruder, missing friction, knockback, pistons, and vertical movement entirely, and it was never enabled. The honest framing is that even if the author had finished it, the check would only have duplicated, at lower fidelity, what Speed already does server-side against the same movement packets. Like the pitch check, it would have consumed zero additional packets, so the module's detectability remains nil; the countering value of Speed here is as the reference implementation the client's stub was reaching toward.
