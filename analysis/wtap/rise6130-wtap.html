Analysis

Overview

Rise 6.1.30's WTap is a two-mode sprint-reset module. The Legit mode drives the real sprint keybind, so the player's own sprint state visibly drops and the vanilla sprint logic emits the C0B entity actions; the Silent mode flips the sprint flag of the PreMotion event, which the patched EntityPlayerSP converts into serverbound C0B packets while the client's own motion never changes. The facade declares the mode value, defaulting to Legit, and the shared chance setting gates every reset. Both modes key off the target's hurtTime, so a reset only fires in the ticks right after a landed hit, which is what makes the module a knockback amplifier rather than a plain sprint toggle.

Facade and gating

The module class holds a ModeValue with the Legit and Silent modes and the NumberValue chance setting used by both. There is no other logic in the facade; the two mode classes register their own event listeners when selected. The chance value is rolled independently at every decision point, so a reset can be armed on the attack but skipped at the release step, and vice versa.

Legit mode

LegitWTap's AttackEvent handler arms the reset when the roll passes and the target's hurtTime is at least 6, meaning the hit has already landed and the target is in its hurt animation. If the player is sprinting, the handler presses the sprint keybind (setPressed(true)) and latches the unsprint flag. The PreMotion handler then releases the keybind on another chance roll. The release runs through the vanilla sprint logic, so the client's own sprint state ends, C0B STOP_SPRINTING goes out, and the next sprint start re-asserts C0B START_SPRINTING; the player's speed genuinely dips for the reset ticks, which is the W-tap effect.

Silent mode

SilentWTap keeps the target from the AttackEvent and, in PreMotion, sets the event's sprint flag to false while the target's hurtTime is exactly 9, the tick after the hit lands. The keybind and the client's own sprint state are untouched. EntityPlayerSP.onUpdateWalkingPlayer (lines 194-204 of the patched client) compares the event flag against serverSprintState and emits the C0B START or STOP action whenever they differ, so the server sees a sprint stop followed by a sprint start straddling the attack while the client's own motion never drops. The module holds no state beyond the target reference, and the flag write is the entire intervention.
