Analysis

Overview

Tenacity's Regen is a two-mode health-regeneration exploit that only fires while food is above 3 and health is at or below a configurable threshold. The Vanilla mode pushes five flag-only C03(true) packets per tick through PacketUtils.sendPacketNoEvent; the Vifa mode first teleports the local player to y = -999, waits for the client's ground flag to go false, then floods twenty C04 position packets re-asserting the pre-teleport position with onGround false and snaps back with setPositionAndUpdate. Both modes lean on the same server-side fact: the 1.8.9 natural-regeneration timers are gated on the player's onGround flag, so re-asserting ground keeps the regen timers running. A 'teleported' latch gates the Vifa sequence and resets on disable.

Architecture

The module carries a two-option ModeSetting (Vanilla default, Vifa), a NumberSetting health (1-20, default 1) that sets the health ceiling, and a boolean teleported latch. The single MotionEvent listener switches on the mode and gates both branches on foodLevel above 3 and health at or below the threshold, so the exploit only runs while the player is hungry-viable and hurt. onDisable clears the latch; the listener resets it whenever the gate fails, so the Vifa sequence always restarts from the teleport step.

Vanilla mode

While the gate holds, the Vanilla branch loops five times calling PacketUtils.sendPacketNoEvent(new C03PacketPlayer(true)) — five flag-only C03 packets per tick that claim ground and change nothing else. sendPacketNoEvent routes through the packet event bus silently, so the sends bypass any module that listens for outgoing packets. One accuracy note: in this source snapshot the utility's send body is stubbed empty (only an mc.thePlayer null check), so the Vanilla branch is inert in the dump; the send-queue path the Vifa branch uses is live. The branch as written intends 5 ground-claim packets per tick, roughly 100/s at 20 TPS.

Vifa mode

The Vifa branch runs a two-step sequence. Step one, on the first tick the gate holds: setPosition(posX, -999, posZ) teleports the local player into the void, and once the client's onGround flag goes false the latch flips. Step two, while latched: twenty C04PacketPlayerPosition packets re-assert the pre-teleport lastTickPos with onGround false, then setPositionAndUpdate snaps the client back to its real position. The server-visible fingerprint is a massive Y excursion to -999, a twenty-packet burst re-asserting the stale position, and a snap-back — the classic teleport-down-and-flood shape used to break the server's fall-distance and movement accounting.

Server-side regen link

The 1.8.9 server's FoodStats.onUpdate runs both natural-regeneration paths off the server entity's onGround flag: the saturation path (food level at 20 with saturation above zero) heals every 10 ticks, and the food path (food at 18 or above) heals every 80 ticks, each adding exhaustion — and any tick where the flag reads false resets the timer. The C03 flood's onGround-true claims keep that flag asserted even while the client moves or jumps, so the regen timers never reset mid-flight. That is the module's entire lever: uninterrupted regeneration while mobile, with the saturation path delivering the fast 10-tick heal cadence whenever food and saturation allow.

How it counteracts this module

Vrekt's Regeneration check measures the time between health events. FightData records the timestamp of the last health event, and check() computes timeSince = now - lastHealthEvent, flagging "regeneration time too fast" whenever that interval falls below the configured regenerationTime, default 3400ms. The check is deliberately simple: vanilla natural regen has a hard 80-tick (4 second) floor on the food path, so any health gain arriving inside the 3.4 second window is impossible without help.\n\nThe module feeds exactly that window. With food at 20 and saturation available, the saturation path heals every 10 ticks — a 500ms interval, seven times faster than the check's limit — and because the module keeps the ground flag asserted, those heals keep arriving while the player moves, which vanilla would otherwise interrupt. Every such heal registers as a health event inside the 3400ms window and accumulates violations. The check's tolerance is the window itself: pure natural regen on the 80-tick path (4000ms) sits just outside it, so the check only engages when the regen cadence is actually compressed.

How it counteracts this module

Grim's Timer adds 50ms of balance to the player clock for every counted tick packet and flags whenever that balance outruns System.nanoTime, anchoring the clock to the player's ping via C0F transactions and PONG. How it counteracts this module

Hawk's FastFall bounds vertical speed.
