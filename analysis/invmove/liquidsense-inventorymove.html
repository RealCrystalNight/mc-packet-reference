Overview

LiquidSense Dev's InvMove keeps the player moving while a screen is open by re-asserting the raw keyboard state into the movement keybinding pressed flags on every UpdateEvent. The handler excludes GuiChat and the pause menu outright, and the NoDetectable switch adds a second carve-out: when it is on, the current screen must not be a GuiContainer, so movement only survives on non-container screens. The AACAdditionPro switch is a display tag only and changes nothing in the handler, and the NoMoveClicks switch cancels every ClickWindowEvent while the player is moving so the forced walk cannot be paired with a GUI click. The wire fingerprint is the same as every inventory-move module: the C03 position stream keeps advancing while a server-side container is open.

Input-path bypass

The module never touches packet code. onUpdate fires once per tick and, when the screen guard passes, writes GameSettings.isKeyDown(keyBindForward) into keyBindForward.pressed for forward, back, right, left, jump and sprint. The vanilla input classes read those flags (MovementInputFromOptions calls getIsKeyPressed), so the player entity keeps producing movement input while a chest, furnace or inventory screen has focus. Because the write happens on the pre update event, the forced state is in place before the tick's movement is computed, and the C03 variant that tick carries nonzero position deltas. The NoDetectable carve-out inverts the guard: with the switch on, the handler only runs when the current screen is not a GuiContainer, which excludes exactly the container screens the inventory-move checks watch.

Click suppression and cleanup

NoMoveClicks is the anti-mistake companion: onClick cancels any ClickWindowEvent while MovementUtils.isMoving() reports forward or strafe input, so a player holding W cannot accidentally shift-click an item out of a moving inventory. onDisable releases every forced pressed flag, but only when the physical key is up or a screen is still open, so the cleanup cannot fight an active key press. The jump and sprint bindings are part of the forced set, which is what makes the module heavier than a walk-only InvMove: the server sees jumps and sprint transitions under an open window, not just horizontal drift.

Server-side view

Vanilla clients freeze in place under a screen because the GUI swallows the movement input. The module's forced flags make the server receive position-changing C03 packets, sprint-state C0B packets and movement for a player whose server-side window is still open, a contradiction the inventory-move checks validate. CheaterDeleter flags position changes under a live screen handler, Photon scores movement past a breaking-time leniency and any jump, Negativity scores distance and sprint and sneak transitions from Bukkit events, and Hawk flags rotation, sprint or sneak while an inventory is open.

What this file does

The module is a single UpdateEvent handler plus one ClickWindowEvent guard and a cleanup routine. The screen condition combines three checks: the current screen must not be GuiChat, must not be GuiIngameMenu, and when NoDetectable is enabled must not be a GuiContainer. When it passes, the six movement keybindings are re-asserted from GameSettings.isKeyDown, which polls the physical keyboard directly and bypasses the GUI input path entirely. The NoMoveClicks handler then cancels window clicks while movement input is present, and onDisable only clears the forced flags when the key is released or a screen remains open. The tag getter is the AACAdditionPro switch's only effect: it appends the AACAdditionPro label to the module name in the module list.

How it counteracts this module

CheaterDeleter's check runs on every serverbound move through PlayerMovementListener.onMovement and keys on the exact module signature: packet.isChangePosition() while player.getCurrentScreenHandler() != null (lines 41-48). After a 500ms grace from the moment the screen opened (lines 58-59), invalidateMove flags when a horizontal delta grows while the server-side velocity on that axis is zero (lines 62-77), which is precisely what forced keybind input produces. The flag is MINOR severity with a 100ms cooldown, and the data resets on window close and on damage (onPlayerDamage extends the grace by 1000ms, lines 99-104). The module's sustained WASD movement past the grace drives deltas that grow against zero server velocity, so the check flags on steady use. Movement that rides server-applied velocity (knockback, a moving platform) or movement confined to the first 500ms after opening does not trip it, and the check skips players near non-solid collision and in spectator.
