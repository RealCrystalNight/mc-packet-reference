Analysis

Overview

Mint B1's Disabler is a single 791-line kitchen-sink packet interceptor. One onEvent(Event) method branches on EventReceivePacket, EventSendPacket, EventMotion and EventUpdate and applies whatever subset of its roughly 45 settings are enabled. Modes are named for the anticheats and servers they target (Hazel, NCP, Kauri, Karhu, Vulcan via the vulcanyaw field, Verus, Spartan, Matrix, Watchdog2020, PurplePrison, Redesky, Warzone, Zonecraft, MineLatino, Supercraft) plus a row of generic packet primitives: C00 keepalive key rewriting, C0F transaction corruption and delay, C0B entity action spam, C07 digging spam, C08 placement spam, C13 abilities injection, C16 respawn spam, C18 spectate spoofs and C0C input spoofs. The dominant technique is queue-and-flush: a packet is cancelled at the event layer, parked in one of three ConcurrentLinkedDeque queues, and released in a burst through sendPacketNoEvent on a timer, so the server receives everything late and out of phase. The file also carries a heavy load of dead code, unreachable branches and at least one guaranteed ClassCastException.

Architecture

All logic lives in onEvent(Event), which dispatches on instanceof for the four event types. State is spread across three ConcurrentLinkedDeque packet queues (a general queue, a C0F-only queue used by the Warzone mode, and a C00-only queue that is never written or read), a single Timer object exposing three independent millisecond clocks (hasTimeElapsed, hasTimeElapsed2 and hasTimeElapsed3), and a handful of booleans. Cross-module communication goes through public statics: hypixelStrafe and desyncrot are written here and consumed elsewhere in Mint, and vulcanyaw doubles as a scratch register, with the NCP motion code storing a jump or sneak offset in it and the Kauri mode reading it back as a yaw. The constructor registers all 45 settings, ending with the cosmetic ModeDisplay mode list, whose only consumer is displayInfo for the HUD label.

Key techniques

The queue-and-flush pattern appears in nearly every mode: cancel the packet, park it, and release the backlog through sendPacketNoEvent on a timer, or re-send it later through the threaded sendPacketNoEventDelayed helper. Flush intervals are per mode: 15 seconds for Watchdog2020, 400ms for Verus, a random 1 to 2 seconds for the shared Redesky/Spartan block, ~5418-5424ms and ~1343-1349ms for Warzone's two queues, 690ms (2500ms for C00/C0F) for Zonecraft, 1550ms (1565ms after a C02) for VerusCombat and ConfirmTransaction, 505ms and 200ms for MineLatino and Supercraft, and a 120-tick flush for Hazel. Field corruption rewrites C0F uid to 1337 and id to 69, C00 keys to 1337, and C13 packets to claim flying, creative and invulnerable. Movement bypasses add constant y drift (Karhu 0.015625, Redesky 0.000125), send mirrored C04 position pairs 9 blocks ahead and behind (NCP), or alternate C03 onGround to tick parity while airborne (Zonecraft). The receive side cancels S08 teleports and re-sends them as C06 (Redesky, NCP), nudges S08 y by 1.0E-4 (SpigotData), and cancels S12 velocity (Redesky).

Code quality

The file is accretion-heavy: settings like HypixelTimerTest, Test, Spartan and watchdog are declared with UI labels but their handlers are empty or absent; packetQueueC00Only, the x/y/z/yaw/pitch fields, transactiontype, placetype and matrixswitch are dead; and getXZDifference is called with packet.x twice, a copy-paste bug whose results are never read. The Hazel mode casts a C0F transaction to C00PacketKeepAlive, which throws ClassCastException the first time the branch runs, and the NCP module scan compares module names with == instead of equals(). The PurplePrison else branch is unreachable, so its C0F-cancel and void-position phases never execute. The ModeDisplay setting is a 31-option mirror of every toggle, used only for the HUD label.

What this file does

This is the module's only file. Everything is driven from onEvent(Event), which fans out on instanceof: EventReceivePacket and EventSendPacket carry the raw Packet objects, EventMotion carries the movement that the vanilla client turns into C03 packets, and EventUpdate carries the pre/post tick hooks used by the spam toggles. State lives in three ConcurrentLinkedDeque queues (packetQueue, packetQueueC0fOnly and packetQueueC00Only, the last one never used) and a single Timer whose two clocks back the independent flush intervals the Warzone mode needs. Several statics leak state to the rest of Mint: hypixelStrafe and desyncrot are consumed by other modules, and vulcanyaw is a float reused as a scratch register between the NCP and Kauri modes, so enabling NCP while Kauri is on feeds Kauri a jump or sneak offset instead of a yaw.

The dominant primitive is queue-and-flush. A mode cancels the event, parks the packet in a queue, and later dumps the backlog through sendPacketNoEvent (which bypasses the event layer) so the server still receives everything, just late and in bursts. Watchdog2020 keeps every C0F transaction for 15 seconds; Verus holds every serverbound packet for 400ms and rewrites each transaction id to 69; the Redesky/Spartan pair shares a random 1000*(Math.random()+1) millisecond window; Warzone splits C00 keepalives and C0F transactions into two queues flushed on hasTimeElapsed(5412+((Math.random()+1)*6)) and hasTimeElapsed2(1337+((Math.random()+1)*6)); VerusCombat and ConfirmTransaction hold C0F packets for 1550ms, 1565ms right after a C02 use-entity, via sendPacketNoEventDelayed, which sleeps a thread and then sends; MineLatino and Supercraft delay every packet 505ms or 200ms the same way (chat messages excluded); Zonecraft delays everything 690ms, or 2500ms for C00/C0F, and permanently slows the game timer to 0.8; Hazel queues into the general queue and flushes every 120 ticks.

The corruption modes aim at the server's transaction and keepalive validation. NetHandlerPlayServer.processConfirmTransaction only re-enables crafting for a window when the packet's uid (the action counter) matches the server's expected value and its id matches the open container's windowId, so C0FData stamping uid=1337 with accepted=false guarantees that check never passes, and Verus stamping id=69 guarantees the window id never matches (the player inventory is window 0). C00Key rewrites the keepalive key to 1337, which never equals the server's current key, so processKeepAlive never updates the ping; vanilla 1.8.9 has no disconnect on a wrong key, so the mode targets anticheat keepalive checks. Watchdog2020 and Hazel both shadow every C03 with a fresh C13 abilities packet and force flags on outgoing C13s, but the server computes isFlying = flying && allowFlying, so claiming flight without allowFlying is inert against vanilla and aimed at anticheat state tracking. C16 PERFORM_RESPAWN spam is a no-op while the player has health (processClientStatus returns early), and C18 spectate spoofs with random UUIDs are only processed for actual spectators, so both toggles exist to pollute the anticheat's packet stream rather than to change vanilla behavior.

The receive side is smaller. HypixelStrafe flags watchdogStrafed on the first S08 after terrain load and then cancels every serverbound packet except C06 confirmations, so the server only ever sees the C06 stream. SpigotData nudges every received S08 y by 1.0E-4. The NCP branch echoes the S08 destination back as a C06 with onGround=true so the server sees the teleport accepted, computing acceptedX and acceptedZ booleans that are never read. Redesky cancels S08 teleports, re-sends the position itself as C06 with the client's real onGround state, and cancels every S12 velocity packet to freeze knockback.

The movement modes mutate EventMotion or inject extra packets. Karhu adds 0.015625 to the event y every tick; Redesky adds 0.000125 while ticksExisted stays below 69 after terrain load; Zonecraft flips the C03 onGround flag to tick parity while airborne; PurplePrison adds 0.015625 to every C03 y once ticksExisted passes 60; MatrixSemiStrafe adds a sub-millimeter sin(yaw*0.001) jitter to x and z on alternating ticks; VoidTP forces the motion y to -1 every 20 ticks; Kauri pins the event yaw to vulcanyaw, snaps it to -3141 on even ticks, and teleports the player locally with MoveUtil.packetComedy(-0.1, 0) (a setPosition call, no packets) while movement keys are held; and NCP, when any movement module or Fly specifically is enabled, injects a mirrored pair of C04 positions 9 blocks ahead and behind along the current yaw, with the forward hop's y offset by 5, -5 or 0 according to the jump and sneak keys. VerusLatestFly records groundpos while grounded and, while airborne, spams C08 stone placements at posY minus groundpos to fake a scaffold under the player.

The generic spammers run from EventUpdate. Interact finds the nearest living entity farther than 1 block and sends C02 INTERACT every even tick; EntityAction sends the C0B action selected by EntityActType every tick, defaulting to RIDING_JUMP, which Matrix4.04Damage also spams every 4 ticks (the enable-time chat message explains the projectile plus jump setup); Dig sends C07 START_DESTROY_BLOCK at Under, Self, OutOfBounds (12 blocks off) or Unloaded (coordinates multiplied by 256) positions; Place spams C08 stone placements one block below the player; Input and GoofyC0C send zeroed or Float.MAX_VALUE C0C input packets; CreativeAction sends C10 with a null ItemStack at slot 1; and Abilities, Respawn and Spectate send C13, C16 and C18 every tick.

Several paths are simply broken. The Hazel C0F branch casts the transaction to C00PacketKeepAlive and writes c00.key on it, so the first C0F arriving on a tick where ticksExisted % 3 == 1 throws ClassCastException; the branch can never complete, and because it sits before the C00 branch the same failure aborts the whole Hazel send block every third tick. The Hazel C00 branch fails more quietly: (int) Math.random() is always 0, so the random key is the constant (int)(Math.PI + Math.E), which is 5. The NCP teleport accept calls getXZDifference(mc.thePlayer.posX, mc.thePlayer.posZ, packet.x, packet.x), passing packet.x for the z argument as well, the helper itself mixes up its operands, and the resulting booleans are never read. String comparisons use ==: a.getName() == "Fly" in the NCP module scan, ea.getMode() == "Self", digtype.getMode() == "Under" and the whole EntityActType chain; these happen to work only because every operand is an interned string literal, and any runtime-built mode string would break them. The PurplePrison else branch is unreachable: it only runs while ticksExisted is at most 60, so the inner ticksExisted > 61 C0F-cancel and the ticksExisted > 100 void rewrite can never fire, leaving only the y drift live. Dead settings include HypixelTimerTest (empty stub), Test (never referenced), the empty Spartan receive stub, verusVoid (never set true), matrixswitch (written, never read), transactiontype and placetype (never read), packetQueueC00Only and the x/y/z/yaw/pitch fields.
