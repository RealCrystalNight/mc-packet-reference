Analysis

Overview

Nekoware's Disabler registers two modes, Ghostly and Verus, and most of the file's logic is dead weight. The live surface is the Ghostly mode: every outgoing C0FPacketConfirmTransaction is cancelled from the packet-out event, and every time the inbound-packet counter passes 10 the module injects a C0CPacketInput with no vehicle state behind it. The Verus mode drains a packet queue on a 490ms timer but nothing in the file ever adds to that queue, and the nigerian counter that is supposed to clear the queue at 2 and reset it at 8 also never sees a populated queue, so both paths are inert.

Ghostly mode

The packet-out consumer increments a counter y on every outgoing packet, cancels each C0FPacketConfirmTransaction it sees, and resets a Timer object that no other branch reads. The packet-in consumer runs the injection: when y exceeds 10 it pushes a fresh C0CPacketInput onto the send queue and zeroes the counter, so roughly one C0C per ten inbound packets goes out while the mode is active. Cancelling the C0F stream removes the server's window-confirmation traffic, and the injected C0C claims vehicle steering input the player never performs.

Dead code and inert drains

The Verus branch fires on a 490ms timer delay and, when the packetQueue is not empty, sends one queued packet through PacketUtil.sendPacketSilent and resets the timer. The queue is a ConcurrentLinkedQueue that onDisable clears, but no handler ever calls packetQueue.add, so the poll always sees an empty queue and the drain never transmits anything. The nigerian counter in the Ghostly branch clears the queue at 2 and resets at 8, which is the same empty-queue loop; the unused imports (S08PacketPlayerPosLook, S2APacketParticles, PlayerCapabilities, RandomUtils) and the VERUS_DISABLE_ constants reinforce that the file is a partial port with the buffering half left out.

Wire footprint

The observable traffic is a cancelled C0F stream plus a periodic C0C injection. The module never touches C00 keepalives, so the keepalive ledger stays intact; the attack targets the transaction side of the connection's ping accounting and the input side that anticheats use to track vehicle and movement state. The sendPacketSilent path in PacketUtil writes straight to the network manager, bypassing the client's own event bus, which is why the Verus drain would not re-enter the cancel handler if the queue were ever populated.

How it counteracts this module

PingSpoofA cross-checks the two ping ledgers the connection maintains. On each movement packet it compares transactionPing against keepAlivePing and fails when the transaction value is larger and the gap exceeds 50ms, unless the player is exempt for lag, teleport, TPS or chunk reasons and has been connected for more than 10 ticks. The transaction ping is fed by the C0F round trips, so cancelling every confirmation starves that ledger while the C00 keepalive ledger keeps updating, and the two pings diverge on exactly the axis the check measures.

This is a direct hit on the Ghostly mode's core technique. The module would need to spoof C0F echoes instead of cancelling them to stay under this check, which is the standard escalation for this technique family.

How it counteracts this module

InventoryMove punishes rotation, sprint and sneak movement while the player's inventory-open state is non-zero, where that state is driven by the packets Hawk observes: window interactions, the C0B open-inventory action, and the input stream the client reports. The injected C0CPacketInput is part of that input stream, so the module's periodic C0C changes the input picture Hawk uses for the check.

Framed honestly, the check bites when the player actually moves while a window is open; the C0C injection alone does not open an inventory. The entry matters because it is the C0C-side consumer that pairs the module's injected input with its movement: on servers where Ghostly runs alongside a movement module, the combined stream is exactly what the check scores.
