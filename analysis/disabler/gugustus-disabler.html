Overview

Gugustus's Disabler is a collection of independent packet-bypass modes gated by individual BooleanValue toggles and dispatched from a single outgoing-packet event. The blanket switches cancel keepalives, status pings, entity actions, abilities and inventory transactions outright; the ping-spoof mode parks keepalive echoes and releases them late from a render-3D tick so the server measures inflated latency; and the anticheat-specific modes run movement exploits for HAC, AAC5 and NCP, a transaction-uid flip for UniversoCraft, a self-spectate injector, a Badlion brand rewrite, and a receive-side S08 teleport eater that re-sends the teleport target as a movement packet.

Architecture

All interception funnels through one method: onEventSendPacket branches on instanceof over the outgoing packet, and each branch is gated by its own BooleanValue. onEventUpdate runs once per tick and carries the movement exploits (HAC, AAC5, NCPTimerSemi, RoyalPixels), onEventRender3D acts as the flush clock for parked keepalives, and onRecv handles the incoming S08 teleport eater. Module state is an ArrayList of CustomC00PacketKeepAlive entries and a boolean 'disabling' flag that the UniversoCraft mode arms and clears. A world-change handler turns the module off when DisableOnWorld is set, so cancellation modes cannot survive a respawn or a server switch.

Key techniques

The ping spoof is a buffer-and-flush cycle with no timer thread. Every 40 network ticks the server stamps a fresh key, sends it in S00PacketKeepAlive, and stores it; the vanilla client replies with C00 carrying that exact key, and processKeepAlive folds the round trip into the ping as (ping * 3 + elapsed) / 4, but only when the echoed key matches the stored one. The module intercepts that echo, parks it with a release time of now plus the delay setting plus 0-200ms of jitter, and cancels it; onEventRender3D re-sends expired entries through addToSendQueueDirect, which bypasses the event bus so a flush is never re-buffered. The echo keeps its original key, so the server accepts it whenever it lands and the measured latency becomes the delay. The NoFlag receive handler is the inverse trick: it cancels an S08 teleport closer than 8 blocks and re-sends the teleport's absolute target as a C06, so the server-side position converges while the client never snaps.

Movement and transaction exploits

The movement modes lean on gaps in vanilla processPlayer validation. The illegal-position check bounds only x and z at 3.0E7 and never touches y, so the AAC5 mode's first C06 (y minus 1.0E159, z plus 10, onGround true) cannot be kicked; the second C06 re-asserts the real position, converging the server entity before the outlier matters. The moved-too-quickly check squares min(delta, motion) per axis, so with server-side motion near zero a large delta like the HAC mode's 11-block drop (every 10 ticks, onGround true) stays under the 100 threshold. NCPTimerSemi shifts the local position down 0.017 per tick and sets motionY to 0.019, a two-line desync with no packet of its own. RoyalPixels streams C13 packets claiming allowFlying and flying, which the server only applies when its own capabilities allow flying. The UniversoCraft branch arms a 'disabling' flag from movement in the first 10 ticks, clears it on a C02 attack, and while it is set under tick 350 rewrites every C0F uid to Short.MIN_VALUE or Short.MAX_VALUE on alternating ticks; processConfirmTransaction only re-enables crafting when the echoed uid equals the recorded short, so those confirmations never validate.

What this file does

onEventSendPacket is the single interception point for every packet the client is about to send, and each branch is a separate toggle. The blanket switches are the simplest: keepAlive cancels every C00 echo, entityAction cancels all C0B packets, playerAbilities cancels C13 packets, and confirmTransaction cancels every C0F. Each one removes a class of traffic the server expects, so each is only usable against servers that tolerate the gap. The ping switch is different: C01PacketPing is a status-phase packet, so in play that branch never fires; it is a leftover from clients that spoof the in-game ping through the status handler.

The ping spoof is built around the vanilla keepalive exchange. The server issues S00PacketKeepAlive roughly every two seconds, recording the key it sent; the vanilla client echoes C00PacketKeepAlive with the identical key, and the server's processKeepAlive accepts any echo whose key matches and folds the elapsed time into the player's ping average. The module intercepts the outgoing echo, builds a CustomC00PacketKeepAlive whose release time is now plus the delay setting plus 0-200ms of random jitter, and cancels the original. onEventRender3D then walks the buffer and, whenever a release time has passed, pushes a fresh C00PacketKeepAlive with the same key through addToSendQueueDirect. Because that path bypasses the event bus, the flushed echo is not re-intercepted, and because the key is preserved, the server accepts the late echo and records the inflated round trip as ping. The delay is capped at 4000ms on purpose: an echo whose key has already been superseded by the next keepalive is silently dropped by the key comparison.

The tick handler runs the movement exploits, and all of them survive vanilla because of two facts about processPlayer. The illegal-position check bounds only x and z at 3.0E7, never y, so the AAC5 mode's first C06 (y minus 1.0E159, z plus 10, yaw and pitch 0, onGround true) is not kicked; the immediately following C06 re-asserting the real position converges the server entity before the outlier matters. The moved-too-quickly check squares min(delta, motion) per axis, so with server-side motion near zero a large delta like the HAC mode's 11-block drop (sent every 10 ticks, onGround true) stays under the 100 threshold. NCPTimerSemi takes a different route: it nudges the local position down 0.017 each tick and sets motionY to 0.019, a two-line desync with no packet of its own. RoyalPixels streams C13 packets with allowFlying and flying set, a claim the server-side handler only applies when the server's own capabilities already grant flying.

The UniversoCraft branch runs a state machine over the outgoing stream. Movement packets inside the first 10 ticks arm the 'disabling' flag, a C02 use-entity attack clears it, and while the flag is set and ticksExisted is below 350 every C0F has its uid rewritten to Short.MIN_VALUE on even ticks or Short.MAX_VALUE on odd ticks. The check against S07PacketRespawn that also arms the flag is unreachable inside an outgoing-packet handler, so it is dead code. Vanilla's processConfirmTransaction re-enables container crafting only when the echoed uid equals the short it recorded for that window, so the flipped confirmations never validate and the transaction tracking the UniversoCraft setup relies on stays broken.

onRecv holds the NoFlag teleport eater: an S08 arriving after tick 20 whose target lies within 8 blocks (Euclidean distance) is cancelled and re-sent as a C06 with the target's x, y, z, yaw and pitch, so the server-side correction lands without the client-side snap that vanilla's handlePlayerPosLook would apply. The 8-block cutoff and the tick-20 guard leave real teleports (spawn, portals) untouched, and the debug toggle prints a chat line when the eater fires. The spectate mode injects C18PacketSpectate with the player's own UUID alongside every C03; vanilla only honors spectate requests in spectator mode, so on survival servers the packet exists purely to disturb anticheats that watch the traffic. The BLC spoof replaces the payload of C17 on the MC|Brand channel, the packet the vanilla client sends once at join carrying ClientBrandRetriever.getClientModName(); the fresh buffer writes the string "blc" so brand fingerprinting classifies the client as Badlion.

What this file does

The carrier subclasses the vanilla C00PacketKeepAlive and adds exactly one thing: a final long time that holds the absolute release deadline. The constructor forwards the keepalive key to the superclass, so the inherited key field and its VarInt serialization are untouched; the added field never reaches the wire, which is what makes the class safe to park in a list and re-emit later as a plain C00PacketKeepAlive(key). The key is what the server's processKeepAlive compares against the value it stored when it sent the matching S00, so preserving it unchanged is the entire point of the subclass.

The Disabler creates one of these per intercepted echo, computing the deadline as System.currentTimeMillis() plus the delay setting plus 0-200ms of jitter, and stores it in the keepAlivePackets list instead of letting the original packet through. The render-3D flush loop then compares packet.getTime() against System.currentTimeMillis() and turns expired entries back into fresh C00PacketKeepAlive objects via getKey(), which is why the class only needs the key and a timestamp. The carrier never appears in the module's own event stream, so a buffered echo cannot loop back into the interception branch. The same carrier class ships in the Augustus b2.6 and Xenza B9 branches of the client lineage.
