Analysis

Overview

Sprint is a keep-sprint module written in Java inside the otherwise Kotlin client. One UpdateEvent handler decides the sprint flag every tick: the release branch calls setSprinting(false) when the player is stationary, sneaking, blinded, low on food, or (with CheckServerSide) when the real look diverges more than 30 degrees from the rotation target a rotation module is driving; the sprint branch calls setSprinting(true) when AllDirections is on or the forward input is at least 0.8, with one interlock: if Criticals is enabled in HYTJump mode the module stays silent, because Criticals.onUpdate force-clears the sprint flag every tick so the HYTJump launch never becomes a sprint jump. The module never constructs a packet; the C0B traffic comes from the vanilla tick machinery that mirrors the sprint flag to the server.

Flag decision chain

The release branch fires on any of: MovementUtils.isMoving false, the player sneaking, blindness active while the Blindness toggle is on, food at or below 6 without allowFlying while the Food toggle is on, or the CheckServerSide condition. The sprint branch then gates on allDirectionsValue or mc.thePlayer.movementInput.moveForward >= 0.8F, and adds the Criticals interlock: LiquidBounce.moduleManager.getModule(Criticals.class) with getState() true and mode HYTJump suppresses the sprint write entirely, because Criticals.onUpdate sets isSprinting = false every tick in HYTJump and NGJump modes to keep the launch from converting into a sprint jump.

Wire presence through the vanilla flag diff

setSprinting is a local flag write; the C0B is produced by the tick machinery that compares the flag against the last server-sprint state and emits one START_SPRINTING or STOP_SPRINTING per transition. The LiquidSense Dev snapshot ships no net/minecraft tree, so the fork's EntityPlayerSP cannot be read; the stock 1.8 contract is a per-tick diff that sends at most one C0B per flag change, meaning repeated setSprinting(true) calls with no state change emit nothing. AllDirections backward and sideways sprint only works if the fork honors multi-direction sprint server-side, which is unverifiable in this snapshot, so the honest statement is that the module asks for sprint in every direction and the server decides.

CheckServerSide rotation gate

With CheckServerSide on, the module unsprints whenever RotationUtils.targetRotation is set and RotationUtils.getRotationDifference(current yaw and pitch) exceeds 30 degrees, and CheckServerSideOnlyGround narrows that test to grounded ticks. This is the anti-interference switch: while Aura or another rotation module swings the view away from the movement direction, Sprint refuses to claim sprint, because a sprinting player whose motion disagrees with the reported look is a recognizable signature. The food gate mirrors vanilla's own starvation unsprint, so the module's defaults keep it inside the legitimate sprint envelope.
