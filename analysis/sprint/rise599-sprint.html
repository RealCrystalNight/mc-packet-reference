Analysis

Overview

Rise 5.99's Sprint is an auto-sprint module. On every StrafeEvent it forces the sprint keybind's pressed flag true and, in All Directions mode, sets the EntityPlayerSP allowMultiDirSprint flag so the player moves at sprint speed in every direction. Silent mode cancels the C0B START_SPRINTING packet whenever the forward key is not held, so omni-sprinting sideways or backward never informs the server of the sprint state, and Only In Air restricts the multi-dir flag to airborne movement with a two-tick ground grace. onDisable restores the real keyboard state and clears the flag.

Key forcing

The handler runs on StrafeEvent, the per-movement-tick event. It maintains an onGroundTicks counter for the Only In Air gate, then unconditionally writes keyBindSprint.setKeyPressed(true), which makes the vanilla sprint-start logic treat the key as held. The vanilla EntityPlayerSP update diffs the sprint state against its last-known server state and emits C0B START_SPRINTING when the state changes, so the wire effect is one START per enable cycle, not a packet per tick. The forced key also keeps the vanilla conditions (moving, not collided, food above the stop threshold) as the effective gates on whether the sprint actually engages.

Multi-directional sprint

All Directions sets allowMultiDirSprint, the client field that lets the movement code apply sprint speed while strafing or moving backward, gated on the module being enabled, the player not sneaking, MoveUtil.isMoving() and no horizontal collision, with Only In Air further requiring fewer than two grounded ticks. Silent mode then filters the C0B stream: when the forward key is not down, a START_SPRINTING packet is cancelled, so the server-side sprint state stays false for sideways and backward motion. When the forward key IS held, the C0B goes through and the server sees a sprinting player moving diagonally, which is the state that direction-aware checks can measure.

Wire fingerprint

The clean fingerprint is one C0B START and one STOP per toggle cycle. In silent multi-dir use the C0B stream is suppressed almost entirely while the C03 deltas still show sprint-speed motion in arbitrary directions, which is the sharper anomaly: the server-side sprint state says not sprinting while the position stream moves faster than walk speed. The module never sends anything else; it only mutates the keybind, the client flag and the outgoing C0B.

What this file does

The module is entirely this file. What this file does

StrafeEvent is the per-movement-tick event the module hooks, carrying the forward and strafe input magnitudes and the friction value the movement code will apply, with setSpeed helpers that other movement modules use to rewrite the player's velocity. How it counteracts this module

Vrekt-Arc v2 has no entity-action consumer at all. The only artifact of the C0B packet in its tree is the ProtocolLib wrapper WrapperPlayClientEntityAction, a generated data holder that is never constructed by the anticheat: PacketListener subscribes only to FLYING, POSITION and POSITION_LOOK, USE_ENTITY, ARM_ANIMATION, HELD_ITEM_SLOT and BLOCK_PLACE (the soup auto-heal branch). No check reads the sprint action, validates sprint state, or measures toggle frequency, so the module's C0B traffic is invisible to Arc v2.

The honest consequence is that Arc v2 exerts no pressure on the sprint claim itself; its movement layer (Speed and MorePackets) sees only the position stream, where a sprint-speed delta without a sprint state is not distinguished from ordinary speed. This entry documents the gap rather than a counter: servers running Arc v2 get no detection from the C0B side of this module, and the module's silent filter does not need to hide anything from this anticheat.
