Overview

Spicy's Eagle is a movement helper with no packet of its own: it drives the client's sneak keybind from world state. Every pre EventUpdate it checks the equipped item and the block one meter below the player's feet; when the item is an ItemBlock and that block is air, keyBindSneak.pressed is forced true, and otherwise it is forced false. The result is automatic sneaking exactly while the player stands on an edge with blocks in hand, which is the classic safe-walk condition for bridging. The module sends nothing itself: the sneak state reaches the server through the vanilla keybind path, and onDisable clears the pressed flag so the fake sneak never sticks.

Architecture

The whole module is one pre EventUpdate branch. It reads mc.thePlayer.getCurrentEquippedItem(); when the stack is non-null and its item is an ItemBlock, it first forces keyBindSneak.pressed = false and then probes the block at BlockPos(posX, posY - 1, posZ): if the world reports air there, the sneak key is forced true. Every tick re-asserts the state, so the fake sneak cannot drift, and any other code that clears the bind is overwritten on the next tick. onDisable unconditionally clears pressed so the player never stays sneaking after the module turns off. The probe uses the client's own world state, so the sneak engages and releases with the geometry, not with any timing logic.

Key techniques

posY is the player's foot position, so the block at posY - 1 is the support block; when it is air the player stands over a gap, and with a block item in hand that is exactly the safe-walk condition. Because the pressed flag is set directly on the GameSettings keybind, the vanilla movement handler treats the module's sneak as a real key press: it flips the sneak pose and emits the normal sneak-toggle traffic when the state changes. The module never constructs a packet itself and never touches motion; its entire contribution is the keybind write.

Detection surface

The module has no wire signature of its own. Its C08 association is the placement stream the behavior enables, since holding a bridge with blocks in hand is the module's purpose, and server-side enforcement of that stream is placement-frequency and slot-change checking rather than anything that reads the sneak key. The sneak toggles themselves are vanilla C0B entity actions at human cadence, which toggle-rate checks tolerate.

How it counteracts this module

The NoCheatPlus blockplace pipeline scores every C08PacketPlayerBlockPlacement into BlockPlaceData.fastPlaceBuckets, an ActionFrequency accumulator, and separately into a short-term tick window. The long-window score (fastPlaceBuckets.score(1f)) is compared against cc.fastPlaceLimit, and the short-term counter increments while consecutive placements land within cc.fastPlaceShortTermTicks, with both paths lag-adjusted through TickTask. A violation runs the configured fastplace actions, cancellation or set-back, from the check's executeActions path.

Eagle itself never emits a placement; it only holds the sneak keybind while the player stands over air with a block in hand, so the server sees FastPlace only through the bridging behavior the module enables. A player walking a bridge with Eagle places one block per step at a human-paced rhythm that stays under the frequency limit, but a tower or speed-bridge attempt that leans on the automatic sneak to place several blocks inside the short-term window trips the tick counter. The module cannot help here: the sneak state does not affect placement timing, so the same frequency gates apply to an Eagle user and to a manual bridger.

The boundary is the sneak toggle itself: the module's keybind writes produce vanilla C0B sneak toggles, which this placement check never inspects. FastPlace is content-blind to why blocks are placed and only counts the C08 stream, so an Eagle user placing slowly passes regardless of how the sneak state is driven.

How it counteracts this module

Hawk's ItemSwitchSpeed is a cancelless CustomCheck over the slot-switch stream. Any InteractItemEvent or InteractWorldEvent (use-item and block-interact actions) stamps the player into a usedSomething set, and the next ItemSwitchEvent for that player must arrive at least MIN_SWITCH_TICKS after the previous switch or it is punished with one VL under the check's 0.999 reward decay. The default MIN_SWITCH_TICKS is 1 tick, and the check is explicitly aimed at autotool and scaffold modules that flip the held slot immediately before every use or placement.

For an Eagle user the relevant pattern is the block-slot switch that precedes each placement while bridging: switch to the block slot, place, repeat. When those switches land inside the one-tick minimum, the check flags regardless of the sneak state. Eagle's contribution is timing-neutral: it neither helps nor hurts the slot-change cadence, so the check's gate applies to the module's users exactly as it does to manual bridgers.

The boundary: ItemSwitchSpeed never reads sneak state, so it cannot see Eagle's keybind writes at all. A player who switches slots slowly while sneaking with Eagle passes; the check exists to bound the fast slot-switch automation that typically accompanies the same bridging playstyle.

How it counteracts this module

Vrekt-Arc-v2's InventoryListener is the event front end for the FastConsume check. The onInteract handler stamps InventoryData.consumeTime on any RIGHT_CLICK_AIR or RIGHT_CLICK_BLOCK with an edible item or potion in hand, and onConsume runs FAST_CONSUME.check when a PlayerItemConsumeEvent fires, canceling the eat if the consumption cadence is too fast. The third handler is an operator GUI that schedules bans from an inventory menu and is unrelated to movement.

The tie to Eagle is the bridging playstyle, not the module's code: a player holding a bridge with Eagle frequently eats golden apples between placements, and the consume-time ledger is exactly the surface that gates how quickly a second bite can follow a first. Eagle sends nothing and stamps nothing, so the listener's data is entirely driven by the player's real interactions, and the check stays fully effective against an Eagle user.

The boundary: FastConsume measures consumption only. It has no view of the sneak keybind, the placement stream, or any other module behavior, so an Eagle user who never eats while bridging is completely invisible to this listener. It is included here as the consumption-timing companion that constrains the same safe-walk session.
