Overview

LiquidSense Dev's HitBox is a value holder with one job: inflate the client-side collision border of every entity so the mouse-over ray trace treats targets as bigger than they are. The module itself only registers a Size FloatValue (default 0.4, range 0 to 1); the effect lives in a Forge mixin, MixinEntity.getCollisionBorderSize, which returns 0.1F plus the Size value whenever the module is enabled. Vanilla EntityLivingBase returns a fixed 0.1F border, and the client's EntityRenderer expands each entity's bounding box by that border on all three axes before ray tracing for the mouse-over target. At the default Size the border becomes 0.5 blocks per axis, so the effective box the client aims against grows to roughly 1.6 wide and 2.6 tall, which lets attacks register at larger angular offsets and at eye-to-surface distances the real box cannot support. The module never sends a packet itself: the inflated box only decides which C02 attacks the player's own clicks or a killaura will send, and because a vanilla 1.8 server trusts the client's hit detection entirely, those attacks land.

Module and mixin split

HitBox.kt is two statements: the ModuleInfo header and the sizeValue declaration. All behavior is in MixinEntity, where an injection at the head of getCollisionBorderSize grabs the module instance through LiquidBounce.moduleManager, checks getState(), and returns 0.1F plus sizeValue when enabled. The vanilla method returns 0.1F for EntityLivingBase, so the returned border spans 0.1 (Size 0) to 1.1 (Size 1) and defaults to 0.5. The mixin class also carries unrelated injections (setAngles, moveFlying, a StrafeEvent hook) that do not participate in the hitbox mechanic.

Where the border bites

In 1.8.9 the client's mouse-over scan expands every entity's bounding box by getCollisionBorderSize() on the x, y and z axes before calling calculateIntercept with the look ray, and the ray trace distance is capped by the block-reach distance (4.5 survival). A larger border therefore does two things: it widens the angular envelope the look ray can intersect, and it pushes the intersectable surface outward along the ray, so a target whose real box is beyond vanilla reach becomes hittable up to the 4.5 cap. The attack path needs no further client-side distance validation: PlayerControllerMP.attackEntity trusts the mouse-over result, and the C02 it sends names the victim with no geometry at all.

Server-side asymmetry

None of the expansion transfers to the server. The server tracks the standard 0.6-wide player box, and every anticheat in this corpus rebuilds that box from packets or Bukkit state rather than trusting the client. A hit that only exists because of the inflated border is therefore a hit against geometry the server does not have: ray-trace checks fail against the real box, and distance checks measure eye to the real box center, which the border does not move. The module's practical value is aim forgiveness for killaura rotations that would otherwise miss the real box, at the cost of making every such hit a server-side reach or hitbox violation.

How it counteracts this module

NoCheatPlus measures each attack against the real server-side geometry. The check computes the distance from the attacker's eye to the damaged entity's clamped position, subtracts centertoedge, a getinset half-width derived from the box, and compares the result with the survival distance limit (default 4.02 in DefaultConfig). How it counteracts this module

Grim queues the attack position on ATTACK and INTERACT_ENTITY and performs the precise ray trace on the following look update, against the packet-entity box rebuilt from server-side teleport and rel-move data. Because 1.8 can lag the look by one tick, the trace checks all possible look directions from both the current and last yaw and pitch and all possible eye heights, and pre-1.9 clients get a 0.1 hitbox margin on the box. The client-side border never reaches the server, so the trace sees the unexpanded box: a hit that only the inflated border made possible fails the intersection, and hits that do intersect beyond the real box surface flag on distance with the default threshold 0.0005. The cancelBuffer then suppresses the next several attacks, which directly counters a killaura that keeps firing into the expanded box.

How it counteracts this module

Arc v2's KillAura check runs from the EntityDamageByEntityEvent path with five sub-checks. The reach sub-check measures the distance from the player to the victim's location minus the victim's current velocity, compared with max-reach 4.2 from config.yml, so knockback does not false-flag and the measurement is against the real center. The direction sub-check compares the look angle to the victim with max-direction-angle 1.2, which exposes the off-axis aim that the expanded border encourages. The inflated client box changes neither the center distance nor the look angle the server sees, so every hit that relied on the border trips one of the two. The speed sub-check (max-attacks 16 and max-attack-packets 20 per second) additionally caps how fast a killaura can exploit the wider envelope.
