Analysis

Overview

Memeware's FastBreak accelerates block breaking by mutating the client-side damage controller. Every update event it zeroes mc.playerController.blockHitDelay, and once the accumulated curBlockDamageMP passes the Break setting (default 0.7) it snaps the accumulator to 1.0, completing the break up to one damage tick early. Removing the 5-tick post-break delay is the larger win: consecutive blocks chain with no gap, which is the wire signature the block-break anticheat checks measure.

Damage accumulation shortcut

PlayerControllerMP.onPlayerDamageBlock decrements blockHitDelay and skips damage while it is positive, adds the block's relative hardness to curBlockDamageMP each damage tick, and breaks the block when the accumulator reaches 1.0, then sets blockHitDelay to 5 (PlayerControllerMP lines 263-267, 279, 292-299). The module writes blockHitDelay to 0 every update, so the 5-tick gate never applies, and promotes curBlockDamageMP to 1.0 as soon as it crosses the Break threshold, so the block finishes on the tick the accumulator first passes 0.7 instead of waiting for 1.0.

Wire fingerprint

The C07 sequence for a block is START_DIGGING on the first damage tick and STOP_DIGGING on the break, and the server breaks the block on receipt without re-validating the elapsed time. The module shortens the per-block window by up to one damage tick (about 50ms at 20 ticks per second) and, with blockHitDelay zeroed, the next block's START_DIGGING lands in the same tick as the previous STOP_DIGGING. Sustained use therefore produces back-to-back break events with no 250ms inter-block gap.

Detection surface

The counters split across the two effects. NCP blockbreak FastBreak and Grim FastBreak compare the measured break time against the expected time derived from the block's hardness and the player's tool, and Grim also scores the inter-break delay, which is the direct counter to the zeroed blockHitDelay. NCP blockbreak Frequency caps breaks per time frame and bites in creative-mode chains. Vrekt-Arc's Nuker is creative-gated and its v2 build dropped the block package, so the Arc lineage offers no survival-mode block-break counter.

What this file does

The module is two field writes on the player controller. The Break setting defaults to 0.7 with a range of 0 to 1, and the handler runs on every update event, so the writes are re-asserted each tick regardless of what the controller does. Setting blockHitDelay to 0 removes the post-break pause, and promoting curBlockDamageMP to 1.0 once it passes the threshold triggers the controller's break path early.

The two writes compose: the delay removal chains blocks, and the threshold snap shortens each block's tail. The module does not send packets itself; it changes the controller state that drives the vanilla C07 emission, which is why the wire difference is visible only in the timing of the dig sequence.

How it counteracts this module

Arc's block-break check registers a BLOCK_DIG packet listener (line 195) and enforces a break-rate cap of 15 breaks per second, a 50ms minimum delta between breaks with a 5-occurrence threshold, and a packet-side cap of 50 break packets per second (lines 63-72, 91-127, 135-164). The gate matters most: creativeOnly defaults to true, and the check returns false immediately for any non-creative player (line 84), so in survival the entire check is dormant.

Against the survival module the check does nothing unless an admin disables the creative-only gate. With the gate off, the module's 30% early break still takes hundreds of milliseconds, so it stays inside the 50ms min-delta, and only the chained breaks from the zeroed blockHitDelay approach the delta threshold; five consecutive chains would trip it. The lineage note matters for attribution: the C07 corpus files under the Vrekt section are the v1 layout (arc.check.block), and Vrekt-Arc v2 dropped the block package entirely, its PacketListener subscribing only to FLYING, POSITION, USE_ENTITY, ARM_ANIMATION, HELD_ITEM_SLOT and BLOCK_PLACE (soup auto-heal), so the v2 build offers no block-break counter at all.
