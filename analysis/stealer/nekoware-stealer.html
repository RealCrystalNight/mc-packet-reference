Overview

Nekoware v1 private's Stealer is a near byte-for-byte port of the Memeware 7.3 module with one renamed mode and one dead branch: it registers Normal and Aura modes, but the empty-chest close condition still tests isMode("Nearby"), which can never match, so the mode-based auto-close is dead code and only the Close setting closes the chest. The steal loop is otherwise identical: one shift-click per Delay ticks through the fork's windowClick (pure C0E, no C09 sync), C0D close through EntityPlayerSP.closeScreen, and an Aura-mode chest scan that swings with C0A and opens chests with C08. The Delay 0 divide-by-zero crash is inherited from the shared modulo gating.

Port relationship

The file differs from its Memeware sibling in exactly three lines: the package, the mode registration (Nearby renamed to Aura) and the unchanged isMode("Nearby") test in the empty-chest close branch. The Aura branch itself works, because the scan condition tests isMode("Aura") against the registered string, but the close condition's Nearby test never matches, so in Aura mode an emptied chest closes only when the Close setting is on. That asymmetry, a renamed mode leaving a stale string test behind, is the kind of copy-paste drift that identifies a port: the developer renamed the mode string in the registration but missed the consumer.

Steal loop and Aura scan

The steal loop matches the sibling exactly: with a GuiChest open, the module shift-clicks the first occupied slot whenever ticksExisted modulo the rounded Delay is zero, one item per click, and calls mc.displayGuiScreen(null) when the first 27 or 54 slots are empty and the Close setting permits. The Aura mode scan runs with no screen open, walks a 7x7x7 box, and for each unlisted chest within distance-squared 16 sends C0APacketAnimation and right-clicks it open via onPlayerRightClick, which emits the C08. The emptied list clears on every S08PacketPlayerPosLook after terrain load and on enable.

Wire behavior

The fork's PlayerControllerMP.windowClick queues only C0EPacketClickWindow and never syncs the held slot, so the drain is pure C0E traffic with no C09, and the module never switches held items. The close emits C0D through the fork's EntityPlayerSP.closeScreen, and the Aura open emits C0A plus C08. The tick-modulo pacing gives 5 C0E per second at the default Delay of 4, 20 per second at Delay 1, and a crash at Delay 0, since ticksExisted modulo zero throws. The S08 consumer is receive-side and only resets the chest set.

NoCheatPlus FastClick scores InventoryClickEvent traffic into an ActionFrequency with five 200ms buckets: the newest bucket is compared against the short-term limit of 4 and the full window against the normal limit of 15, with TickTask lag division before the comparison.
