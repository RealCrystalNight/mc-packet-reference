Analysis

Overview

Sigma 4.11's ChestStealer drains chests one item at a time through the vanilla container protocol. Every steal passes through mc.playerController.windowClick, which emits C0EPacketClickWindow against the open window id, paced by a timer of 50 milliseconds per delay-setting tick. The Hypixel mode doubles every steal into two shift-clicks (button 0 then button 1) so each item costs two C0E packets, and the Drop option appends a -999 outside-window throw. A title blacklist refuses to touch shop, selector and lobby GUIs, the item filter keeps junk and worse swords out of the inventory, and the optional ChestAura opens nearby chests with C08PacketPlayerBlockPlacement sent through the no-event packet path. The module closes the chest with the client closeScreen once the viewed contents are gone or the inventory is full.

Steal loop and pacing

The handler runs on EventUpdate pre. While a GuiChest is open and the title passes the blacklist, a per-item delay is computed as 50 times the Delay setting (default 2, so 100ms per item) and gated through a Sigma Timer. A First Delay setting (default 0, range 0 to 15) holds the first click for that many update ticks. Each steal is a windowClick against the chest window id, and the timer resets after every click. The loop first verifies the player inventory is not full, then scans the chest slots for the first stack that passes the isBad filter; when nothing stealable remains, or when the inventory is full, the module closes the screen and clears the stealing flag.

Modes and filters

In Hypixel mode each item costs two window clicks: the first with button 0 and the second with button 1, both in shift mode, which doubles the C0E rate to roughly 20 packets per second at the default delay. With Drop enabled the steal is a left-click pickup followed by a -999 outside-window throw, and the server-side drop is also issued per item. The isBad filter compares candidate swords against the best sword already in the inventory using sharpness times 1.25 plus base damage, and rejects a long unlocalized-name list (tnt, sticks, eggs, string, flint, compass, feathers, buckets, snow, fish, enchantments, xp, shears, anvils, torches, seeds, leather, pistons), plus pickaxes, glass bottles, tools and harmful splash potions. The chest-title blacklist holds about forty substrings such as menu, selector, game, shop, lobby, vault and anticheat, and any match makes the handler return without stealing.

ChestAura

ChestAura is a separate pre-update branch that runs while no screen is open. It walks the loaded tile-entity list, and for each TileEntityChest within 4 blocks that is not marked empty it sends a C08PacketPlayerBlockPlacement with the chest position, a ray-traced facing direction and the current held item through NetUtil.sendPacketNoEvents, then marks the chest empty client-side and breaks. The stealTimer gates re-scans at 1000ms and resets the stealing flag after 2000ms of inactivity, so the module re-opens chests as they become available. The C08 goes out through the network manager's no-event path, bypassing the client's outgoing event bus.

What this file does

The module is one EventUpdate handler with two branches. The chest branch runs the paced steal loop: it computes the 50-millisecond per-item delay, applies the first-delay counter, verifies the inventory is not full, scans for a non-bad stack and shift-clicks it through windowClick, which emits C0E via the fork's PlayerControllerMP. The Hypixel double-click and the Drop throw are extra windowClick calls in the same branch. The ChestAura branch opens nearby chests with C08 through NetUtil.sendPacketNoEvents and tracks them with a client-side isEmpty flag.\n\nThe close path is mc.thePlayer.closeScreen, which the Sigma fork's EntityPlayerSP overrides to queue C0DPacketCloseWindow with the open container window id. The C09 held-item chip is inherited from the client's window protocol: the fork's windowClick emits pure C0E and only other sync paths, like the per-tick updateController sync, ever emit C09, and this module never changes the held item. The title blacklist and the sword-damage comparison are pure client-side filters that decide which stacks are worth a click.

What this file does

NetUtil is the module's only external helper. sendPacketNoEvents routes a packet straight to the network manager's sendPacketNoEvent, which queues it for the wire without running it through the client's outgoing event bus, so no other module or event listener can cancel or observe the ChestAura open in flight. sendPacket sends through the normal event-visible path. The module uses the no-event variant specifically for the C08 chest-open packets so the open cannot be intercepted by other handlers.\n\nThe distinction matters for the wire behavior: both paths ultimately reach the server, and the server sees the C08 as a normal use-item-on-block action that opens the chest and starts the S30 window refresh the steal loop then consumes. The class is a thin static wrapper over the fork's NetworkManager, which is why it is the right supporting file for the ChestAura half of the module.

How it counteracts this module

NoCheatPlus FastClick scores InventoryClickEvent traffic into an ActionFrequency with five 200ms buckets: the newest bucket is compared against the short-term limit of 4 and the full window against the normal limit of 15, with TickTask lag division before the comparison. A plain shift-click with an empty cursor counts 1.0 via getAmountWithAction. The check also carries the container-interaction path: any click landing within the 155ms min-interaction-duration default after the container opened adds a violation of (155 / duration) * 100. Slot -999 outside-window throws are excluded entirely, so the Drop mode's throws never count.\n\nThe stock Sigma configuration sits just under the rate limits: 100ms per item is 10 clicks per second, or 2 per bucket, below both the short-term 4 and the window 15, so a default-delay drain passes the rate paths. Hypixel mode changes that: two clicks per item at 20 per second blows the 15 window (roughly 5 VL per click, cancel at vl>150 in about 1.5 seconds) and touches the 4-per-bucket short-term limit. The interact_time path is the most reliable hit because the First Delay default of 0 lands the first click within a frame of the chest opening, deep inside the 155ms window, worth close to 100 VL on its own. The honest gap is the delay dial: raising Delay to 4 ticks or more puts the rate back under both windows.

How it counteracts this module

NCP's Open check watches PlayerMoveEvent traffic while an inventory window is open. checkOnMove skips duplicate packets, vehicles, creative quickbar clicks, merchants and velocity-affected moves, then decides whether the move carries an impulse: with modern input it reads the WASD/jump bits directly, otherwise it falls back to the movement model's hasImpulse decision.
