Deep Analysis

Server-side per-player survival, creative, adventure and spectator interaction controller. Validates dig timing, block harvesting, item use and block activation from NetHandlerPlayServer. Sends corrections and progress animations plus gamemode broadcasts to other players.

Key Methods — In Depth (8)

setGameType

Change gamemode and broadcast to all players

setGameType changes the owned player's gamemode and broadcasts it to the whole server. It stores the new WorldSettings.GameType in gameType for later survivalOrAdventure and isCreative checks. It calls type.configurePlayerCapabilities on thisPlayerMP.capabilities to set fly, edit, and damage flags. It calls thisPlayerMP.sendPlayerAbilities to push those flags to the owner, updating its own client permissions. It then broadcasts S38PacketPlayerListItem with Action UPDATE_GAME_MODE and an array containing thisPlayerMP via sendPacketToAllPlayers. Every connected client receives S38 and updates the tab-list gamemode icon plus adventure interaction rules for that player. The owner also gets the broadcast in addition to the direct abilities packet. No block or inventory change happens here.

Storing gameType updates local mode used by dig and use guards. configurePlayerCapabilities maps survival, creative, adventure, and spectator to capability booleans. sendPlayerAbilities pushes those flags to the owner client. Broadcasting S38 UPDATE_GAME_MODE informs all other clients of the new mode for rendering and permissions.

onBlockClicked

Begin survival dig or instant creative break

onBlockClicked starts block breaking when the client sends a dig-start packet. In creative it tries extinguishFire first to put out fire without breaking, and if not fire it calls tryHarvestBlock for instant removal. In survival and adventure it loads the target Block and enforces adventure canDestroy rules via isAllowEdit and held stack canDestroy, returning early for spectator or disallowed tools. It extinguishes fire at the position, snapshots initialDamage from curblockDamage, and queries getPlayerRelativeBlockHardness for dig speed. It notifies the block via onBlockClicked for doors and special handling. If hardness is at least 1.0 it calls tryHarvestBlock immediately for instant crops or soft blocks. Otherwise it sets isDestroyingBlock true, records field_180240_f position, and calls theWorld.sendBlockBreakProgress with staged crack 0 to 10. That call emits S25PacketBlockBreakAnim to watching clients so all see the crack overlay grow.

updateBlockRemoving

Tick ongoing dig progress and finish harvest

updateBlockRemoving ticks every server tick to advance survival digging and emit S25 progress. It increments curblockDamage as the tick counter for both pending-finish and active-dig paths. If receivedFinishDiggingPacket is true meaning stop-dig arrived early, it computes elapsed ticks, loads the Block at field_180241_i, and clears the flag if now air. It multiplies getPlayerRelativeBlockHardness by elapsed plus one to get fraction f and scales to 0 to 10 stage j. If j differs from durabilityRemainingOnBlock it calls theWorld.sendBlockBreakProgress with player ID, position, and stage, which sends S25PacketBlockBreakAnim to trackers. When f reaches 1.0 it clears the flag and calls tryHarvestBlock to remove and loot the block. Else if isDestroyingBlock is active it performs similar progress for field_180240_f, sending -1 reset and clearing the flag if the block turned to air. Stage caching avoids spamming S25 every tick when unchanged.

blockRemoving

Handle stop-digging packet mid-break

blockRemoving handles the stop-digging C07 packet when it arrives mid-break. It first verifies pos equals field_180240_f so stale or moved targets are ignored. It computes elapsed ticks as curblockDamage minus initialDamage and loads the server Block. If material is air it does nothing because onUpdate or harvest already cleared it. It multiplies getPlayerRelativeBlockHardness by elapsed plus one to estimate break fraction f. If f is at least 0.7 it treats the dig as complete: clears isDestroyingBlock, sends progress -1 via sendBlockBreakProgress to erase crack via S25, and calls tryHarvestBlock to remove and drop loot. If below 0.7 and receivedFinishDiggingPacket is not already set, it parks the request by clearing isDestroyingBlock, setting receivedFinishDiggingPacket true, and copying position and initial damage into field_180241_i and initialBlockDamage. updateBlockRemoving will then finish it over subsequent ticks with staged S25 updates.

cancelDestroyingBlock

Abort dig and clear crack overlay

cancelDestroyingBlock aborts an in-progress survival dig when the client sends abort or switches target. It unconditionally sets isDestroyingBlock false to stop updateBlockRemoving from advancing crack stages. It calls theWorld.sendBlockBreakProgress with the breaker entity ID, field_180240_f position, and -1 stage. WorldServer forwards that as S25PacketBlockBreakAnim with destroy stage -1 to all clients tracking the position. Receivers clear the crack overlay for that breaker ID. No block removal, loot, or tool damage occurs on cancel. The curblockDamage counter is left for the next onBlockClicked to re-baseline via initialDamage. Duplicate cancels simply resend -1 which clients treat as idempotent clear.

tryUseItem

Apply right-click item use with creative restore

tryUseItem applies right-click item use from NetHandlerPlayServer C08 handling. It immediately returns false for spectator mode to block consumables, throws, and placements. It snapshots stackSize and metadata before calling stack.useItemRightClick with world and player for potions, food, buckets, or projectiles. If the returned stack differs by identity, size, max use duration, or metadata, it writes the result into the current hotbar slot. In creative it restores stackSize and item damage so blocks and items are infinite while still triggering effects. If size reached zero it clears the slot to null to remove consumed items. If the player is not in a use animation it calls sendContainerToPlayer to resync the inventory container, correcting any client-server drift. True signals the interaction was consumed while false lets the caller try block activation instead. No block-change packet is sent here beyond container sync.

activateBlockOrUseItem

Activate block or place held item

activateBlockOrUseItem handles right-click on a block position, choosing block activation versus item placement. Spectators only open chest and inventory GUIs via displayGUIChest without editing, returning false for other blocks. For players it first tries onBlockActivated when not sneaking or when empty-handed, letting doors, chests, furnaces, and levers consume the click with true. If that fails and stack is null it returns false to end the interaction. In creative it records metadata and size, calls stack.onItemUse for placement, then restores damage and size for infinite blocks before returning the result. In survival it directly returns stack.onItemUse which places blocks, consumes items, and triggers TileEntity updates. Block changes from placement flow through WorldServer mark-and-notify as S22 and S23 packets rather than from this method. Deduplication with NetHandlerPlayServer position and face validation prevents ghost blocks.
